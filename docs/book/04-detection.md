# 第4章 変異の検出条件

変更した行を実行しても、テストが失敗するとは限らない。
`0 + 0` と `0 - 0` では計算結果が同じだった。
違いが生まれても、後続の処理で消えることがある。
さらに、結果が異なっていても、その結果を検査しなければ見逃す。

## 到達、状態の差、伝播、判定

変異によるテスト失敗を考えるとき、次の四つを順に点検すると、生存の理由を調べやすい。
一般にRIPRとして整理される検出条件に対応する。

| 条件 | 点検すること | 送料計算での例 |
| --- | --- | --- |
| 到達 | 変更箇所を実行するか | 重量加算の処理を実行する |
| 状態の差 | 元と変異後で値や制御に差が生じるか | `> 2000` と `>= 2000` が2000gで異なる |
| 伝播 | 差が観測対象まで残るか | 重量加算の差が最終送料まで残る |
| 判定 | オラクルが観測された差を拒むか | 期待送料500円に対して800円を拒む |

これは、生存した原因を一意に自動分類する規則ではない。
ある入力で状態の差が生じなくても、別の入力では差が生じる可能性がある。
調査した入力と仕様の範囲を添えて使う。

## 後続処理で消える違い

次の処理で、重量加算を300円から301円に変えたとする。

```python
fee = 500
if weight > 2000:
    fee += 300
if subtotal >= 5000:
    fee = 0
return fee
```

重量3000g、商品合計額6000円では、重量加算後の値は800円と801円で異なる。
しかし、次の条件で両方とも0円に上書きされる。
最終送料だけを観測するテストでは、この入力によって二つを区別できない。

商品合計額を1000円にすれば上書きが起こらず、800円と801円の差が戻り値まで残る。
そのうえで期待値800円を検査すれば、変異を検出できる。
入力を選ぶときは、変更箇所を通ることに加え、後続の処理に差を消されない条件も考える。

## 差が残っても成功するテスト

最終送料が800円から801円へ変わっても、`assert fee >= 0` は成功する。
差は戻り値に届いているが、アサーションがどちらも許すためである。
この場合は、実行経路を増やすより、仕様から正しい金額を導く方が直接的な改善になる。

内部変数をテストから読み出せば、上書き前の差を捉えられるかもしれない。
しかし、仕様が最終送料しか定めないなら、中間の計算形式を固定する理由にはならない。
観測対象は、公開された振る舞いと要求に合わせて選ぶ。

## 分岐の組み合わせ

会員、重量、送料無料、遠隔地の条件には相互作用がある。
それぞれが真になるテストを一つずつ用意しても、適用順序の誤りまで確かめたとは限らない。
たとえば、遠隔地加算を送料無料処理より前に移すと、5000円以上の遠隔地注文で加算が消える。
各条件の単独テストに加え、仕様が順序を要求する組み合わせを選ぶ必要がある。
