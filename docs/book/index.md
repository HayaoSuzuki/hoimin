# ミューテーションテストによるテスト改善

Pythonとhoiminで学ぶ理論と実践

テストはすべて成功し、カバレッジも100%になった。
それでも、境界値で料金が変わったり、会員割引が適用されなかったりする不具合は入り込める。
実行したコードの量から、期待する振る舞いをどこまで確かめたかは読み取れないためである。

**ミューテーションテスト**は、コードに小さな変更を加え、既存のテストがその違いを検出するか調べる手法である。
たとえば「5000円以上」を「5000円を超える」に変えたとき、テストは失敗するだろうか。
失敗しなければ、境界のテストが足りない可能性がある。
ただし、テストの不足以外にも変更を検出しない理由がある。
その区別をつけ、仕様に基づくテスト改善につなげるのが本書の目標である。

## 対象読者と前提知識

対象は、単体テストを書き、カバレッジも測定しているが、テストが見逃すバグに困っているソフトウェアエンジニアである。
Pythonの関数、条件分岐、例外、`assert` の読み書きを前提とする。
pytestのパラメータ化やcoverage.pyの操作は例とともに説明する。
Rustやhoiminの内部実装の知識は必要ない。

第Ⅰ部と第Ⅱ部は、短いコードと手作業の変異から原理を学ぶ。
第Ⅲ部では、行と分岐のカバレッジが100%になる送料計算の教材を、AIエージェントとhoiminで調査する。
読者はJSONやJSONLを手で解析する必要はない。
エージェントに実行を依頼し、返ってきたコードの差分、仕様の根拠、検証結果を評価する。

AIエージェントにはローカルのファイル編集とコマンド実行ができる環境を使う。
特定の製品やモデルには依存しない。
利用に伴う料金、組織のコード持ち出し規則、実行権限は利用環境に従う。

## 教材と再現条件

[送料計算の教材ZIP](assets/shipping-workshop.zip)をダウンロードして展開する。
教材の仕様は[実習仕様](specification.md)、依頼文は[コピー用プロンプト](prompts.md)にも掲載した。
ZIPには初期テストと解答例が両方入っているが、通常のテスト実行では初期テストだけを収集する。

本書の操作例はhoimin 0.14.0を対象とする。
教材の依存関係は `requirements.txt` に固定する。
改訂後の版や別のOSでは表示や候補集合が変わりうるため、版と実行条件を報告に残す。
本書が目標にするのは、仕様を守るテストを増やし、その効果を確かめることである。

## 本書の背景

hoiminは、AIエージェントが限られた資源でPythonのテストを改善するためのCLIである。
開発の動機は、著者の記事[「ミューテーションテストツール『hoimin』の実装」](https://hayaosuzuki.github.io/articles/2026/2026-10-07-hoimin/)に記されている。
記事の背景を踏まえつつ、本書の操作と用途は[現在の製品方針](https://hayaosuzuki.github.io/hoimin/docs/product-principles/)に合わせる。
人間は仕様上の疑問を解決し、提案されたテストをレビューする。
