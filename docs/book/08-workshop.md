# 第8章 カバレッジ100%の料金計算

送料には、重量、会員区分、無料になる購入額、遠隔地への加算が関係する。
各条件を一度ずつ通すだけでは、境界や適用順序を十分に確かめられない。
短い送料計算を使い、行と分岐の100%が何を意味するかを実測する。

## 料金規則を読む

最初に教材の `SPEC.md` または[実習仕様](specification.md)を読む。
仕様はこの架空の料金制度の正解を定めるものであり、実装を見て期待値を決めるための資料ではない。
特に、次の境界と順序に注目する。

- 2000gを「超える」場合に重量加算する。
- 5000円「以上」なら通常送料を無料にする。
- 遠隔地加算は、その無料化よりあとに適用する。
- 商品合計額と重量が「両方0」のときだけ空注文にする。

会員で遠隔地、商品合計額1000円、重量3000gなら、500円に300円を加え、200円を引き、400円を加えて1000円になる。
商品合計額だけを5000円にすると、無料化が重量加算と割引の後に入り、最後に遠隔地加算400円が残る。

## 実装の読み取り

教材の `shipping.py` は次の実装である。

```python
def shipping_fee(
    subtotal: int, weight: int, *, member: bool, remote: bool
) -> int:
    if subtotal < 0 or weight < 0:
        raise ValueError("subtotal and weight must be nonnegative")
    if subtotal == 0 and weight == 0:
        return 0

    fee = 500
    if weight > 2000:
        fee += 300
    if member:
        fee = max(0, fee - 200)
    if subtotal >= 5000:
        fee = 0
    if remote:
        fee += 400
    return fee
```

この実装を改造するのが実習の目的ではない。
仕様どおりに書かれた元コードに対し、既存のテストがどんな誤りを見逃すかを調べる。

## 初期テストの確認

初期テストは、負数での例外、空注文の0円、いくつかの通常注文を確かめる。
通常注文では、具体的な金額ではなく次の性質だけを検査している。

```python
fee = shipping_fee(subtotal, weight, member=member, remote=remote)
assert fee >= 0
```

このテストにも意味はある。
負の金額を返す変更は拒めるが、500円と501円、300円と700円を区別できない。
わざと弱くした教材なので、実務のテストより不足が目立つと感じるかもしれない。
その単純化によって、カバレッジと検出力の違いを同じコードで測定できる。

## 行と分岐の測定

作業ルートで実行する。

```console
python -m coverage run --branch --source=shipping -m pytest -q
python -m coverage report -m
```

初期教材では、9件のテストが成功し、`shipping.py` は実行可能行15、未実行行0、分岐12、部分分岐0、合計100%になる。
`--branch` を指定した表示の `Cover` は、行と分岐の測定機会を合わせた割合である。
行と分岐を別に確認するにはJSONレポートを使える。

```console
python -m coverage json -o coverage.json
```

`shipping.py` の `missing_lines` が空、`missing_branches` が空であることを確認する。
表示上の丸めで100%になっただけかどうかも、ここで区別できる。

この測定は、複合条件の各要素や全組み合わせまで調べた証拠ではない。
また、通常料金の具体的な値を検査した証拠でもない。
初期テストを読んだときの不足は、100%という測定結果と矛盾しない。

## 調査前の予測

まだhoiminを動かす前に、どの仕様を見逃しそうか三つ挙げる。
候補の例は、送料無料の境界、重量加算、遠隔地加算の順序である。
実行結果を受け取ったら、この予測と照合する。
予測した問題に対応する変異が選ばれなかった場合も、予測が否定されたわけではない。
