# Ordered candidate phase implementation plan

> **For agentic workers:** Execute inline under the already approved Issue #912 design. Use the test-driven-development and executing-plans workflows; parent owns independent review and integration.

**Goal:** Represent ordered collection and execution as mutually exclusive private states.

**Architecture:** Keep `OrderedCandidateState.ids` as the stable, deduplicated request order. Replace its map, queue and completion flag with `OrderedCandidatePhase::Collecting { discovered } | Ready { remaining }`. Collection completion consumes the map; stopping consumes only the current phase's candidates in request order.

**Tech Stack:** Rust, existing core state-machine harness, proptest.

**Spec:** Issue #912, reproduced by the design contract below; evidence in [review record](2026-10-15-issue-912-review.md).

## Design contract

The private enum excludes a populated execution queue during collection and leftover discovered candidates after readiness. Missing selections still fail at end of collection in request order. Selected duplicates execute once; max_mutants counts real executions only. A collection stop reports only discovered selected candidates, never resumes reads, and rejects retired read completions without double accounting. Keep existing worker, completion-retirement, persistence and report logic; no public API, CLI, JSON, database or Lean model changes. VerificationSelection belongs to #911 and is outside this change.

The stop path replaces the phase with an empty Ready value while draining it. This records that collection has ended even when interrupted. Existing stop scheduling and effect-retirement rules remain authoritative.

## Review focus

1. Stop before any selected candidate is discovered: zero synthetic results.
2. Stop after all candidates are discovered but before EOF: only discovered results, in requested order.
3. Late read completion after cancellation/deadline: retired effect rejected.
4. Ready queue plus active worker: drain each selected ID exactly once.
5. Missing selection and budget boundaries: retain missing error and real-run budget.
