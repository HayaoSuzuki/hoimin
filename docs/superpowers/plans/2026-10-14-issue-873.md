# Issue 873: typed source decoding failure classification

For maintainers: preserve source-encoding diagnostics and candidate validation
precedence while removing the display-label discriminator.

Baseline: main `49a34a63ac4e995bfefb156f85ff3a934b594e6b`.
Branch: `codex/issue-873-typed-encoding`.

## Design review passes

1. Traced decoder failure construction and candidate validation. The implicit
   UTF-8 label is presentation data but is compared to select a typed error.
2. Compared implicit and declared UTF-8 inputs. Their classification intentionally
   differs, even though both may reject the same invalid byte sequence.
3. Reviewed public error construction. Preserve SourceEncodingError's two public
   fields and the public decoder signature; do not add required/private fields.
4. Chose a crate-private two-variant decoding failure carrying the unchanged
   diagnostic. The decoder determines origin from the encoding declaration,
   never from the label; candidate validation consumes the variant.
5. Checked compatibility and abstraction cost. A classified internal decoder and
   public diagnostic adapter hide one existing distinction without a registry,
   new external error format, schema/version-floor change or migration.

## Planning review passes

1. Write a regression before production edits that relabels implicit failure and
   gives declared failure the old implicit label; assert fixed variant outcomes.
2. Keep original mismatch before decoding errors. Existing candidate_policy tests
   already pin this ordering; rerun them rather than mirror each validation step.
3. Retain decoded_source's borrowed public diagnostic API using an internal
   diagnostic view, avoiding copies of decoded bytes or error text.
4. Run core source_encoding/candidate_policy and classification/library tests,
   formatting and core Clippy with two jobs/test threads and debug info disabled.
5. Update the existing analyzer OKF concept with precise source hashes; retain
   all evidence in this plan (outside design/report source catalogs). Clean only
   the dedicated target and publish through the root coordinator.

## Execution

The regression failed against the original implementation: changing the implicit
label returned InvalidEncoding instead of the expected InvalidUtf8 (one failed,
zero passed; initial compile 20.36s). After typed classification it passes, also
checking that a declared failure relabeled as the old implicit sentinel remains
InvalidEncoding. No deliberately failing public behavior was invented.

## Implementation review passes

1. Compared the decoder factory and codec branches with baseline. Only failure
   transport changes; declaration parsing, BOM checks and diagnostic text remain.
2. Verified the public decoder and SourceEncodingError fields/traits/signatures.
   The crate-private adapter preserves outward errors without new public fields.
3. Reviewed borrowed diagnostic access. decoded_source retains its exact public
   return type; no extra decoded source or diagnostic clone is introduced.
4. Checked candidate validation order. Metadata, original-byte comparison and
   decoding-error precedence are unchanged; only the discriminator is replaced.
5. Reviewed regression independence and fixture validity. Fixed enum expectations
   do not derive from a new helper; corrected the declared fixture line to two.
   Remaining literal label is diagnostic data/test input, not classification.
