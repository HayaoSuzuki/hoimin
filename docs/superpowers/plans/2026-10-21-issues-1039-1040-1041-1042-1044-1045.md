# Six performance fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Resolve #1039, #1040, #1041, #1042, #1044 and #1045 without changing public CLI results or validation.

**Architecture:** Keep indexes local to their existing ownership boundaries. Share verification validation between typed execution and preview preparation, cache traversal metadata once, and elide only proven-redundant output seeks.

**Tech Stack:** Rust 1.99, existing Tokio and Ruff crates, current Cargo.lock, existing heap/operation test utilities.

**Spec:** docs/maintenance/2026-10-21-issues-1039-1040-1041-1042-1044-1045/README.md and its six Issue acceptance specifications.

## Global Constraints

- Preserve candidate identity/order/span/diagnostics/truncation, source and manifest validation, deadlines, no-follow filesystem rules and cleanup ownership.
- One Cargo build at a time, `CARGO_BUILD_JOBS=2`, shared target, shared existing Python environment; monitor disk growth.
- No all-pairs or persistent caches, new saved formats, or lowered candidate limits.
- Use operation/allocation regressions for pass/fail; report release observations separately.
- Branch and worktree names include all six issue numbers; deliver one reviewable PR with issue-scoped commits.

## Review Focus

- Private and shadowed aliases, deferred functions, generic classes and prefix boundaries must retain the same candidates.
- Sparse and dense related classes must preserve constructor-policy versus visibility versus no-related reasons.
- Normal verify must not retain preview text, while all dry-run formats and selected order remain correct.
- Deep/non-UTF8 worker entries and reversed deletion must retain no-follow and depth boundaries.
- Exact output-ring boundaries, oversized chunks, deferred write errors and cancellation must preserve bytes and first errors.
