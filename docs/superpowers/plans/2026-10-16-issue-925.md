# Issue 925: candidate descriptor projection

This record covers the approved refactor from `MutationCandidate` to
`CandidateDescriptor`. Both types belong to core; core owns their projection
through `From<&MutationCandidate>`. Plan, review and workspace call it
directly. The two CLI helpers are deleted without compatibility wrappers.
The review store uses `CANDIDATE_SCHEMA_VERSION` for descriptor validation;
its SQLite version remains independent. Analyzer decoded/raw span conversion
continues to own a different responsibility.

## Design self-review passes

1. Ownership: read both type declarations and both projection helpers. The same
   ten descriptor fields are projected; `id` and `sequence` are intentionally
   omitted. Core already owns the identity and validation policies.
2. Call boundaries: searched all helper uses in plan, review and workspace,
   including tests. `From<&MutationCandidate>` accepts every existing borrowed
   candidate, so no forwarding API, allocation policy or caller flag is needed.
3. Identity: inspected descriptor-to-identity conversion and stable-ID validation.
   Projection must keep the current schema and metadata even when those fields
   do not participate in the stable hash; full-descriptor comparisons stay full.
4. Error precedence: read plan descriptor validation, review source observation,
   and workspace mutation preflight. Only the projection expression changes;
   file/hash/span/location checks and comparison order remain in place.
5. Scope: checked review store descriptor validation against SQLite user_version,
   and the existing survivor-review Lean corpus adapter. No format or semantics
   change needs a version bump, migration, reverse factory or new formal model.

Scoped software-design-philosophy score before change: 6.25/10, five of eight
rows established. Encapsulated change and clear ownership fail because callers
repeat projection policy; centralizing it in core addresses both. The design
work time ratio is unmeasured, so it cannot count toward 10/10. The selected
interface is the ordinary Rust conversion trait, with a comment explaining the
excluded bookkeeping fields rather than restating field assignments.

## Test design self-review passes

1. Existing behavior: selected the plan test
   `descriptor_validation_preserves_each_validation_and_stable_identity` and
   core candidate-policy tests to retain source, location and stable-ID coverage.
2. Review boundaries: selected the complete review unit scope for full descriptor
   mismatches and project/identity/descriptor rejection order. The existing Lean
   adapter independently varies every descriptor field and review history.
3. Workspace boundaries: selected mutation tests that reject hash, location and
   stable-ID mismatches without changing worker bytes. Their checks exercise
   the first observable consumer of the projection.
4. Property: add a core property that generates assigned IDs and sequence
   numbers, then validates the projected candidate against an independent valid
   descriptor fixture. Copying either bookkeeping value into fields used by source validation or
   stable identity must fail validation or change identity. This checks policy rather than
   repeating ten field assignments as ten assertions.
5. Structure: use explicit Arrange/Act/Assert blocks for that single invariant;
   generated strings and u64 values exercise bookkeeping beyond examples. Reuse
   existing parameterized validation cases and oracle rather than adding a
   redundant table. First run the new public conversion test before adding the
   trait implementation, then rerun it and relevant consumers after conversion.

## Implementation self-review passes

   or forwarding helper was introduced.
2. Borrowing: inspected every replacement in its containing function. The first
   CLI compile exposed three `&&MutationCandidate` map lookup arguments formerly
   handled by function coercion. Dereferencing each at the call site keeps the
   single borrowed conversion instead of adding another trait implementation.
3. Consumers: reviewed the complete plan/review/workspace diff. Full descriptor
   comparisons remain intact, and no validation, early return, source read or
   error mapping moved. The review test's existing descriptor import was reused

   literal became the core constant; SQLite version and schema definitions are
   untouched. Analyzer conversion and the Lean model/corpus have no changes.
5. Tests and footprint: inspected the new property's independent descriptor
   fixture and AAA blocks. It validates real source and identity instead of
   comparing copied fields. Existing tests only change conversion expressions
   and imports; no new dependency, wrapper, fixture API or Python code is added.
