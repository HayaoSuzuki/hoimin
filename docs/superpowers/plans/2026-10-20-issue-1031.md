# Ordered candidate replay implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` and TDD. Independent file ownership follows `superpowers:dispatching-parallel-agents`.

**Goal:** Remove selected candidate bodies from ordered execution queues while preserving dispatch and stop behavior.

**Architecture:** Core owns requested IDs, accepted discovery membership and worker state. I/O owns a sequential spool cursor and a selected-ID-to-position index. After one complete discovery scan, core requests one body at a time for an available worker; cancellation drains known IDs through the same indexed reads.

**Tech Stack:** Rust, existing core effects/events, bounded JSONL spool reader, Tokio blocking I/O ownership, existing Rust/Python/Lean-correspondence tests.

**Spec:** [Issue #1031](https://github.com/HayaoSuzuki/hoimin/issues/1031). Base: `3054427a1b1b9a7d2f5cdd1b6ce62053e6c417ac`.

## Global constraints

- One current internal API; no compatibility overload, legacy reader or package-floor increase.
- Core has no physical spool cursor or queued candidate bodies. I/O indexes selected IDs only.
- Preserve complete scan before ordered dispatch, first missing requested ID, last discovered body for duplicate spool IDs, stable requested order and one pending candidate read.
- Preserve budget observation, max-mutants accounting, NotRun output, truncated-plan handling and cancellation. A stopped scan reports only IDs accepted by core before the stop.
- No lookahead beyond an available worker. Worker/effect clones remain bounded by jobs.
- One sequential scan plus direct indexed reads; no per-candidate full rescan.
- Measure queue/index costs separately from plan loading, reports, child processes and whole-CLI RSS.
- AAA and one case per test function; use existing macro parameterization/property tests where useful. Record at least five design, implementation and verification reviews.

## Review focus

1. Stop between issuing an indexed read and accepting its result, including a repeated stop during NotRun drain, must retain that requested ID.
2. Retired sequential completions may update the I/O index but must not expand core's accepted stopped-report membership.
3. All requested IDs found early does not permit skipping the remaining spool: corruption and duplicate-ID replacement remain observable.
4. An indexed read must return the requested ID; missing/corrupt data is an infrastructure error, never normal EOF or an infinite retry.
5. Large payloads and reverse requested order must not grow waiting-body ownership or cause repeated prefix scans.

## Design reviews

1. **Ownership:** the existing cursor and payload queue expose spool concerns to core. The selected design moves physical positions to I/O and retains only logical IDs in core.
2. **Read scheduling:** preserve one pending read and use an idle worker as the admission limit. Concurrent indexed reads could reorder dispatch; extra prefetch is unnecessary.
3. **Complete discovery:** preserve EOF validation, first missing ID and last duplicate body. An index slot is replaced only after a successful record read.
4. **Stop ownership:** pending indexed reads retain their ID in the worker. Stopped queues contain references plus at most worker-owned bodies; retired scan results do not change accepted membership.
5. **Error and cost boundary:** reject wrong/missing indexed bodies and consume failed requests once. Count real record reads and measure live state before draining; plan/report allocation is outside the queue claim.

Using the software-design-philosophy diagnostic, the initial boundary satisfies
five of eight rows (6.25/10). Physical cursor propagation fails implementation
independence, spool ownership is not hidden, and the boundary requires reading
both implementations to understand. Logical requests, one I/O replay owner and
explicit ownership comments address those three rows; review the resulting
interfaces again after implementation rather than claiming a score in advance.
