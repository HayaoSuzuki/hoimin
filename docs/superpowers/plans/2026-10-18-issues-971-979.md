# Issues 971–979 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the nine approved design, integrity, liveness and resource findings and open a reviewable PR.

**Architecture:** Keep one owner for raw CLI arguments, discovery settings and analyzer session configuration. Enforce regular-file and independent-inode requirements at filesystem boundaries. Reject excess retained candidate payload explicitly, and avoid generating edits that selection will discard.

**Tech Stack:** Rust 1.99, Tokio, cap-primitives, Serde, proptest; existing Python documentation and quality tools.

**Spec:** Approved GitHub Issues [971](https://github.com/HayaoSuzuki/hoimin/issues/971), [972](https://github.com/HayaoSuzuki/hoimin/issues/972), [973](https://github.com/HayaoSuzuki/hoimin/issues/973), [974](https://github.com/HayaoSuzuki/hoimin/issues/974), [975](https://github.com/HayaoSuzuki/hoimin/issues/975), [976](https://github.com/HayaoSuzuki/hoimin/issues/976), [977](https://github.com/HayaoSuzuki/hoimin/issues/977), [978](https://github.com/HayaoSuzuki/hoimin/issues/978), [979](https://github.com/HayaoSuzuki/hoimin/issues/979). These written requirements and the preceding design decisions were approved before implementation was requested.

## Global Constraints

- No compatibility adapters, deprecated forwarding APIs or old-schema conversions.
- Shared mutation-target inodes must be rejected before permission or content changes. Automatic detachment to continue mutation is not the chosen behavior.
- Candidate payload is the first memory-control scope; do not claim an analyzer-wide RSS bound. Internal overflow fails explicitly, independently of user-requested count truncation.
- Run must not accept or fingerprint an ineffective discovery timeout; plan and verify retain one complete-discovery deadline.
- Preserve native test argv, selection, stable candidate IDs/order, applicable error precedence and cancellation/resource ownership.
- New/changed tests use AAA and one behavior per test case. Use bounded proptest for broad domains and named parameter cases for finite categories. Do not hide scenario-selecting assertions in helpers.
- Each task records at least five distinct self-review passes in each of requirements/design, implementation, verification and completion preparation. Record concrete findings, corrections or evidence, not a repeated approval sentence.
- One implementation worker and one Cargo invocation at a time. Use CARGO_BUILD_JOBS=2, CARGO_PROFILE_DEV_DEBUG=0, CARGO_PROFILE_TEST_DEBUG=0, CARGO_INCREMENTAL=0. Use the worktree target; no independent target per worker.
- Check target size/free space between tasks. Clean only this task's build outputs when necessary; preserve user files and unrelated targets.
- Run focused RED/GREEN checks while editing; run integrated workspace/contracts/lint/docs checks before the PR. Review each task independently and conduct a final whole-branch review.

## Review Focus

1. A baseline-created same-content, readonly hardlink must fail before chmod even when reset has not run (Task 1).
2. Existing review stores open protected source/fingerprint paths separately; those opens must not wait for FIFO writers (Task 2).
3. A bad candidate ID and missing source must preserve the existing ID-first diagnostic, including late-source placement (Task 3).
4. CLI and saved config changes must not normalize native argv to UTF-8 or silently accept old ineffective fields (Tasks 5–6).
5. Out-of-selection parents can contain selected children; memory limits span simultaneously retained producers and plan files, including eviction/cancellation (Tasks 8–9).
