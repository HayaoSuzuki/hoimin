# Issue 936: one saved fingerprint input list

The approved design removes `PlanManifest.fingerprint_inputs`. The single saved
list is `normalized_config.fingerprint_inputs`. This is a format redesign, not a
repair of inconsistent writer output. `sources` retains its mutation-target role.

Base: `5237d1e53a2c8b34fca80f6eeb7d644a01d732e2`.
Branch: `refactor/issue-936-single-fingerprint-inputs`.

1. Run the existing plan tests; add failing serialization/schema and reader tests.
2. Remove the duplicate field and comparison. Share schema-first decoding between

3. Keep nested record validation, current-file resolution, environment checks,

## Design self-review (five passes)

1. Ownership: `PlanConfig` already supplies runtime fingerprint inputs; retaining
   that representation removes knowledge duplication without a new abstraction.
2. Consumer audit: verify compares live records; review protects store aliases.
   Both must read the nested list. Source records have a different role and stay.
3. Decode ordering: `deny_unknown_fields` would hide regeneration guidance in
   review. A shared private decoder checks schema before typed deserialization.
4. Execution boundary: `VerifiedPlan`, environment validation, copy-manifest
   filtering and pre-execution rechecks remain necessary and outside removal.
5. Compatibility: reject all previous schemas, reject the old field even under
   current schema, and publish explicit regeneration instructions. No migration.

Design diagnostic score: 7.5/10 before the change (six of eight diagnostics).
Implementation independence fails because one input-set decision leaks through
two persisted fields and callers. Removing the duplicate and sharing decoding
addresses it. The design-time allocation diagnostic is unmeasured; no claim of
spending 10–20% on design is made. After this change, seven of eight diagnostics
pass (8.75/10); time allocation remains unknown.

## Decoder regression and preview-schema correction

The external reviewer found that decoding through `serde_json::Value` before
`from_value` discarded duplicate known keys. Review had previously rejected
these during typed decoding. A new raw-JSON parameterized test covers duplicate
`kind` and nested `fingerprint_inputs` through both readers; it failed with an
actual accepted review result (`Ok(())`) before the fix. The shared decoder now
checks schema using the temporary value, drops it, and decodes the original bytes
with typed `from_slice`. Review retains its prior behavior and verify now rejects
those duplicates too. No generic parser or adapter was added.

`line_diverse_public_reports_and_previews_match_current_schemas` and

embeds the plan version; updated its constant to 8 while retaining preview schema

and report-handler checks and a final full-workspace run follow both fixes.
