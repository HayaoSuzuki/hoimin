# Owned writer delivery implementation plan

> Execute inline using the executing-plans, TDD, software-design-philosophy, technical-documentation and verification-before-completion skills.

**Goal:** Remove borrowed writer execution compatibility and use owned deadline-aware delivery for every run and verify entry.

**Architecture:** One `run_with_writers` dispatcher owns `Write + Send + 'static` outputs; `run_from` delegates with stdio. Short commands use local synchronous outputs. Run and checked-plan execution transfer outputs into report delivery, with one error-reporting responsibility.

**Tech Stack:** Rust/Tokio, owned synchronous `std::io::Write` operations, Python and MkDocs documentation checks.

**Spec:** [Issue 889](https://github.com/HayaoSuzuki/hoimin/issues/889), base `056cb558953ddf5eb8b229976ee894ae7c6bc87f`.

## Constraints

Keep write/flush deadlines, in-flight ownership, delivery leases, cancellation, cleanup order, metrics, exit codes and stream routing. No borrowed compatibility wrapper or buffering adapter. No new dependency or schema. Internal Rust APIs have no independent stability promise under `docs/compatibility.md`; retain 0.6.0 unless final public CLI diff requires otherwise. ## Design reviews

1. Compared `lib.rs` dispatches: both interpret run/verify independently. Replace with one owned dispatcher; argument parsing remains once.
2. Traced `run_loop`, `run_loop_with_control`, `run_owned_loop`, `run_verified` and `VerifiedPlan::execute`: borrowed bounds and optional factory propagate two reporting contracts. Keep controlled execution but require owned writers throughout runtime.
3. Inspected report task state: a cancelled join must retain running writer and delivery owner. Preserve task-owned lease and admission checks; do not abort a started blocking write.
4. Inspected finalization diagnostic: owned delivery emits loop failure once, while preparation errors require dispatcher reporting. Preserve distinction by execution boundary rather than writer mode.
5. Compared compatibility policy and short-command behavior: Rust source callers migrate; CLI/saved formats and synchronous progress/review need no new lifecycle or floor change.

Provisional design score: 7.5/10. Removal reduces mode knowledge and duplicate dispatch, but delivery/context generics and cross-cutting shutdown knowledge still need implementation review. Design fraction is unmeasured; no full-score claim.

## Implementation reviews

1. Compared the single dispatcher against the previous two matches: parsing occurs once, run/verify ownership transfers once, dry-run preview and short commands use local synchronous writers.
2. Removed `OwnedReportFactory`, `owned_report: Option`, `ReportDelivery::Inline` and optional admission. Every runtime output now uses the retained task driver, and its deadline/interrupt branches are unconditional.
3. Erased writer generics from `ShellContext` and context-only helpers. Actual type erasure already occurred in owned delivery; this removes propagation without adding an interface or speculative policy.
4. Traced setup failure ownership: setup runs before output attachment; error stderr transfers to `write_terminal_error`. Once attached, the shell finalization path owns diagnostics. Dispatcher does not reprint shell errors.
5. Traced blocked writer ownership: `spawn_blocking` still moves the handler, admission and delivery-root lease into its closure; cancellation leaves the join handle retained. Driver drop marks admission abandoned; no started operation is aborted. Existing spool/root and failure assertions are retained with owned capture snapshots.
