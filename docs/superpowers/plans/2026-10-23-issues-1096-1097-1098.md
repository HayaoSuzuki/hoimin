# Dependency reduction implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. The user has authorized issue creation and implementation of the previously proposed replacements.

**Goal:** Remove fs2, crc32fast and clap_complete without adding dependencies.

**Architecture:** Use standard-library file locks with typed contention errors. Keep the coordinator's two 512-byte slots, replacing CRC32 with a full 32-byte BLAKE3 digest and advancing the schema to 2. Remove the completions command and regenerate CLI documentation.

**Tech Stack:** Rust 1.99, std, existing blake3/clap, Cargo, Python documentation checks.

**Spec:** GitHub issues #1096, #1097 and #1098; the user's accepted dependency-reduction proposal. No compatibility support is required. New coordinators use hoimin-workspaces-v2 so an old persistent coordinator cannot block a fresh execution; the old namespace is untouched.

## Global constraints

- Work only on refactor/issues-1096-1097-1098, based on main 393f00c3.
- Two Cargo build jobs, incremental disabled, no dev debug information; reuse one target.
- No new dependencies, OS lock shims, old-format readers or command aliases.
- Preserve process-local serialization, lock deadlines, RAII release, lease inheritance and source safety.
- The checksum is corruption detection, not authentication. Schema 1 files are refused without rewriting them.
- Keep existing formal proofs and historical implementation/audit records.

## Review focus

- Separate handles/processes must contend and allow acquisition after release.
- Non-contention I/O failures must remain failures, not retries.
- A damaged newest slot must fall back to the intact older slot; two invalid slots must fail closed.
- Old-format coordinator files must be rejected without modification, including files with valid old checksums.
- Root/help/reference must omit completions; invocation must fail with no script on stdout.
