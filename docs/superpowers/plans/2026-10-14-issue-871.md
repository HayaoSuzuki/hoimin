# Issue #871: checked AST acquisition

This record is for maintainers reviewing ownership and behavior across symbol validation, mutation analysis, and exception indexing. Baseline: main `49a34a63ac4e995bfefb156f85ff3a934b594e6b`.

## Design

Keep one internal entry point beside the depth walker. It retains unchecked parser ownership, checks syntax before depth, and disposes every rejected tree through Ruff's nonrecursive cleanup. A successful result retains the parser's module and tokens. The three callers own their existing presentation policies. Cancellation before parse remains in each existing caller; the entry point polls only through the existing depth traversal. Depth remains 128, counting the module as one and auxiliary visitor nodes as children.

Sequential design reviews:

1. Traced all three production call sites: each has the same ownership sequence. No other production `parse_unchecked_source` caller requires migration. The helper belongs in `rust/depth.rs`, without another module or framework.
2. Compared invalid-source outcomes: symbol definitions return their exact string; analysis returns its existing empty-candidate diagnostic; hierarchy retains the source hash and skips summary creation. Keep these adapters separate.
3. Compared observation order: mutation analysis checks cancellation and supplied hierarchy source identity before parsing; hierarchy checks mapping and per-module cancellation first; symbol validation does not cancel. The helper must not add an entry cancellation poll.
4. Traced destruction on syntax error, depth overflow, and cancellation. Unchecked parse is essential for invalid partial trees; a convenience checked parser would recursively drop them. Successful trees are bounded and may drop normally.
5. Assessed abstraction cost using the eight software-design diagnostics: baseline score 7.5/10: implementation-change isolation fails because the disposal sequence lives in three callers, and the time-investment ratio is unmeasured. A small checked-parse API centralizes that decision; the interface documents validity, depth, cancellation timing, and ownership. The isolation change targets seven confirmed diagnostics (8.75/10); measuring the time-investment ratio is outside this refactor. No public interface, schema, ranking, candidate ID, exit code, or version floor changes.
