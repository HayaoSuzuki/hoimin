# Issue 881: Current-schema report reader

Baseline: `97c394760bc02a56be0bfdeb6301257eac80d1c7`. Scope approved by Issue 881 and the implementation request.

Progress accepts only `REPORT_SCHEMA_VERSION` (4), in JSON documents and JSONL streams. Remove the v2 document/summary types and four legacy functions, v2 routing, and v3 acceptance without an adapter. Preserve opaque normalized configuration, current synthetic null terminations, validation and streaming/fingerprint behavior. Review stays current-schema JSON only.

## Design self-review

1. Traced v2 routing, deserialization and duplicated validation: all belong to removed support; core result checks remain shared.
2. Compared current JSON and JSONL paths: both end at `validate_document`; JSONL additionally checks full lifecycle using `ReportSequence`.
3. Examined `ProgressRunStarted` versus `RunStarted`: retain the former because progress intentionally accepts opaque configuration. Reuse would impose unrelated configuration policy.
4. Examined null termination: current reused/not-started/synthetic results depend on it; keep `MutantFinished::validate_result` unchanged.
5. Checked evidence claims: Lean models do not encode schema versions. Existing historical runs are evidence at their recorded revision, while adapters need current-schema fixtures.

Design diagnostic: seven of eight rows confirmed (8.75/10); the time-investment row remains unmeasured until execution evidence. The single current validation path removes change amplification without adding an interface.
