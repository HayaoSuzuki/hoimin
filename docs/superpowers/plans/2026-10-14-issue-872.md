# Shared workspace creation and reset policy (#872)

Maintainers use this record to review ownership and recovery in synchronous handlers and production owned tasks.

## Design

A private operation result returns an active workspace on success or an error and optional pending workspace on failure. Shared create and reset functions own validation, cleanup and recovery policy. Prepare/execute/accept ownership and parallel execution remain intact. Apply retains its distinct candidate contracts.

Sequential design self-review passes:

1. Traced production prepare/execute/accept and synchronous callers; consolidate operation knowledge without replacing lifecycle ownership.
2. Compared create branches: grant validation precedes pending cleanup; cleaned ownership is dropped before replacement; copied import roots are checked before publication.
3. Compared reset failures: successful discard releases ownership; failed discard retains pending ownership; depth errors take precedence over cleanup errors.
4. Checked signatures and accounting: candidate arguments, reservation identity, worker slots and copy accounting remain unchanged.
5. Eight design diagnostics: baseline 6.25/10 (five confirmed rows, two failures, one unmeasured); implementation independence and hidden operation knowledge fail because recovery is duplicated. Target seven confirmed diagnostic rows (8.75/10); elapsed-time investment is not independently measured. Private documented result ownership and one implementation address the two identified failures. No generic framework or new state transitions.
