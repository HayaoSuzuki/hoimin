# Issue 924: Windows root cleanup authority

Approved scope: [#924](https://github.com/HayaoSuzuki/hoimin/issues/924).
This is a private representation change in `workspace/owned.rs`:
`RootCleanupAuthority::{ByName, Pinned(Dir), Consumed}` replaces the boolean
and optional root handle. `lease_guard` stays independent. No CLI, schema,
namespace lifecycle, lock, deadline, or compatibility changes are intended.

## Design review (five passes)

1. State coverage: `ByName` maps false/None, `Pinned` maps true/Some, and
   `Consumed` maps true/None. The meaningless false/Some case disappears.
2. Authority lifetime: take with `mem::replace(..., Consumed)`, restoring
   `Pinned` only while the original handle still exists after validation or
   deletion API failure. A post-deletion metadata error cannot restore it.
3. Independence: missing lease with a retained root is valid after marker
   deletion. Owner take/restore and janitor queue must retain this state.
4. Scope: owner `rename_handle`, namespace lifecycle, lock ordering, deadline
   checks, and handle close ordering remain outside the enum and unchanged.
5. Simplicity: software-design-philosophy score 8.75/10 for the proposed change
   (seven of eight diagnostics established). The time-investment row is
   unmeasured; reaching 10/10 would require recording the design-time ratio. One private type
   hides one state decision, leaves existing interfaces intact, and documents
   why `Consumed` is not an absence guarantee. No new hooks or abstraction
   layer are needed.

## Test review (five passes)

1. Mutation targets: losing a root pin on deletion failure must break retry;
   treating consumed authority as by-name must delete a replacement sentinel
   and fail; restoring authority after deletion must fail the consumed check.
2. Real boundaries: a nonempty directory forces the real Windows deletion API
   to fail. Invalid-NUL metadata lookup and an existing named entry exercise
   the two post-deletion error branches without mocking deletion.
3. Owner integration: after removing lease and failing root removal, restore
   capabilities into the owner and invoke normal cleanup. This exercises the
   root-present/lease-absent handoff rather than only a private-state check.
4. Replacement protection: supply the replacement's own identity on retry.
   Identity mismatch cannot hide accidental fallback to by-name cleanup.
5. AAA and independence: each test has one failure boundary; the two
   postcheck outcomes are table-driven. Existing owner/janitor/child tests
   cover normal paths. Expectations use filesystem effects and literal
   sentinel contents, not a second implementation of the state machine.

## Formal correspondence

`workspace/cleanup_capability_oracle_tests.rs` compares the existing Lean
corpus with Unix capability cleanup and distinguishes model-only schedules.
The five scenarios remain stable-entry, preexisting link, post-inspection
swap, post-binding swap (model-only), and retained-wrapper swap. This edit
changes no admission, retry ordering, quiescence, or underlying deletion
semantics; a new Lean model is unnecessary. Those tests and
`partial_cleanup_preserves_lease_markers_and_owner_resume_completes` are Unix
regression evidence only, not evidence for Windows authority transitions.

## Implementation review (five passes)

1. Reference sweep: all `exact_root` and `CleanupCapabilities.root_pin`
   references were replaced. Local `root_pin` variables remain ordinary
   owned handles, with no compatibility fields or adapters.
2. Constructor and handoff audit: default is `ByName`; claimed construction
   and owner resumption without a lease are `Pinned`. Restoration moves only
   a `Pinned` handle into `rename_handle`; janitor queues retain the same
   capability object.
3. Failure audit: owner-verification failure, identity mismatch, identity
   lookup failure, and guarded deletion failure each restore the original
   pin. Successful deletion drops its handle before checking the name and
   never restores authority after that check.
4. Branch-order audit: consumed opening still performs only an absence
   probe, without adding a deadline check. Pinned opening keeps its original
   deadline/owner/identity/deadline sequence. Lease marker handling includes
   both `Pinned` and `Consumed`, exactly as the previous true flag did.
5. Test adversary audit: added a fifth test for direct root removal of an
   empty same-name replacement, because nonempty-only assertions could mask
   accidental by-name fallback behind a directory-not-empty error. The test
   first verifies consumed absence can be observed, then checks the new
   entry is preserved even with its own expected identity. No production
   hooks or extra interfaces were introduced.
