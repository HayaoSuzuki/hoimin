# Issue 874: command-local review source validation

This plan records the implementation and evidence for maintainers reviewing
source validation reuse. Baseline: main 49a34a63ac4e995bfefb156f85ff3a934b594e6b.

## Design

Group selected candidates by their root-relative path. Process one group's
bounded source bytes and validation context at a time, then drop both before
loading the next file. Return candidate-specific Results in original order.
The rendering loop consumes those Results at the same point as the previous
source_state call, preserving source/applicability/execution error precedence.
Keep record_store's independent freshness check.

A file is observed once during a display command. Candidates for that path
share that observation even when interleaved with other paths. Different files
are not an atomic snapshot. A subsequent command and the record freshness
check read again; no cache survives a command.

### Sequential design self-review

1. Traced run -> source_state -> bounded_read -> CandidateValidationContext.
   Repeated reads, decoding, indexing and hashing are the actual repeated work.
2. Compared grouping with retaining an all-file cache. Group-local ownership
   bounds source storage to one file plus per-candidate result metadata.
3. Checked candidate hash precedes descriptor/encoding validation. A stale
   candidate must remain stale even with an invalid descriptor; preserve this.
4. Checked interleaved paths and first-error precedence. Eagerly returning an
   error from a file group would reorder failures; retain individual Results.
5. Checked record semantics and root containment. Preserve standalone
   source_state for record; group only identical lexical paths and use the
   existing normalized-path and canonical-root checks.

Design score: 8.75/10, seven of eight diagnostics supported by static design
review. Group ownership, information hiding, ordered results, and freshness
policy are explicit. Strategic improvement over time remains unassessed;
runtime evidence and implementation review are still pending.

## Implementation plan

1. Add counters at real source-read and context-construction sites under
   cfg(test), then a run-level regression requiring one of each per source.
2. Observe the regression fail before modifying production behavior.
3. Extract grouped validation while retaining standalone source_state.
4. Add interleaved order, individual validation, unavailable/encoding/root,
   stale precedence and first-error regressions.
5. Run focused review tests, CLI review integration tests, the Lean corpus
   adapter, formatting, Clippy, and OKF structure/reference checks.

## Implementation self-review

1. Compared each old source_state branch with the shared file path: normalized
   relative paths, canonical containment, bounded reads, and unavailable states
   keep their previous messages and precedence.
2. Checked candidates sharing a path are independently validated against their
   own hash, span, original, location, mutation, encoding and stable identity.
   Changed the descriptor regression to put the invalid candidate after a
   valid candidate in the same batch, catching state reuse across candidates.
3. Checked interleaved paths explicitly: groups are visited in first-occurrence
   order, results are indexed back into original positions, and an earlier
   other-file error wins over a later same-file error.
4. Inspected lifetimes: source_states_for_file returns only result metadata.
   Its bytes and borrowed context are dropped before the next group's load.
   Empty batches never call the nonempty private group helper.
5. Compared record_store and rendering separately. record_store still calls
   source_state independently, and run consumes deferred source errors at the
   old location before applicability/execution. Root's independent static
   review found no actionable defect; no extra abstraction was introduced.
