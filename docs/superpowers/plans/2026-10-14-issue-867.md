# Issue 867: Typed cleanup classification

## Design

Keep cleanup kind and retry eligibility as internal typed evidence until report formatting. CleanupRecord is an internal non-serialized carrier: report construction explicitly projects its existing fields. Attach an optional CleanupRetryReason::CoordinatorContention, set only when process or file coordinator admission reports contention. The shell retains the absolute deadline and ten-millisecond retry delay.

ManagedCleanupOutcome owns the single conversion to DiskCleanupOutcome. Failure messages remain display data. Recordless cleanup accepts CleanupThreadFailure directly; unknown root identity forces deferred status even for stopped/spawn failures. Marker-operation failures retain their known active path, since marker work cannot claim or rename it.

Scope: retain CleanupProgress, DiskLifecycle, cleanup admission, janitor transfer, acknowledgement, primary/secondary errors and bounded detail. No report fields, schema, default, CLI, platform, package, or version floor change; patch-compatible internal refactoring under docs/compatibility.md. Existing Lean models remain applicable because no transition, deadline, retry-admission condition or ordering changes.

### Design review passes

1. Traced all reported boundaries against ordinary execution. Found three combined Failed/Deferred arms parsing diagnostic prefixes, while ordinary execution already matches typed variants. Central conversion must cover all four paths.
2. Examined marker and actual-cleanup thread failures. Found the stable-path distinction: marker cannot rename; cleanup may. Retain the marker Some(path) and actual-cleanup Spawn-only path evidence.
3. Traced contention creation in workspace cleanup. Local WouldBlock and file lock busy yield Deferred; poisoned and other file failures remain Failed. Attach the reason only to those two busy returns, and require Deferred in the eligibility method.
4. Compared carrier extension with a new wrapper result and general error taxonomy. A single optional reason on existing internal CleanupRecord adds no new result pipeline or public schema. Keep other deferrals untagged.
5. Reviewed safety claims against runtime lifecycle and compatibility concepts. Refactoring does not prove cleanup or acknowledgement completion. Preserve unknown identity, original deadline, nonduplication and janitor behavior; record execution evidence separately.

Design diagnostics: baseline 7.5/10 (implementation-change locality and obvious boundaries fail because shell knows diagnostic wording). Target 10/10 for this boundary: the type owns meaning, workspace owns contention, shell owns scheduling; interface comments state invariants. This is a scoped interface assessment, not a whole-repository score.
