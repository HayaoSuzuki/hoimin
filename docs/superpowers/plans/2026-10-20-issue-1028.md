# One progress output schema implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` and TDD. Check off steps only after observing results.

**Goal:** Implement #1028 with one current JSON output contract independent of the details flag.

**Architecture:** Rendering always emits schema version 3 with a required nullable `details` field. Null means details were not requested; a requested object retains its existing availability/eligibility fields, including an unavailable comparison. Comparison and exit-policy logic remain unchanged.

**Tech Stack:** Rust/Serde, existing JSON Schema and Rust/Python schema/golden tests.

**Spec:** [#1028](https://github.com/HayaoSuzuki/hoimin/issues/1028). User approved this as a separate PR from analyzer performance work. Base: `1f7feae33fa310aae87fbadb390105f6d770439d`.

## Global constraints

- One canonical current schema at `docs/json-schema/progress-result.schema.json`; remove the separate v2 schema and obsolete byte-compatibility tests, not semantic tests.
- Always emit `schema_version: 3`; require `details`, with null for not requested and an object for requested details, even when unavailable.
- Preserve comparisons, aggregate counts, stalled/saturated decisions, exit codes, transition ordering and details-limit semantics.
- Preserve the current run-report input contract, human output and CLI flag names. Add no old-version flag or parallel reader.
- Update compatibility/migration notice and version-floor files according to actual stable release state and `docs/compatibility.md`.
- AAA and one test case per function; parameterize equivalent cases. Record at least five design, implementation and verification reviews.

## Review focus

1. Details omitted by the user differs from requested but unavailable details.
2. Limit zero changes displayed transitions only, preserving aggregate decisions and exits.
3. Equal/unequal/duplicate candidate sets and unusable reports preserve their existing classifications.
4. Schema validation must reject missing details and superseded versions without preserving a second current schema.
5. Documentation, packaged assets, Rust/Python fixtures and release-floor lockfiles must agree with the single public contract.
