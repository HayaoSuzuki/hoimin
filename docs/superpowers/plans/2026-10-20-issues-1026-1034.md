# Target selection, report input, and preparation timeout implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` for each domain and `superpowers:dispatching-parallel-agents` for the independent domains below. Check off steps only after observing their results.

**Goal:** Implement issues #1026, #1027, #1032, and #1034 against `05c909c5`.

**Architecture:** The target adapter owns one Git runner for environment policy, cancellation, and child completion. The report reader consumes the event discriminator before validating closed payloads without discarding duplicate keys. The shell starts one deadline at the specified run/verify boundary and carries it through preparation, execution, and shutdown.

**Tech stack:** Rust, Tokio, Serde, existing process gates and managed workspace roots.

**Spec:** [#1026](https://github.com/HayaoSuzuki/hoimin/issues/1026), [#1027](https://github.com/HayaoSuzuki/hoimin/issues/1027), [#1032](https://github.com/HayaoSuzuki/hoimin/issues/1032), [#1034](https://github.com/HayaoSuzuki/hoimin/issues/1034). These issue bodies contain the accepted behavior and acceptance criteria.

## Global constraints

- Preserve current selection, report version 9, status/ID validation, and error contracts; add no compatibility path.
- Keep target Git environment policy local to its subprocesses.
- Preserve duplicate JSON keys until typed validation.
- Use one run deadline and the existing two-second shutdown grace. Stage transitions cannot extend either deadline.
- A running blocking operation retains its resource owners until completion. Expiring its waiter does not prove completion.
- A normal total timeout returns incomplete/exit 4; infrastructure or shutdown failures remain exit 2.
- Keep plan behavior, verify prevalidation, and dry-run scope unchanged.
- Use AAA tests with one case per function, parameterized where appropriate. Prefer controlled clocks and start notifications.
- Record at least five design, five implementation, and five verification reviews per issue, with evidence and limits.

## Review focus

1. Ambient Git settings must not alter IDs, candidate order, context ranking, or saved configuration on either scoped or rename diff paths.
2. Cancellation during a later Git command must prevent another command from starting and retain ownership through reap and pipe completion.
3. Closing event payloads must still accept the producer's nested raw fields and reject duplicate discriminators and nested known keys.
4. Cancellation or deadline expiry racing setup completion must prevent baseline dispatch and retain live managed roots.
5. Preparation rollback, late completion, and blocked diagnostic output must share the original shutdown deadline.

## Design review record

1. Scope: the four issue bodies define current behavior; no schema migration, sandbox, gc command, or new formal proof is required.
2. Dependencies: #1026 and #1032 share one runner; #1034 consumes its termination contract. #1027 can proceed independently.
3. Ownership: process completion requires reap and pipe completion; setup timeout requires retained blocking owners. Neither future drop nor `kill_on_drop` alone meets the contract.
4. Input boundary: a tagged Serde enum that buffers through `Content` can break nested `RawValue`. The report worker will validate the chosen streaming envelope against current producer data.
5. Observability: each change needs a pre-fix failure, post-fix behavior, and explicit evidence limits. Expected cancellation must not become a generic target error/exit 2.
