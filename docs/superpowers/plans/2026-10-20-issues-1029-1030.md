# Analyzer work admission and exception visibility implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` within each domain and `superpowers:dispatching-parallel-agents` for the independent tasks. Check off steps only after observing results.

**Goal:** Implement #1030 and #1029 without changing selected candidates or exception visibility.

**Architecture:** Reject out-of-selection whole-call candidates before optional-keyword enumeration and replacement construction while continuing child traversal. Resolve a module's eligible exception members once and reuse them across import aliases; retain importer-specific resolution and visibility rules.

**Tech Stack:** Rust, existing analyzer selection/name-resolution types, operation counters and release allocation/timing probes.

**Spec:** [#1030](https://github.com/HayaoSuzuki/hoimin/issues/1030), [#1029](https://github.com/HayaoSuzuki/hoimin/issues/1029). User approved these together; #1028 is implemented on a separate branch. Base: `1f7feae33fa310aae87fbadb390105f6d770439d`.

## Global constraints

- No compatibility path, operator default, candidate identity, ranking or saved-schema change.
- Preserve call-start selection semantics, child traversal, candidate order/replacements, payload budgeting, truncation and cancellation.
- Preserve loaded-module, ambiguity, shadowing, import-depth, candidate-order/ID and diagnostic contracts for exception visibility.
- Account separately for unavoidable alias × visible-class output. Do not promise a bound independent of output size.
- Measure release wall time, cumulative requested allocation and retained/peak requested heap separately; none is RSS.
- Include small-input cost and deterministic operation gates. Do not turn noisy wall time into a CI threshold.
- AAA, one case per test, parameterized/property coverage where useful; observe meaningful failures before fixes.
- Record at least five design, implementation and verification review passes per issue. Current development instructions prohibit cargo-mutants.

## Review focus

1. A selected expression inside an excluded multiline call still produces its own candidates.
2. Zero payload budget and varying candidate limits must not trigger excluded optional replacement builders.
3. Alias spellings, imported descendants and shadowing must retain the same resolution and ordering.
4. The eligible-member cache must not undercount actual visible outputs or silently bypass summary limits/cancellation.
5. Benchmark fixtures and setup allocation must be separated from the measured production operation.
