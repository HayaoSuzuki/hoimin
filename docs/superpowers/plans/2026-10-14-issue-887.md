# Issue 887: typed environment snapshots

## Approved design

`RunConfig<E = EnvironmentSnapshot>` has one state parameter. CLI normalization creates `RunConfig<EnvironmentRequest>`; preparation consumes it and creates the default snapshot configuration. Execution, plans, reports, and fingerprint inputs accept snapshots. This avoids duplicating all configuration fields or carrying pending and captured variants into execution. The transition rebuilds the configuration once and checks that snapshot names match the request.

`EnvironmentRequest` owns canonical names. `EnvironmentSnapshot` distinguishes `Untracked` and `Captured`; the captured payload has private names and digest, checked on construction and deserialization. Values stay in native OS representation and only enter the aggregate digest. No environment value is persisted or included in diagnostics.

Plan schema 5 becomes 6 and report schema 4 becomes 5 because normalized configuration changes to one tagged `environment` snapshot. Fingerprint schema remains 11 only if a golden comparison confirms identical framing. Existing omitted metadata is a valid current untracked encoding, not evidence of an exclusively legacy format. The new schema writes explicit untracked state; old plans require regeneration. Existing sessions are never converted or deleted.

## Design reviews

1. **State separation:** inspected `config.rs` and `shell.rs`; independent names/hash plus `prepared` allow inconsistent states. Approved one state parameter rather than a second complete configuration struct.
2. **Invariant ownership:** inspected `fingerprint_env.rs`; constructors and custom deserialization must enforce canonical nonempty captured names and lowercase 64-digit digest. Captured fields remain private.
3. **Native semantics:** inspected CLI capture implementation; preserve Windows name uppercasing and UTF-16 units, Unix bytes, absent/empty discriminator, and length framing.
4. **Persistence:** inspected current writer omission test and plan verification; default omission is current behavior. New explicit snapshot requires plan/report schema changes, not a historical-only adapter.
5. **Interface cost:** inspected execution and fingerprint callers; default snapshot keeps trusted boundaries readable, request type is explicit only at ingress. Seven of eight software-design diagnostics are supported; the design-time fraction is unmeasured and receives no claimed point (8.75/10).

## Implementation reviews

1. **Construction boundary:** implemented private request names and private captured payload; both constructor and deserializer enforce canonical names, nonempty captured selections, and lowercase 64-digit digest. Untracked carries no metadata.
2. **Phase transition:** the single environment parameter changes only through `with_environment`, which checks exact selected-name equality. Root review retained request-taking `run_loop`/`plan::create` frontends as deep modules; they capture once and pass snapshots into execution, fingerprint generation, and persistence. A brief stricter frontend draft was reverted before compilation because it spread preparation into callers.

Root review found newly historical schema 4 missing from progress rejection matrices; added it and updated only live oracle encoding labels to version 5.
5. **Interface and scope:** documented generic validation as common-field validation, leaving environment invariants to their constructors. No environment OS reads moved into core, no generic state framework/sealed trait was introduced, and CLI argument vectors remain raw at the parse boundary. Manifest/lock changes only raise local package floors to 0.7.0 and both deny ranges to `>=0.7.0, <0.8.0`.
