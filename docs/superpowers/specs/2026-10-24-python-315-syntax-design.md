# Python 3.15構文と上流Ruffの取り込み

Python 3.14・3.15の実行環境対応に続き、3.15の構文をhoiminの解析対象にする。
利用者は2026-10-24に、上流が対応済みであれば独自の構文移植より上流取り込みを優先すると指定した。

## 上流の固定と依存関係

Ruff 0.17.2、コミット `30516b42ab972ffa2569e5efcfee81135da466d3` を使用する。
この版のparserにはPEP 810の遅延importとPEP 798の内包表記アンパックが実装されている。
parserのソースを既存のvendorへ更新し、AST・trivia・text-size・Unicode処理とそのビルド依存は同一コミットのvendorソースで揃える。
Ruffの別の解析器やCLIは取り込まない。
依存するvendorソースをsdistから再構築できることと、SBOMが実際のソースを識別することを検証する。

## 解析時の意味

`lazy import`と`lazy from`、リスト・集合・辞書内包表記およびジェネレーター式のアンパックを扱う。
辞書内包表記のアンパックは上流ASTの表現に従い、存在しない子ノードを訪問しない。
遅延importから得た名前は、既存の静的な標準ライブラリ由来の証明にそのまま使わない。
`__lazy_modules__`による暗黙の遅延importも保守的に扱う。
通常の名前参照が起こす例外、スコープ、注釈、ミューテーションのソース範囲を回帰テストで確認する。
新しい組み込み型を使うコードを受け付け、標準ライブラリの名前一覧は両バージョンの和集合を維持する。
新しい専用ミューテーション演算子は追加しない。

## 既存の安全策

parserの再帰チェックを有効にし、128 KiBのred zone、1 MiBの拡張単位、各チェック地点での検査を維持する。
文脈付与・代入先検証・回復処理の再帰保護、投機的ASTの反復破棄を更新後も維持する。
hoiminの深さ128の制限と構文エラーを含むASTの破棄を維持する。
f-stringとt-stringが混在するエラー回復の既知のクラッシュを再検証する。

## 受け入れ条件

既存の解析・深さ・配布・SBOM・CI設定テストを通す。
追加構文の候補を変異後も3.15.1でコンパイルし、3.14.9では既存構文の回帰を検証する。
両バージョンでPythonテストとRustテストを実行する。
各段階で5回以上セルフレビューし、結果を保守記録に残す。
並列ビルド数を2に制限し、ビルドキャッシュを再利用する。
