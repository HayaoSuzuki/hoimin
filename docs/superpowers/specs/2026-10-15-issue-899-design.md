# Issue 899: Typed changed selection

The normalized `Selection.changed` is `Option<ChangedSelection>`. `None` disables Git selection and cannot carry context or a base. `Some` contains a private `context: u32` and optional base, created through a constructor that rejects context above 1073741823. Read-only accessors expose the values to target resolution. Serde deserialization uses that constructor and rejects unknown object fields. The required context has no compatibility default.

The serialized shape is `"changed": null` or `"changed": {"context": 2, "diff_base": "main"}`. An absent base remains distinct from an explicit base: the former uses HEAD/worktree behavior; the latter uses merge-base/worktree behavior. Selection rejects unknown fields, including obsolete sibling `changed_context` and `diff_base`; boolean `changed` is rejected. No migration or compatibility adapter is added.

`RawRunConfig` and CLI arguments retain independent input fields. Core raw normalization owns their relationship checks once, then creates the typed selection. Config validation retains the source requirement, root agreement and selector requirement; the constructor/deserializer owns the context bound. File, line and symbol selectors remain independent and intersect the changed scope. Ranking asks only whether changed selection is enabled.

Existing Git effects and low-level Git implementation stay unchanged. Test coverage exercises constructor and deserialization bounds, raw dependencies, plan/run roundtrip, old representation rejection, selector intersections, context neighbors, empty scope and non-Git roots. Plan schema advances 6 to 7 and report schema advances 5 to 6. New v6 goldens use nested selections; v5 goldens remain byte-identical historical rejected inputs. Readers accept only current schemas; versions are not migrated by production code.

## Five design review passes

1. Representation review: inspected Selection, RawRunConfig and TargetHandler. Independent fields allowed disabled context; selected Option and private fields rather than a second enable flag.
2. Persistence review (corrected again during implementation after schema-boundary review): inspected plan_config and report_handler golden loading. Merely removing sibling fields would silently ignore obsolete values; corrected design to deny unknown Selection fields and reject bool changed.
3. Validation review: traced validate_selection and TryFrom raw. Source requirement is a selection-wide constraint; retained it there, moved only the triplet relationship to raw normalization, and kept bound enforcement in the value constructor.
4. Semantics review: inspected resolve_changed_scoped and ranking. Kept omitted versus explicit base intact and left Git plumbing unchanged; ranking derives enabled from Option.
5. Scope/test review: inspected changed_git_scope, target_handler and Lean adapters. Existing integration tests already cover intersections, empty scope and non-Git failures. Added serialization/property tests rather than a duplicate formal model; changed fixture transport only.
