# Issue #631: allocate only returned page IDs

`verify --top 1 --offset K` currently clones K + 1 IDs and retains the prefix vector capacity. Selection must return the same page while owning strings and result capacity only for that page.

## Contract and architecture

For either strict or diverse policy, selection is `full_policy_order.drop(offset).take(count)`. Strict order is saved rank order. Diverse order completes each contiguous score tier and round robins files in their first-appearance order, retaining rank order within each file. Offset must never be applied before diversity ordering.

Keep the existing private selection API and route prefix selection through offset zero. Strict selection borrows the saved slice. A private `DiverseCandidates` iterator yields borrowed `RankedPlanCandidate` references, reusing the existing active file queue algorithm. It builds each tier only when needed; exhausted groups leave the active queue. Both policies skip borrowed candidates, take the clipped page length, then clone only returned IDs into a vector reserved for that page. No boxes, ID ownership in queues, or temporary owned prefix.

Check `offset >= candidates.len()` before subtracting. Compute page length as `count.get().min(candidates.len() - offset)` to handle `usize::MAX` without addition overflow. Empty and out-of-range internal selection returns an empty vector; public validation and diagnostics stay unchanged.

## Evidence and limits

Use the current selection tests as baseline. Add literal page tests for both policies at zero, middle, last, past-end and maximum offsets/counts. A separate allocator integration binary includes the real selection module with the public production candidate types; it measures only selection, using long synthetic IDs to distinguish discarded clones from borrowed queue memory. Check both peak allocation and returned capacity, and retain an eager-clone broken control. Public CLI correspondence uses an unedited six-candidate plan and all 59 cases generated by the existing bounded Lean audit.

Promote the audit into a namespaced Lean paging model, bounded proofs and sensitivity witnesses, generator, committed corpus, Rust CLI adapter and existing guarded CI generation checks. The generic theorem proves list slicing equivalence; finite cases check production correspondence. Neither establishes a general Rust proof or an allocation proof. Allocation tests measure allocator request bytes, not process RSS or whole-CLI memory. The fixed corpus has 56 small cases and three 64-bit boundaries; the Rust adapter explicitly handles platform width.

No public API changes, manifest changes, ranking changes, Python production changes, new dependencies, or changes to other issues. Use one guarded Lean command at a time, with 20-second wall time, 2048 MiB RSS, and 10000 heartbeats per theorem. Coordinate the global Lean slot with the parent agent.

## Design self-review

1. **Ordering review:** a slice of saved candidates before diverse grouping would restart round robin. Chosen action: offset consumes the complete borrowed policy iterator; retain tier and queue state across skipped candidates.
2. **Ownership and bounds review:** merely shrinking the result would hide discarded string clones and cost another allocation. Chosen action: clone after skip/take and reserve clipped remaining length; subtract only after the range guard.
3. **Evidence review:** capacity alone cannot detect temporary clones, and a symmetric tier fixture cannot detect ignored tiers. Chosen action: allocator peak assertion plus broken control, and retain the asymmetric two-file/two-tier Lean fixture and public diagnostic assertions. Formal claims explicitly exclude allocation and arbitrary implementation inputs.
