# Issue 898 typed process requests

## Purpose and boundary

Make process purpose determine required metadata. Baseline requires worker and run ID; mutant also requires mutant ID. Probe legitimately has no workspace identity. Preserve argv, limits, cancellation, worker environment, metrics and process-output policy. This request-boundary change is independent of worker lifecycle and outcome refactors.

## Representation

Use `RunProcess<C>` with required `context: C` and shared id/argv/cwd/limits. `ProbeContext` is a unit type. `BaselineContext` has worker/run_id; `MutantContext` has worker/run_id/mutant_id. `RunEffect::RunBaseline` carries only `RunProcess<BaselineContext>` and `RunMutant` only `RunProcess<MutantContext>`. No default generic parameter or optional required identity is provided. Closed serde objects reject obsolete independent metadata fields; missing or wrong context fields fail decoding. Empty IDs retain existing meaning; this change does not invent ID-content validation.

The CLI ProcessRequest owns the shared command with one private typed execution enum (Probe/Baseline/Mutant) after consuming its typed input. Three normal From implementations lower current typed inputs; none accepts the obsolete API or format. Optional worker/mutant projections remain only for existing tracing and ProcessFinished output where probe/baseline absence is legitimate. There is no independently editable optional metadata tuple.

The private shell workspace-context interface is implemented only for BaselineContext/MutantContext, with required worker and run ID. Worker environment construction receives this context; it always writes HOIMIN_RUN_ID and HOIMIN_WORKER_ROOT, removes case-insensitive inherited metadata, and writes HOIMIN_MUTANT_ID only for mutants. Probe cannot enter workspace dispatch. The shell no longer checks missing workers or repairs metadata. Cancellation and metrics use required worker directly.

## Persistence and compatibility

These request/effect shapes are internal; no public plan/report shape changes, schema version bump or fixture migration is needed. Reject old RunProcess serialized triplets without adapters. Preserve public ProcessFinished optional worker because probes use it. Historical design documents are not rewritten.

## Alternatives considered

A single context enum inside RunProcess while retaining RunEffect baseline/mutant would permit contradictory purposes. Replacing both effects with one enum-bearing effect would prevent that but unnecessarily rewrites scheduler completion matching and many tests. Typed generic payloads keep current effects while enforcing the distinction. Broad public context traits and generic ProcessHandler lifecycles add interface obligations; one private runner enum avoids them.

## Five design review passes

1. Callers: inspected effect.rs, machine baseline/mutant constructors, shell dispatch and runner. Only baseline and mutant share workspace preparation; probes and low-level backend fixtures need no worker. Selected typed payloads without changing effect names.
2. Invariants: checked outer effect/payload combinations. A context enum alone inside existing effects could mismatch; concrete generic payloads remove that state. Required strings preserve existing empty-string semantics rather than adding unrelated validation.
3. Legitimate absence: traced tracing, ProcessFinished and output-drain classification. Probe worker absence and baseline mutant absence are valid projections; requests must not use Option to encode required identity.
4. Environment and lifecycle: inspected metadata case cleanup, cancellation admission, queued-worker accounting and process spawning. Keep shared runner machinery and cancellation gates intact; remove only missing-worker branches and optional identity guesses.
5. Scope and complexity: searched consumers and historical docs. Keep reports, budgets, worker states and outcome classification unchanged; add one private lowering enum rather than public execution traits. Scoped design score 8.75/10: seven structural diagnostics pass, none fail; time-allocation diagnostic is unmeasured. Reaching a measured 10 needs recorded design-time allocation rather than another abstraction.
