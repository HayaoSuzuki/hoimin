## Design review 1 — allocation ownership

Scope: trace every full-call helper from producer through `make_candidate`, compare collection-literal gating.
Finding: append has two independently selectable families; one coarse append guard would either skip selected work or still construct an unselected replacement.
Remediation: specify one gate per match branch with exact operator mapping. Direct attribute-name replacements remain out of scope.

## Design review 2 — symmetric operations and traversal

Scope: inspect mapping and subscript visitor paths, child walking, annotation exclusions, and arity predicates.
Finding: mapping subscript→get also formats the full expression; putting its guard at entry of `collect_subscript` would suppress unrelated index/slice candidates.
Remediation: include the symmetric helper and place its gate after neighbor collection. Preserve visitor walking and existing annotation/argument checks.

## Design review 3 — proof of improvement and compatibility

Scope: assess counters, allocation metrics and public candidate contracts against issue acceptance.
Finding: emitted-candidate counters cannot detect discarded allocation, and a zero-only assertion can pass with disconnected instrumentation. Debug timing does not establish speedup or peak RSS.
Remediation: require helper-entry and actual copy/format-boundary counters with direct positive controls; baseline public descriptors/IDs and prefix/truncation; standalone cumulative allocation probe before/after with equal-length ignore control and repeated after run.

## Plan review 1 — coverage and sequencing

## Plan review 2 — fixture reachability and boundaries

Scope: check source shapes against helper arity/receiver/key predicates and limit behavior.
Finding: `obj.sort(1 + 2)` would never reach the no-argument sort helper. A plain numeric subscript exercises additional neighbor producers.
Remediation: use `(1 + 2).sort()` and reverse with selected child in receiver; use `obj[1 + 2]` for unrelated-operator case and a separate index-neighbor case; include zero/exact/overflow prefixes.

## Plan review 3 — reproducibility and resource isolation

Finding: the audit runner hardcodes repo `target`, while concurrent issue builds require an isolated target. Existing debug dependency globs may be ambiguous if reused across profiles.
Remediation: fresh issue-specific target, explicit rustc command using its single dependency artifacts, fixed debug/profile settings, and no edit to the historical Python driver. Whole-workspace test run uses two threads to avoid known shell timing pressure. Root exclusively handles knowledge catalog and publication.
