# Lean Annotation-Scope Correspondence Audit Report

Date: 2026-08-11

## Result

No same-premise mismatch was found in the audited annotation-site propagation
or comprehension name-resolution behavior. The prior binding-flow audit's two
`global`/`nonlocal` model-only gaps now have marker-addressed implementation
observations. All 20 private observations and all 9 public observations match
the expectations generated by Lean.

The durable claim is:

> At every audited annotation site, Hoimin resolves supported typing imports
> from the correct lexical target scope, does not leak comprehension targets
> into the enclosing scope, and does not retain a typing fact after a write to
> the scope selected by `global` or `nonlocal` unless that scope is re-imported.

Lean proves the explicit reduced model, not the production Rust analyzer. Rust
correspondence tests establish agreement at the fixed, same-premise observation
points. The production candidate algorithm and its public API were not changed;
Rust additions are test-only projections plus a test-only scope-kind field.

## Audited Surface and Exclusions

The audit covers direct supported typing imports; writes and re-imports routed
by `global` and `nonlocal`; class bodies that redirect writes to an external
scope; list, set, dictionary, and generator comprehension target isolation; and
the distinction between a comprehension's enclosing-scope first iterable and
its target-shadowed body. Observations include exact normalized import facts,
annotation symbol and scope, name-resolution result, candidate identity,
replacement, operator, symbol, and a marker-contained byte span.

It excludes aliased typing imports, comprehension filters and later generator
clauses, arbitrary runtime mutation of modules or `builtins`, Ruff parser
correctness, malformed-input recovery, asynchronous generator execution,
walrus restrictions beyond the parsed binding index, mutation ranking and
limits, mutant execution, and report rendering. It does not claim
correspondence for arbitrary Python programs or expand the earlier structured
search beyond depth 2.

## Lean Proofs

`AnnotationScopeProofs.lean` proves that:

- leaving a comprehension preserves its enclosing environment;
- a comprehension target is shadowed inside the comprehension;
- a global write updates the module and preserves the nearest function;
- a nonlocal write updates the nearest function and preserves the module;
- a normal write updates the current scope;
- re-import restores exact typing knowledge in the directed target; and
- an observed unrelated name is preserved across a comprehension.

The new Lean files contain no `sorry`, `admit`, custom `axiom`, or unlimited
heartbeat setting. Non-trivial declarations retain the bounded theorem policy.

## Sensitivity

All five new literal broken variants were distinguished. The comprehension
leak witness changes the same post-comprehension resolution rendered into the
corpus rather than only changing an unobserved Lean state:

| Broken family | Detected |
| --- | --- |
| comprehension target leaks into the enclosing scope | yes |
| target is bound before the first iterable | yes |
| `global` writes the current function instead of the module | yes |
| `nonlocal` skips the nearest enclosing function | yes |
| annotation projection observes suite-exit instead of site-entry state | yes |

The earlier binding-flow suite remains in the workspace test run and continues
to distinguish union-instead-of-meet, method lookup through class scope,
finally exit loss, loop-head replacement instead of meet, and source-only
candidate gating. The private Rust sensitivity test also compares distinct
site-entry/suite-later facts and first-iterable/body resolution so that moving a
marker projection to the wrong stage is observable.

## Outcome and Next Target

There is no confirmed production defect or unresolved specification ambiguity
in the retained correspondence set. The previous audit's annotation-site
observability gap is closed without adding production behavior.

A useful independent next target is exception-handler and match-case binding
visibility at exact expression sites, especially handler target deletion and
failed-case binding propagation. It should reuse marker-addressed projections,
the interpreter fallback, and the same resource ceiling rather than deepening
the structured search.
