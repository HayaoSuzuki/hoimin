# Issue 560 review log

## Design review 1 — root cause and alternatives

Read Assign, Named, ordered histories, and occurrence lookup. Both sides use byte offsets, so reordering stores alone cannot fix the issue. Selected an event index and retained source spans only for identity; rejected whole-statement invalidation because it loses the required RHS positive control.

## Design review 2 — scope boundaries

Checked class/function/type-parameter and comprehension handling. A timestamp migration must move definition stores after eager evaluation, and eliminate source-based outward walrus completion boundaries. Kept static function locals, conservative captured globals, loop backedges, and deferred annotation lookup unchanged.

## Design review 3 — failure paths and completeness

Checked partial nested unpacking and exceptions: an earlier store may survive a later target failure. Existing conditional history is conservative in try suites and must remain so. Added explicit nested/augassign/exception coverage and other builtin pairs to the acceptance matrix. This design does not claim path-sensitive execution or exception reachability analysis.

## Plan review 1 — acceptance mapping

Every issue acceptance condition maps to focused analyzer cases and public CLI checks. Found missing public run evidence in the first outline; added a run regression for the reported custom callable.

## Plan review 2 — implementation dependencies

Occurrence event introduction and binding-helper migration must land together; mixing offsets and event values would invalidate all ordered lookups. Tests come first, followed by the coherent migration and then broader regressions. No dependency or public manifest changes are needed.

## Plan review 3 — verification independence

Tests assert observable candidate counts/spans and executable subject behavior, not event counter values. Positive RHS and augassign controls prevent a blanket suppress-all fix. Require workspace tests, formatting, and Clippy, and record any infrastructure limitation by exact command.

## Implementation review 1 — every event producer

Audited all binding helper call sites after switching coordinates. Found that bulk deletion would now invalidate an earlier subscript lookup. Added `evaluation_order_retains_lookups_before_later_deletions`, observed 0 candidates versus expected 1, and changed deletion to recursive sequential evaluation. Moved pattern capture effects after the child pattern traversal to preserve their prior completion timing.

## Implementation review 2 — scope and eager/deferred boundaries

Rechecked definitions, dynamic calls, and all four comprehension forms. Definition names are stored after eager headers/class bodies; dynamic uncertainty is published after arguments; the first comprehension iterable remains before outward conditional writes. The existing 650-test library suite passed (12 ignored) after the initial migration. Renamed internal resolver time parameters to `event` to keep the source-span/event distinction visible.

Ruling: reuse Ruff's argument walker — reading its implementation confirmed it already evaluates all positional/starred arguments before keywords. The defect is its events being queried by text offsets. A redundant override would duplicate correct upstream behavior without strengthening the invariant.

## Implementation review 3 — target and failure semantics

Traced chained, nested tuple/list/starred, for/with targets and augmented assignment. Stores occur between recursive targets; augmented targets evaluate only once before the RHS. Try suites keep conditional binding effects, so partial stores cannot produce an unsafe builtin proof in a handler. Added both source and destination target-walrus controls for augmented assignment. No claim of precise reachability is made for statements that always raise before a store.
