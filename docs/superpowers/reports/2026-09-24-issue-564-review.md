# Issue 564 review log

## Design review 1 — root cause

Read nullable_add_allowed/is_supported_annotation and the #548 collection guard. Nullable addition checks spelling but never calls annotation_resolution; scalar names are also absent from tracked_resolution_name. Both the gate and tracked names must change. Reusing the annotation resolver preserves its deferred-evaluation contract.

## Design review 2 — scope semantics

Compared function headers, local annotations, enclosing functions, classes, and type parameters. Header annotations are indexed outside the function body, so own parameters/local stores must not suppress valid builtin headers. Module/class later bindings remain uncertain. Added these positive and negative controls rather than applying statement-order runtime lookup.

## Design review 3 — adjacent issue boundaries

Builtin provenance must also hold in nested arguments, but disallowed syntax is a separate predicate (#565). A provenance walk may traverse tuples without deciding whether Any/object are supported. Imported aliases with builtin spellings must use KnownImports before checking bare collection constructors. Nullable removal and collection-pair eligibility remain unchanged.

## Plan review 1 — acceptance coverage

Mapped all five scalar and three constructor names to positive/negative matrices. Added the custom metaclass case as executable evidence: merely reparsing a mutant would not expose its erroneous runtime union dispatch.

## Plan review 2 — implementation completeness

Extending the shared tracked-builtin list also updates wildcard imports and dynamic uncertainty, avoiding a partial fix that only tracks assignments. The new eligibility signature passes AstFacts from the existing replacement generator; no second scope index or external dependency is needed.

## Plan review 3 — independent tests and verification

Tests assert public candidate counts and source spans, not resolver labels. Normal builtins and aliased standard-library constructors prevent a suppress-all implementation. Public regressions run before edits; workspace tests and CI's all-features Clippy are required. Historical audit findings and separate #565 status are retained in OKF.
