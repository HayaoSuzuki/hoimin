# Issue #480: Python source encodings and raw-byte candidates

Support UTF-8 (default), ASCII and ISO-8859-1/Latin-1 through a pure Rust core decoder. Recognize a cookie in a standalone first-line comment, or a second-line comment when the first line contains only whitespace/comment. Preserve LF, CRLF and CR rather than normalizing source bytes. Match lowercase `coding` followed immediately by `:` or `=`, horizontal spaces, and an ASCII encoding identifier. Strings, trailing comments after statements and cookies after line two are not declarations. A comment such as `# explanation coding: latin-1` does match Python's cookie rule.

Use CPython's UTF-8/Latin-1 hyphen/underscore normalization and documented common codec aliases. With a UTF-8 BOM, require a declaration normalized by CPython's tokenizer to UTF-8; the generic codec alias `utf8` is not BOM-compatible. Retain the BOM in decoded text so existing original-byte offsets and BOM column rules are unchanged. Unsupported/unknown names share an explicit unsupported-or-unknown diagnostic, since hoimin has no Python codec registry. All decoding errors name the source path at the caller and retain the original declaration (or UTF-8 default).

`hoimin_core::decode_python_source` returns decoded Unicode text, source encoding, and checked mappings between UTF-8 and original offsets. UTF-8/ASCII text borrows the input. Latin-1 owns a UTF-8 string plus a sparse index of bytes >=128; each such byte contributes one extra UTF-8 byte. Queries use binary search and reject non-boundaries. Original file hashes, candidate spans and worker contents always refer to raw bytes; original/replacement metadata remains Unicode. Stable IDs retain schema 1: raw source hash, raw span and Unicode replacement already distinguish the mutation deterministically. Existing valid UTF-8 IDs remain unchanged.

`CandidateValidationContext` owns/reuses decoded facts and the existing Unicode-column index. Candidate conversion maps analyzer UTF-8 spans to raw spans before common validation. Validation checks source-encoded original text, raw hash, mapped boundaries, decoded columns and replacement representability. Worker mutation uses the same context and codec to encode replacement bytes before any write; raw prefix/suffix and reset bytes stay exact. No source-wide transcoding occurs in worker files, plans or fingerprints.

Discovery and direct run decode once per source validation context inside blocking analysis. Parse/candidate generation uses decoded text, while plan source records and fingerprints retain raw bytes. Error precedence for existing malformed candidate metadata remains intact. The implementation does not add Python runtime calls or dependencies. Codec support is deliberately finite; other codecs require their own mappings and encode guarantees.

#476 adds symbol validation before candidate analysis. This PR will depend on #536: merge that branch after the initial encoding implementation, replace its UTF-8-only read with the shared decoder and test Latin-1 symbol selection together. Final PR base is `enhancement/issue-476`.

Tests must cover cookie placement, aliases, BOM conflict, invalid UTF-8/ASCII, unsupported names, raw/decoded boundaries, hashes, IDs, encoded replacements containing accented characters, and public plan/run/verify executing Python against worker bytes. Use CPython only as an independent test oracle. Existing AST/candidate/source-index and workspace tests remain relevant; prior Lean UTF-8 models do not prove new codec semantics.

Sources read: [Python 3.14 encoding declarations](https://docs.python.org/3.14/reference/lexical_analysis.html#encoding-declarations), [PEP 263](https://peps.python.org/pep-0263/), [CPython 3.14 tokenizer helpers](https://github.com/python/cpython/blob/3.14/Parser/tokenizer/helpers.c). Inspected on 2026-09-14; CPython source branch is mutable and observations are not a pinned formal proof.

Normal run retains its existing baseline-before-analysis lifecycle: codec diagnostics from AnalyzeFile may therefore follow a successful baseline, and an earlier baseline failure retains precedence. Plan decodes without a baseline. Symbol-selected files are decoded earlier by #476 target validation. This change does not add a second all-file pre-baseline scan.
