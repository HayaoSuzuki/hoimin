# Issue 913: Unix process-group authority

The approved audit identified a representation problem, not an observed unsafe
signal: PortableSupervisor stores signal authority and a retained probe identifier
in separate Option fields. Replace them with private Unix-only
`ProcessGroup::{None, Signalable(i32), ProbeOnly(i32)}`. The numeric payload is a
PGID; a newtype would add no validation or capability beyond this enum.

`record_root_reaped` changes Signalable to ProbeOnly and is idempotent. The probe
operation first disarms, then calls the OS. An error or presence retains ProbeOnly;
absence clears the identifier. None does not prove absence. Termination may send
SIGKILL only from Signalable while the caller owns the live root. Drop follows
that same termination path. Neither reap, probe, termination nor Drop can rearm.
Attach initializes Signalable under the existing once-before-reap caller contract.

`terminated` records a successful termination attempt; `tree_quiescent` records
independent absence evidence. Keep both fields and their short circuits unchanged.
Preserve error ordering, error text, ESRCH/EPERM handling, public/shared APIs,
Windows Job Objects and Linux cgroups.

Tests replace only Unix kill at its OS boundary using a thread-local RAII fake.
It remains installed through supervisor Drop, records group and signal, and
supplies errno results. Tests exercise real supervisor operations without signaling
arbitrary real PGIDs. Existing real descendant integration coverage remains.

## Design self-review (five passes)

1. State audit: the two Some fields are mutually exclusive on valid lifecycle
   paths; the enum removes the unrepresentable combination without merging facts.
2. Caller audit: attach happens once; reap notification precedes cleanup yield;
   terminate(false) and refresh must also disarm before a fallible probe.
3. Failure audit: probe error retains ID and removes signal authority before
   returning; terminate injection remains after probe, before SIGKILL.
4. Platform audit: all new state and fake boundaries are Unix-only; Windows
   layout and control flow and Linux cgroup implementation require no changes.
5. Complexity audit: one local enum owns lifecycle knowledge; the OS wrapper
   centralizes the existing kill boundary. No public abstraction is added.
   Score: 8.75/10: seven observable software-design-philosophy diagnostics pass
   for this scoped change. The eighth (10–20% design-time investment) was not
   measured, so it earns no point and requires no speculative implementation.
   The original pair failed invariant ownership and newcomer-visible boundaries;
   the enum addresses both. This does not grade the entire module.
