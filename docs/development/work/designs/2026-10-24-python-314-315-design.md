# Python 3.14・3.15の実行環境対応

Python 3.14を共通コードの最低バージョンとして維持し、Python 3.15でもhoiminをインストールして既存構文を扱えるようにする。
ユーザーが選択した段階的対応であり、3.12・3.13への拡大は行わない。

## 対応範囲

配布のRequires-Pythonは`>=3.14,<3.16`とし、3.15 classifierを追加する。
開発ツールの構文・型検査は3.14を基準とする。
3.15の新構文への対応や新しいmutation演算子は追加しない。
解析は既存の構文・演算子の範囲に限定し、遅延importや内包表記のアンパックへの対応は約束しない。

## 検討した方式

- 採用: 実行環境への対応を先行し、既存の解析を両版で検証する。新構文の対応を独立して検討できる。
- 見送り: パーサー更新と3.15の新構文への対応を同時に行う。独自のスタック保護・AST処理の再検証で変更範囲が広がる。

## 検証と配布

Linuxおよび手動Windows/macOS CIのRust統合テストは3.14・3.15のmatrixで実施する。
通常CIと手動非Linux CI、および各OSのリリースwheel検証では、同じwheelを両版でインストール・実行する。
wheel smokeのuvx呼び出しには、そのsmokeを実行中のPythonを指定して意図しない3.14への固定を防ぐ。
3.14固有の意味論を3.15でも維持するテストは両版を許可するが、バージョン検査を削除しない。

## リソース管理

ローカルのCargoはビルド並列数2、増分コンパイル無効、dev/testのdebug情報なしで実行する。
成果物はこのworktree内に置き、元のチェックアウトのtargetや一時ファイルは削除しない。
不要になった成果物は検証結果を記録した後にcargo clean等で削除する。
