# Python 品質基盤の設計

## 目的

Python 製アナライザとそのテストを厳格に静的解析し、テスト実行の網羅性を含む行カバレッジを 100% に保つ。
加えて、プロパティベーステストと hoimin 自身によるミューテーションテストで、例示ベースのテストでは見落としやすい入力を検証する。

## 対象と非対象

対象は `python/hoimin_analyzer.py`、`python/tests/`、および Python テストを起動するルートの `tests/` である。
Rust の lint・テスト設定、公開パッケージの実行時依存、既存 CLI の仕様変更は対象外とする。

## 構成

設定はルートの `pyproject.toml` に集約する。

- 開発依存に `ruff`、`pytest-cov`、`pytest-randomly`、`hypothesis` を追加する。
- Ruff は `lint.select = ["ALL"]` とし、CLI の標準出力、pytest の `assert`、テスト用の短い関数・マジック値など、意図が明確な箇所だけをルール ID 単位で除外する。
- `python/tests` を pytest の標準収集対象にする。必要ならルート `tests` の Python テストも明示して収集対象に含める。
- pytest の標準オプションでランダム順序実行、カバレッジ計測、欠損行の報告、100% 未満での失敗を有効にする。

## カバレッジ契約

coverage の source は `python` と `tests` を含める。したがって、アナライザ本体だけでなくテストコードも計測対象となる。
未実行のテスト関数を含むテストファイルは未実行行を残すため、全体カバレッジ 100% の判定で失敗する。
実行時のみ到達不能と判断できる行は、理由をコメントとして残したうえで coverage の標準除外規則に限定して除外する。

## テスト強化

既存の例示テストは保持し、Hypothesis のテストを追加する。
プロパティは、アナライザが扱う Python 構文・演算子・位置情報について次を確認する。

- 有効な入力では JSON 契約を満たす結果を返す。
- 候補の位置と置換内容は元のソースと整合する。
- 不正または範囲外の入力では、クラッシュや不正な成功結果を返さない。
- 同じ入力から得る構造化結果は決定的である。

Hypothesis の失敗例は最小化された再現ケースとして通常の pytest 実行で回帰する。

## ミューテーションテスト

hoimin を `python/hoimin_analyzer.py` に対して実行し、pytest コマンドを子プロセスとして渡す。
ベースライン失敗、タイムアウト、環境依存の結果は先に解消または明示的に記録する。
生存変異は一件ずつ確認し、仕様上等価な変異を除いて、欠けている振る舞いを表す決定的な pytest または Hypothesis の性質テストを追加する。
このコマンドと確認基準を開発者向け文書に残す。

## 検証

品質ゲートは次の順序で実行する。

1. `uv run ruff check python tests`
2. `uv run ruff format --check python tests`
3. `uv run pytest`（ランダム順序と、テストコードを含む 100% カバレッジを含む）
4. `uv run hoimin run` によるアナライザ対象のミューテーションテスト

各コマンドはローカルと CI で同じ設定を利用する。
