## 独立レビューと裁定

builder checkでは設計8.75/10、計画6.25/10。計画のinterface・コメント・境界説明が不足していたため、正確なAPIと検証コマンドを追記した。実装の独立レビューでは7.5/10で、保存先、bounded freshness、full manifest、artifact容量の4つのP1を指摘された。I4–I5で修正・検証した。独立reviewer自身はテストを実行していない。修正後の確認は作者によるセルフレビューと実行試験であり、再度の独立レビューではない。

Ruling: 保存先の**既存最終要素**とproject内保存を拒否し、親はcanonicalizeして能力を保持する。OS標準の `/tmp` や `/var` のsymlinkを含む親は許容する。入力の実バイトと保存先capabilityを守る契約に統一した。誤りの場合の影響は保存先指定の受理範囲であり、書込みが別directoryへ移ることはcapabilityの試験で防ぐ。

Ruling: 新規成果物は探索中にbackground disk monitorで監視し、実行停止・root cleanup後は保持したartifact directoryだけを各公開の直前・直後に測定する。root monitor停止後にambient pathで無制限に書く方式を廃止した。事前に追加bytesとfree-space reserveを検査する。誤りの場合は公開時の容量違反になるため、失敗時はpartial diffを削除して非成功を返す。

Ruling: 論理的なsource/plan/command/environment/variant identityは単一session内の不変handleとして構成し、JSONには実際のplan/source/variant/environment hash、全copy manifestのsnapshot hashとnormalized configを保存する。Leanはこれらの実バイト対応を証明しない。誤りの場合は異なる証跡の流用になるため、CLIから任意handleを受け取らず、同じowned session内だけで構築する。

Deferred minors: なし。

完全な実行コマンド、ログdigest、guardの資源記録は隣の `2026-11-19-issue-1172-reduce-validation.json` に保存する。Lean consumerはinternal-fixtureであり、実際の子プロセス、ASTとバイト位置、OS時計、cleanupがLeanで証明されたという主張ではない。public runnerの各対応は上記の実装試験による。

初回Rust全体検証はsandbox下で失敗した。`plan::validation_tests::issue_1081_membership_matches_content_manifest_selection` の3ケースと `workspace::owned::coverage_tests::cleanup_propagates_a_real_cursor_limit_without_deleting_the_leaf_payload` はfixture作成のPermissionDenied。`target::git::runner::tests` の `normal_completion_keeps_stdout_stderr_and_status`、`request_cancelled_between_commands_blocks_next_spawn`、`cancellation_closes_pipes_after_root_has_already_been_reaped`、`cancellation_racing_normal_exit_keeps_reap_and_output_contract`、`cancelling_started_child_reaps_before_returning`、`dropping_waiter_cancels_and_preserves_lifecycle_owner`、`stdout_overflow_terminates_and_reaps_with_both_pipes_busy` はworktreeの `.venv` 不在により失敗した。既存venvをリンクし、許可された制限外実行で全体を再検証して解消した。

初回Python全体の6 failures / 35 setup errorsには、新targetで古くなったroster、sandboxに拒否されたLean RSS監視、重複rustflagsによるsdist生成失敗が含まれた。roster更新と検証環境修正後に全体成功を確認した。初回Lean freshnessのmonitor_error（exit126）も、同じ資源上限のまま監視可能な環境で再実行し解消した。検証都合で資源上限を増やしてはいない。

この環境で実行したOSはmacOS。Linux/Windowsのhosted CI自体は実行していない。shared resource backendの選択は既存policyを使う。merge/pushは行わず作業branchに保存する。
