# Quint 導入計画

1. 有限台帳モデルと過剰予約の負の対照を作り、typecheck、TLC の正常終了と実際の不変条件違反を確認する。
2. seed 固定の ITF 履歴を生成する。Rust で公開 API に再生し、期待状態を直接比較する。
3. リテラルの操作列を rstest で独立ケースにし、同じ操作言語を proptest と libFuzzer へ拡張する。境界量、未知 ID、二重解放、種類間の独立性を含める。
4. 開発 CI の必須集約へモデル検査を追加し、パス選択と失敗伝播をテストする。npm/Java は検証環境だけに導入する。
5. 設計・計画・実装・テストをそれぞれ5観点で自己レビューし、実コマンドの結果と有限性の制約を記録する。

設計レビューでは software-design-philosophy の深いモジュール、情報隠蔽、知識の重複、単純な入口、コメントの契約を確認する。検証のために汎用フレームワークや製品の設定項目を増やさない。
