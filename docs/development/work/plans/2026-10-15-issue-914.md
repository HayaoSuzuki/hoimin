# Issue 914: annotation class context

Baseline: `54093222abe08c79e8e36e4656ee04b9c6d8dda0`.

## Design

Replace AnnotationCollector's three correlated optional class fields with one
private `Option<ClassContext>`. The context owns `fallback: KnownImports`,
`external_bindings: ClassExternalBindings`, and `parent_scope: ScopeKind`.
Presence means all class-specific data exists together. Keep `scope_kind`
separate because it describes module and function scopes too.

Entering a function or class takes the enclosing context once and restores it
once. Function entry updates external declarations before taking the context;
class entry derives its fallback before installing a complete new context.
No generic visitor framework, scope enum, new public API, or accessor layer is
needed. ClassContext deliberately has no Clone implementation. Loop convergence
snapshots clone only the fallback imports and compare borrowed fallbacks.

Keep all existing global/nonlocal projection, type-parameter entry, class-name
invalidation, import rebinding, callbacks, and annotation visit counts. Candidate
records, ranking, persisted schemas, and default operators do not change.

### Design self-review (five completed passes before production edits)

1. Ownership: enumerated all three fields' references; class/function entry and
   restoration are the only ownership transitions. One Option excludes partial
   class state without changing module/function scope representation.
2. Semantics: traced `copy_for_fallback`; module parents copy globals, function
   and class parents copy nonlocals. Preserve this ordering before function entry.
3. Nested scope: traced class exit projection and type parameters; retain the
   enclosing context independently from inherited imports and scope kind.
4. Cost: inspected loop transfer and finally observation tests. Avoid deriving
   Clone for the context, and snapshot only KnownImports in loop convergence.
5. Boundary: no serialization, candidate generation, ranking, or operator changes
   required. Existing Lean annotation-scope corpus is the appropriate semantic
   comparison; a new representation-only Lean model would duplicate coverage.

## Implementation review

Five completed passes after the representation edit, before green execution:

1. Transition audit: compared every old-field reference with the diff. Empty
   construction has None; function entry takes once, class entry takes once and
   installs all fields, each exit restores the owned context once.
2. External-write audit: function header/statement transfer still precedes
   `copy_for_fallback`; module globals and function nonlocals still project from
   class fallthrough into inherited imports. Abrupt class paths are unchanged.

   inherited fallback; class names are invalidated and type parameters entered at
   the same point. `scope_kind` and qualified-name restoration remain unchanged.

   `context.fallback`, compares `Option<&KnownImports>`, and drops the snapshot
   before head updates. Saved outer contexts move instead of cloning bindings.
5. Test/boundary audit: finally's observer maps only fallback imports, preserving
   its oracle. Existing loop tests are untouched. Candidate/ranking/schema/default
   definitions are outside the diff; tests assert observable candidate behavior.
