# Issue 935: exclusive known bindings

Baseline: `5237d1e53a2c8b34fca80f6eeb7d644a01d732e2`.

## Scope and design

Replace `KnownImports`' exclusive direct/module/type-variable collections with
one private `HashMap<String, KnownBinding>` and `KnownBinding::{Direct(String),
Module(String), TypeVar}`. Category and payload equality define intersection;
replacement and removal affect one entry. Keep the flow exit categories and
name-resolution index separate. No public API, schema, candidate ordering,
operator, compatibility adapter, cache, or Lean model change is needed.

Preserve recognized-provider wildcard imports retaining modules, scalar-named
TypeVars, import-only stability checks, direct spelling priority followed by
lexical minimum, class global/nonlocal projection, PEP 695 shadows, normalized
oracle facts, and clone-entry instrumentation. A map scan may now inspect
TypeVars as well; this is not a performance improvement claim.

### Scope self-review: five completed passes before production edits

1. Representation: audited all old-field references; generated states use one
   category per name, so replacing the collections loses no valid state.
2. Transitions: traced imports, TypeVar assignment, type parameters, invalidation,
   copy and intersection. Unknown imports still invalidate known bindings.
3. Consumers: traced name resolution, spelling search, scalar annotation checks,
   and stability. TypeVars must not count as imported names.
4. Coverage: existing tests cover PEP 695, qualified provider spelling, external
   class writes, loop/exception joins and size-dependent clone work. New tests
   target category/payload transitions and intersection algebra, not duplicate
   end-to-end fixtures.
5. Boundaries: preserve sorted `direct:`, `module:` and `type-var:` oracle facts;
   no formal-model rewrite or speed claim is justified by this representation.
