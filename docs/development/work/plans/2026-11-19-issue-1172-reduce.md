# reduce Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Track completion below.

**Goal:** Issue #1172 の確定仕様に従うローカル削減探索を実装する。
**Architecture:** 定義編集、採用判定、既存基盤を使う session に知識を集約する。
**Tech Stack:** Rust / Ruff AST / Tokio / rstest / proptest / libFuzzer / Lean corpus.
**Spec:** ../designs/2026-11-19-issue-1172-reduce-design.md

## Global Constraints

元ファイルに変更を適用しない。固定 mutant IDs / timeout を維持する。保持区間と交差する除去は禁止。正確な率は0%超100%未満。観測済みゼロは停止。締切と同時の完成は停止優先。未認証案から diff を出さない。1テスト関数1ケース、AAA、parameterization、property based testing、fuzzing を実施する。

## Review Focus

1. decorator、async、入れ子・同名定義・空 suite の物理編集。
2. survivor の新規 kill、欠落・重複した結果、観測済みゼロと未観測枠。
3. 元から自動決定した timeout の固定、独立削除の不正な合成。
4. 締切同時完成、半組での失敗、停止後の成果物保持。
5. 非UTF8・CRLF、元バイトと diff の一致、資源障害と通常失敗の区別。

## 確定したAPIと実行コマンド

Task1は `hoimin_core::reduce::{pair_pass(num:u128,den:u128,original:u128,reduced:u128)->bool, median([u128;3])->u128, Context, Proposal, State::step(&Context,Event)}` を実装する。corpusの全componentフィールドと各中間状態を比較する。REDは `cargo test -p hoimin-core --test reduce_policy`、GREENは同コマンドと `--test lean_reduce_spec_oracle`。

Task2は `hoimin_python::reduce::DefinitionSource::parse(&[u8])->Result<Self,String>` と `remove(&self, removed:&[usize], kept:&[usize])->Result<Vec<u8>,String>` を実装する。選択名の一意性と原snapshot上の保持範囲を所有する。`cargo test -p hoimin-python --test reduce` で検証する。

Task3は `reduce::run(ReduceArgs)->Result<i32,String>` をCLIから呼ぶ。全体deadlineをsession作成時に一度確定し、停止後はdispatchしない。入力不正、元失敗、案なし、最終確認前の停止、認証済み案のdiffを独立したintegration caseで検証する。`cargo test -p hoimin-cli reduce` を実行する。
