# 評価設計

対象は #1177、#1179、#1182、#1186。製品機能の実装判断に先立ち、既存CLIと外部テストだけで改善を得られるかを評価する。
実験開始前に対象と比較条件を固定する。対象は現在の hoimin の実用 Python モジュールの複製であり、別プロジェクトへの一般化はしない。

## 比較

- #1177: `ci_metrics.total`。既存の欠測テスト、順序反転・連結の関係、独立した合計オラクルを比較する。入力は小さい非負整数と欠測に限定し、浮動小数の結合則を一般に仮定しない。同じ mutant が関係の両辺に作用する。定数関数・個数関数も満たす関係は正しさの証明にならない。
- #1179: `ci_selection.main` の cgroup 判定4条件。allpairspy 2.5.1 の2-way／3-way、同件数の無作為抽出3seed、全16通り、現在のCLIテストを比較する。期待値は「push、main、明示的許可、Rust対象の全条件が必要」という契約。網羅率は独立に列挙して検算する。
- #1182: `changed_paths`。現行の実Gitテスト、意図的に固定出力を返す fake、実Gitと同じ契約を検査するテストを比較する。固定出力 fake は実製品のバグではなく既知の不適合対照。Git のオプションを変えた要求に対する出力を実Gitと照合し、普通の契約テストだけで検出できる分を分離する。
- #1186: total の入力（狭い／広い）×assertion（非負／独立した合計）の2×2比較を同じ候補で行う。この弱いテストは原因切り分け用の人工対照であり、現行テストの代用としない。追加価値は現行テストとの比較で判断する。

全実験に同一の候補集合を使い、元コードの成功、完走、終了理由、候補同一性を検査する。
実行は単一worker、1 arm 90秒、mutant 8秒、baseline 15秒、512MiB、出力256KiB、workspace64MiB、空き10GiB以上。
実行全体は15分上限。生成時間とテスト時間を保存するが、この小標本から速度向上の統計的結論を出さない。
失敗候補を隔離したコピーで再実行し、診断を保存する。ネットワークと外部サービスは使わず、Gitのコミットは一時リポジトリ内だけ。

## 設計セルフレビュー（実行前5回）

1. 効果の定義: kill数をバグ数と呼ばない。既存テストで既に検出済みかを必ず併記する。
2. オラクル: 非負整数の合計は整数の逐次加算から導く。MRの成立条件と不成立例を分ける。
3. 代表性: 同一リポジトリの小関数という制限を明記。外部プロジェクトでの採用率は未測定。
4. 契約: fakeが変異した引数を無視することと、本物の契約違反を分離。許される出力順序差は集合比較で許容する。
5. 複雑性: 公開APIや生成基盤を足さず、固定実験driver、入力データ、テスト、監査に責務を限定する。

## 実施計画とセルフレビュー（実行前5回）

計画はソースの複製・ハッシュ保存、入力生成、未変異テスト、plan/verify比較、失敗の再確認、有限モデル検証、結論記録の順。

1. 対象逸脱: `--line` のみで選択し、候補pathを検査する。`--source .` は使わない。
2. 公平性: 同一群で候補辞書全体を比較し、arm変更による対象差を拒否する。
3. 再現性: 入力・seed・外部generatorの版・ソース・バイナリのハッシュを保存する。
4. テスト: parameterizeで1 invocation 1ケース、AAAを明記。Hypothesisで入力を生成して固定コーパスとして再利用する。
5. 停止条件: baseline失敗、タイムアウト、不完全実行、候補差を効果として数えない。結果に合わせて入力を選び直さない。

## software-design-philosophy による評価

初案は実験用の共通生成フレームワークを想定すると、インターフェースの単純さ、重要な判断の隠蔽、境界の理解容易性が不合格（5/8、6.25/10）。
固定対象を扱う一つのdriverと、一つのテストモジュールに縮小し、候補・予算はdriverが所有、仕様はテストが所有する。
最終評価は実装後に8項目を再確認する。これは評価用コードの設計点であり、研究の有効性の点数ではない。
