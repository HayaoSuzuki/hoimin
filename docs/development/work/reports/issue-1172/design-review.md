# reduce 仕様の複雑性評価

`software-design-philosophy` の八つの Quick Diagnostic で、今回の仕様・モデル・将来の実装境界を評価した。製品 `reduce` の実装品質を採点したものではない。

**変更前は 5/8、6.25/10。変更後は 7/8、8.75/10。** 初稿では、率の前提とゼロ時間の意味を呼出側が知る必要があり、証跡・停止の境界の説明も不足していた。変更後も「実装を変えて呼出側を維持できること」の実証は未完了である。

| 診断 | 変更前 | 変更後 | 根拠・必要な作業 |
| --- | --- | --- | --- |
| モジュールの目的を一文で説明できる | 合格 | 合格 | モデルは採用と停止の規則、proofs はその不変条件、cases は反例、main は列挙・JSON を所有する |
| interface が内部処理より簡単 | 合格 | 合格 | 利用者は対象・保持・予算・率を指定する。時刻の同時境界や nested edit の例外を設定しない |
| 内部変更が呼出側へ波及しない | 未実証 | 未実証 | 製品実装と adapter がない。10/10 へ進むには、以下の境界に実装を接続し、同じ期待値で変更耐性を確認する必要がある |
| interface コメントが抽象化を説明する | 不足 | 合格 | `validRate`、`measurementsValid`、`scopeValid`、`Certified`、`step` が条件・入力の意味・停止時の扱いを説明する |
| review に設計の議論を含む | 合格 | 合格 | 本書と独立レビューで、正しさだけでなく知識の重複と設定増加も確認する |
| 各境界が重要な判断を隠す | 合格 | 合格 | 編集は範囲と source snapshot、ポリシーは率と証跡、session は予算と最良案を所有する |
| 実装を読まず境界を理解できる | 不足 | 合格 | 以下の所有権と consumer contract に入力前提、保証、除外範囲を明記した |
| 変更とともに設計改善へ投資する | 合格 | 合格 | 補足を追加するだけでなく、率と測定値の検査を集約し、重複した数値前提を除去した。時間配分の百分率を実測したという主張ではない |

## 情報の所有権

製品実装では、次の三つの責務を基準にする。名前は概念名であり、新たに三つの class や crate を作る要求ではない。既存の実行基盤を再利用し、薄い転送用 module を増やさない。

| 責務 | 所有する判断 | 呼出側へ漏らさない情報 |
| --- | --- | --- |
| ソース variant の構成 | 定義の選択・一意性、decorator を含む区間、保持範囲との交差、snapshot、編集と diff | Python の構文位置、encoding、編集の正規化、空ブロックの補完 |
| 証跡の採用ポリシー | 固定 mutant IDs と timeout、正確な率、観測済み時間、通常テスト成功、認証の成立 | 個々の条件の順序、丸めの回避、未観測値の表現 |
| 探索 session | 一つの絶対締切、候補のまとめた探索、実行資源、認証済み best、停止と成果物 | 試行順、予算予約、仮の候補と完成した候補の内部状態 |

この分割は read → validate → apply のような時間順の分割ではない。同じ source の知識は variant 構成に、同じ採用規則はポリシーに集約する。JSON への変換は audit main が所有し、expected の計算を adapter に複製しない。

## 今回の改善

- `validRate` が許容率を一か所で定義し、設定検証と短縮判定の両方から使う。
- `measurementsValid` が観測済みの時間と未観測の final pair 枠を区別する。前者のゼロは停止、後者は未完了であり、同じ数値表現から勝手に同じ意味を推測しない。
- `Certified` に重複していた三つの正の時間条件を測定ポリシーに集約した。corpus はその判定を呼び出し、第二の仕様を実装しない。
- 保持 ID と編集範囲を一緒に検査する。利用者に「外側も保持指定する」ことを要求しない。
- 締切との同時完了、ゼロ時間の再試行、保持範囲を無視する例外モードを設定項目にしない。

## 過剰な一般化を避ける範囲

任意コマンドは既存 hoimin の能力を使う一方、削減単位は Python の定義に限定する。汎用の test runner plugin framework、複数言語の編集 API、統計的有意性の設定、探索アルゴリズムの外部 plugin は追加しない。

一つの decision model に小さな数値・集合・区間の helper があること自体は classitis ではない。それらに別個の public service を設けず、認証と session の契約の内部として扱う。corpus の component fields は形式監査用であり、そのまま製品 CLI の利用者に組み立てさせる API ではない。

## 残る改善条件

8.75/10 から 10/10 に進む条件は、実装後に source snapshot・認証済み成果物を所有する境界を実体化し、内部表現の変更で CLI と adapter の前提が漏れないことを確認することである。本 PR で未実装の依存関係を合格扱いにはしない。
