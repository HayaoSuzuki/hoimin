# #1172 の確定した境界条件

ユーザーは監査で挙げた C1–C3 の補足、設計評価、PR 作成を依頼した。以下を今回の仕様補足とする。初回監査の [仕様 snapshot](specification.md) は履歴として変更せず、Issue の現在仕様と本書に補足を反映する。

## 保持指定は編集範囲にも適用する

保持した定義の ID を retained に含めるだけでは不十分である。作業コピーで除去する半開バイト区間は、保持定義の区間と交差してはならない。保持した定義を内包する外側の関数を削除する案も棄却する。境界が接するだけの区間は交差しない。

範囲は decorator を含め、同じ元ソースの snapshot 上で求める。実際の diff は検証した variant と同じバイト列を再現する。AST、文字コード、重複する編集の正規化は編集処理が隠蔽し、利用者に範囲計算や例外モードを要求しない。

## 短縮率と測定値

最低短縮率は既定 5%。利用者が指定できる領域は厳密に `0% < p < 100%` とする。モデルの有理数表現では `0 < numerator < denominator`。領域外は探索開始前の設定エラーとして扱い、短縮案なしの正常終了にはしない。正確な CLI 入力文法は後続実装の事項である。

判定は正確な比率で行う。割引量を先に丸めず、`denominator * reduced ≤ (denominator - numerator) * original` と同等の判定を用いる。固定幅整数を使う実装は overflow を防ぐ。

通常テストの時間観測は正でなければならない。元スイート、探索候補、最終確認のいずれでも、実際に観測したゼロ時間、時計の逆行、時間を取得できない事象は測定不成立として探索を停止する。成功した測定や単なる「短縮なし」に読み替えず、自動再試行や予算延長は追加しない。既に最終確認済みの案は保持できる。未観測の測定枠はゼロ時間の観測とは区別し、その枠を含む案は認証しない。

探索中の中央値と、最終三組すべての短縮率判定は、同じ時間計測ポリシーに属する。CLI、探索処理、成果物処理に率の解釈を重複させない。

## 締切との同時完了

全体予算は一つの単調時計による絶対締切で管理する。認証に必要なすべての証跡の完成時刻が、厳密に締切より前である場合だけ、その案を新たに認証できる。`completedAt = deadline` は締切到達を優先し、新しい案を認証しない。

停止状態から新しい候補の評価・認証を再開しない。締切前に認証済みの案は失わない。停止理由と残存成果物は同じ結果として報告する。

この規則は認証と探索の締切である。OS による子プロセス終了、cleanup、結果の物理書込みが締切と同時に必ず完了するという保証ではない。これらは既存の資源制御・後始末契約に従い、新しい探索には使わない。
