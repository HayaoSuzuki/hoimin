# Python regular expression mutation design

This report specifies discovery and verification for implementers of issue #1191. The reference revision is `4cf630f9`. The behavior below is proposed for the Rust analyzer. The CPython observations in the review table were measured independently of hoimin. [Issue #1191](https://github.com/HayaoSuzuki/hoimin/issues/1191)

## Operator identities and edits

Expose three independently selectable operators. The proposed IDs are `regex_match_boundary`, `regex_character_set`, and `regex_ascii_mode`. Register adopted IDs in the default operator inventory and use ordinary operator selection for exclusion. Use the existing candidate identity, including operator, source range, and exact replacement. The preview and operator guide must distinguish changing the match span, changing one atom, and changing the pattern-wide default. Use directions such as “word boundary uses ASCII word characters” for assertions whose result depends on both neighbors.

| Operator | Source | Destination and applicability |
| --- | --- | --- |
| Match boundary | `fullmatch`, `match`, `search` | Move one step either way along whole input, prefix, and substring. Treat Python 3.15 `prefixmatch` as a prefix input. Use `match` as the cross-version prefix destination. Preserve all arguments, flags, subject, and compiled region bounds. |
| Match boundary | `^`, `\A` | Neutralize an anchor with an empty noncapturing group. Swap line start and absolute start only when effective `MULTILINE` distinguishes them. |
| Match boundary | `$`, `\Z`, `\z` | Neutralize a terminal assertion or exchange `$` with strict end. Emit `\Z` as the canonical strict-end destination. A final newline distinguishes `$` from strict end even with `MULTILINE` off. |
| Character set | `\d`, `\w`, `\s` | In Unicode text mode, substitute `[0-9]`, `[A-Za-z0-9_]`, and `[\x09-\x0d\x20]` respectively. Under Unicode `IGNORECASE`, use `(?a:[A-Za-z0-9_])` to keep the word class ASCII-only. |
| Character set | `\D`, `\W`, `\S` | Use the corresponding negated class. Narrowing the excluded set expands the characters accepted by the complement. Apply the same word-class case-fold protection. |
| Character set | Explicit ASCII digit, word, or whitespace class and its negation | Compare the class's literal/range union with the three ASCII sets. Allow order, escapes, and equivalent ranges. Replace with the corresponding Unicode shorthand, adding `(?u:...)` when ambient mode is ASCII. Account for current case folding when identifying a meaningful change. |
| Character set | Shorthand already in ASCII mode | Use a Unicode-scoped shorthand, including complements. This changes one atom even if the enclosing expression uses `re.ASCII`. |
| Character set | `\b`, `\B` outside a bracket class | Scope the assertion with `(?a:...)` or `(?u:...)` according to its effective mode. This changes the classification of adjacent characters on either side. Within a class, `\b` is backspace. |
| Character set | A mixed class containing a sensitive shorthand, or a case-insensitive ASCII letter range | Switch the effective mode of the whole bracket atom with a scoped group. For `[a-z]` or `[A-Z]` under Unicode `IGNORECASE`, ASCII mode excludes İ, ı, ſ, and K. Keep explicit exclusions and all other class members. |
| ASCII mode | Pattern-wide default for a text pattern | Toggle its root ASCII/Unicode mode when at least one sensitive atom inherits the root. Preserve other flags and all scoped overrides. Describe the affected scope in the operator guide. |

Use a single canonical edit for each source atom and semantic destination. Prefer an exact category substitution to a generic whole-class switch. For the pattern-wide operator, use the known flag argument when an existing expression determines the default, editing only ASCII/Unicode bits while preserving other known bits. When inline flags determine the default, edit the mode in the original global flag group. When neither source specifies a mode, insert `(?a)` at the beginning of the pattern. External and global inline flags can jointly constrain the default. Compose changes to both spellings into one covering source replacement, copying intervening call text unchanged and preserving the actual argument order. The result must have a consistent root mode and retain all other flags and scoped overrides. Distinguish pattern-wide and atom edits by their semantic reach and observable root flags. Keep their eligibility independent of which sibling operator is selected; suppress a cross-operator duplicate only when that full observable equivalence is proven.

For a simple, mandatory top-level anchor, use match context to suppress proven equivalents. At subject offset zero, `^` and `\A` can be redundant under a module-level prefix or whole-input call. A compiled pattern may run with nonzero `pos`. Its leading anchor can distinguish a prefix at that position from the beginning of the subject. A mandatory terminal assertion can be redundant under whole-input matching. Alternation, internal anchors, scoped flags, and unknown call sites invalidate simple edge reasoning. Preserve the distinction between line start and strict start and between line end and strict end when the consumer can observe them. Reserve general regex equivalence for future work.

## Trusted targets and pattern sources

Build `CallableImports` with the `re` module when any regex operator is selected. `CallableImports::resolve` supplies the original member and the range of a qualified member. Support `import re as rx`, `from re import match as m`, and imported flag aliases. For a bare function alias, follow the existing `operator_functions.rs` convention for obtaining a different trusted member through the guarded built-in `__import__`. Reject shadowed or rebound names, ambiguous class namespaces, star imports, tracked module escapes, attribute writes, and dynamic namespace access under the same trust model as other standard-library operators. Document the assumption that imports resolve to the standard library.

Accept direct match calls, direct `re.compile(...)` pattern sites, and proven compiled receivers. Recognize `re.compile(...).search(...)` and uniquely assigned, preceding, unconditional module or function-local names whose initializer is a trusted compile call. Use the shared reaching-initializer proof, including lexical shadowing, rebinding, and explicit module-namespace hazards. Collect pattern edits once at the compile site and method edits at each use. Support method mutation on a known `re` callable with a dynamic pattern when its signature is shared by both methods. Pattern internals require a known value and known flags.

For a unique literal assignment such as `CODE = r"\d+"`, resolve the use by the same binding proof. For a direct call that refers to `CODE`, substitute the altered literal at the reference. This preserves unrelated uses of the variable and provides a single contiguous source edit. Omit pattern edits for f-strings, formatting, runtime concatenation, arbitrary calls, and unresolved variable bindings. An implicitly concatenated literal can be decoded statically. Map a cross-token atom into one covering source replacement while retaining each token prefix and quote delimiter, intervening comments, unaffected escape spellings, and necessary token separation. Validate its decoded pattern. Source token boundaries alone do not exclude an atom.

## Python semantics and source mapping

Bind positional and keyword arguments against the documented signature. For `compile`, the flags position is the second argument. For module matching, it is the third. For compiled matching, the optional arguments are `pos` and `endpos`. Reject ambiguous starred arguments, expanded keywords, duplicate parameter assignments, and incompatible pattern/subject types when both types are known. Parse known flag expressions built from trusted `A/ASCII`, `U/UNICODE`, `I/IGNORECASE`, `M/MULTILINE`, `S/DOTALL`, `X/VERBOSE`, `L/LOCALE`, `NOFLAG`, and static OR combinations or known integer flag bits. Unknown flag expressions disable flag-dependent edits.

For text, the initial mode defaults to Unicode. For bytes, the initial mode is ASCII and explicit `re.ASCII` adds no Unicode distinction. Emit method or anchor mutations for bytes with known flags. Leave locale-dependent word and case classification untouched. Reject invalid text/bytes flag combinations. Push and restore effective mode at scoped flag groups. The `a`, `L`, and `u` settings override the enclosing character mode in their valid contexts. Scoped `i`, `m`, `s`, and `x` additions/removals affect only their enclosed pattern. Global flag groups must stay at the legal leading position. [Python 3.14 regular expression syntax](https://docs.python.org/3.14/library/re.html#regular-expression-syntax)

Keep the private pattern analyzer iterative and Python-specific. Read Ruff's decoded string or bytes value and retain a mapping to source token ranges. Distinguish characters, escaped sequences, groups, alternation, assertions, bracket classes, and comment regions. Inside a class handle its first literal `]`, optional leading `^`, escapes, ranges, and a literal hyphen. Outside classes skip regex comments and effective `VERBOSE` comments. Preserve named and numeric escapes as lexical units. Use balanced groups and validated quantifier placement. Reject a pattern for syntax-dependent edits when its inputs, grammar, or effective modes cannot be classified. Examples include ambiguous future set operations, unsupported group constructs, undecodable mappings, invalid regex escapes, and unmatched delimiters. A template that inserts a scope around a complete pattern needs special handling for a trailing verbose comment. Prefer editing known global bindings to this template.

Map edits back to original source coordinates. Retain the literal prefix, quote characters, adjacent tokens, and unaffected escape spellings. Double inserted regex backslashes for ordinary Python literals and preserve raw-string escaping for raw literals. Account for physical lines, line continuations, Unicode source offsets, and bytes escapes. Check that the rewritten literal decodes to the intended pattern. Escape spellings can consume a variable number of digits. Include enough neighboring source to prevent joining a new digit to an octal escape, or discard the edit. Parenthesized atom scope keeps quantifiers attached and introduces no numbered captures.

## Discovery and admission

Use a private regex index for call identity, compiled receiver provenance, and flag binding. A private pattern module owns tokenization, effective flags, class comparison, source mapping, and canonical edits. Expose an operation that visits the chosen call's edits and stops as soon as the consumer requests termination. The collector accepts the edit range, operator, and a replacement renderer. Its shared prefix tracks ranking and overflow so the regex emitter can skip work for losing reference sites. Keep Python regex grammar and flag constants internal to these modules. A Python collector, runtime matcher, or internal model is unnecessary.

Gate the index on operator selection. While scanning a pattern, check cancellation at bounded intervals and apply the analyzer's admission rules. Validate the complete supported structure before publishing edits so malformed suffixes cannot leak partial candidates. Scan once for structure and stream accepted edit descriptors in source order, using memory proportional to pattern size and nesting. Avoid cloning a whole pattern for every atom. Stop promptly after capacity failure. Keep candidate IDs stable across repeated runs and preserve line and symbol selection for the actual source edit.

## Five design review passes

| Pass | Finding | Design correction or evidence |
| --- | --- | --- |
| 1. Import and value identity | A method named `search` can belong to an unrelated object. Mutating a reused pattern definition could silently alter several API calls. | Reuse the import resolver, check compiled receivers against a unique binding, visit a compile literal once, and mutate literal-variable uses locally. |
| 2. Set semantics | Unicode case-insensitive ASCII letters admit four extra characters. Switching a complemented class to ASCII has the opposite effect on its accepted set. | Scope the word range under ASCII where needed and describe complement direction explicitly. CPython 3.14.9 and 3.15.1 distinguished all six shorthand/complement probes and all four extra letters. |
| 3. Flag and literal boundaries | Scoped Unicode overrides external ASCII. Inside a class, a source spelling resembling a word boundary may represent backspace. | Restore modes at each closing group and decode Python literals before interpreting regex escapes. Both interpreters distinguished `(?u:\d)` under external ASCII and treated `[\b]` as backspace. |
| 4. Match boundaries and versions | `$` and strict end differ on a final newline. Compiled `pos` can expose a leading anchor. `\B` accepts empty input in the supported versions. | Both interpreters accepted `match("a$", "a\n")` and rejected its strict-end counterpart. A compiled plain prefix matched at offset 1 in `"xa"` while `^a` failed. `prefixmatch` was available on 3.15.1 only. [Python 3.15 matching APIs](https://docs.python.org/3.15/library/re.html#re.prefixmatch) |
| 5. Source edits and budget | Whole-literal clones scale poorly with repeated atoms. A bracket-local insertion can create invalid syntax. A verbose comment can swallow a closing group. | Use source-mapped atom edits and a balanced, cancellation-aware scanner. Switch whole bracket atoms and edit a global flag binding directly. Verify heap bounds and early termination in the implementation. |

The software-design-philosophy assessment is **8.75/10**. The proposal satisfies seven diagnostics through explicit module responsibilities, a narrow edit interface, independent internals, documented guarantees, recorded review decisions, hidden provenance and grammar details, and identifiable boundaries for a newcomer. The eighth diagnostic measures ongoing investment in design improvement. Record implementation review time and compare discovery cost on the same inputs before scoring that diagnostic.

## Verification and release evidence

| Area | Required fixtures and assertions |
| --- | --- |
| Sets and witnesses | Exercise 123, １２３, ١٢٣, and 1２3 for digit and complement behavior. Include superscript two, an accented letter, underscore, a combining mark, and an emoji for word membership. Distinguish ASCII space and all five ASCII whitespace controls from U+001C and U+00A0. Exercise both word boundary assertions on punctuation, mixed text, and empty input. |
| Modes and classes | Exercise external flags by both calling conventions, imported aliases, OR expressions, leading flags, nested mode overrides, scoped removal of `i/m/x`, and sibling restoration. Test positive and negative explicit sets, reordered ranges, mixed sets, and all four Unicode case-fold exceptions. Include bytes with high-bit values and locale-dependent exclusion. |
| Range and source | Check actual match span and captures for whole, prefix, and substring on empty input, leading/suffix junk, final/internal newlines, and compiled `pos/endpos`. Exercise raw, ordinary, bytes, triple-quoted, and adjacent literals, escaped backslash, escaped bracket, class backspace, verbose comments, comments inside regex groups, newline continuation, and non-ASCII source prefixes. |
| Admission and exclusions | Check alias/rebinding, conditional assignment, unknown flags, dynamic inputs, imported external objects with matching method names, malformed patterns, redundant anchors, and fully scoped modes. Ensure unknown cases produce no pattern edit. Verify every produced source parses and its pattern compiles on both supported CPython versions. |
| Product and resource controls | Execute representative mutants through plan, verify, and report. Assert stable IDs, exact source ranges, default and excluded selection, line and symbol filtering, deterministic budget prefixes, cancellation, and unchanged execution outcomes after review. Measure candidate count, wall time, and peak heap on typical sources, long literals, deeply nested groups, and files with no `re` imports. Compare identical fixtures and budgets with existing literal and scalar operators. |
| Specification-led review | Start with an ASCII-only code specification and Unicode `\d+`. Add a test rejecting `"１２３"`. Its failure on the original records an existing bug. Separately require Unicode decimal acceptance, start with correct `\d+` and ASCII-only tests, and add a test accepting `"١٢٣"`. Confirm that the original passes and the surviving ASCII mutant fails. Preserve both outcomes in the review evidence. |

The local probes cover the specific CPython observations in the five-pass table. Release verification still requires implementation of the Rust analyzer, executable integration fixtures, both specification-led examples, comparison with existing operators, and recorded measurements under the existing resource controls.
