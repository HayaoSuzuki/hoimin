# Control-flow mutation design

At commit `4cf630f9`, analyzer maintainers can implement the three issue contracts below with ordinary candidates containing one original span and one replacement. This document records proposed rules and CPython probes. The end-to-end checks and adoption measurements below are implementation work. [Cleanup guarantee](https://github.com/HayaoSuzuki/hoimin/issues/1190), [match dispatch](https://github.com/HayaoSuzuki/hoimin/issues/1197), [statement order](https://github.com/HayaoSuzuki/hoimin/issues/1200).

## Cleanup guarantee

Generate one `finally_unwrap` per `StmtTry` with a nonempty final suite. In a bare try/finally, replace the two header keywords with `if True`, leaving the intervening bytes intact. In a try with handlers, including `except*` and an optional `else`, replace just the final keyword with `if True`. Find its token in the gap between the last preceding suite and the first final statement. A keyword inside a nested try belongs to that child. Use the actual changed range for line selection and identity. The bare form starts on the try line, the handler form on the finally line.

Both constant headers preserve the original suites and lexical scope. They work with tabs, one-line suites, semicolons, nested definitions, and strings spanning physical lines. A string at the start of the protected body cannot become an enclosing docstring. On fallthrough, including a handled exception followed by fallthrough, cleanup runs in its original order. An exception escaping the protected region, an early return, or a break or continue targeting an enclosing loop skips cleanup. The same rule applies to a cancellation or generator close that propagates out of the region. A suspension followed by normal resumption still reaches cleanup. A control transfer inside cleanup keeps its effect on paths that reach it. An exception originally suppressed by a return in cleanup can propagate in the mutant. [Python finally clause](https://docs.python.org/3.14/reference/compound_stmts.html#finally-clause).

## Match dispatch

Use three individually selectable operators. Keep the existing singleton boolean-pattern and expression operators in place.

| Operator | Edit and behavioral contract |
| --- | --- |
| `match_case_delete` | Omit every runtime action of one arm, including its pattern and captures. Replace that arm with `case _ if False:` containing `match None:` and a copy of the original case header. For an indented original suite, append ` pass` to the copied header. The original suite stays at its exact indentation as the next statements of the outer dead arm. For an inline original suite, its existing text follows the copied header directly. The edit ends at the original header colon and retains lexical declarations, free references, generator classification, and enclosing order. The same construction handles a sole case, the last wildcard, class, mapping, sequence, capture, AS, and nested patterns. The outer match evaluates its subject once. Anchor at the original case keyword. |
| `match_guard_constant` | For a nonliteral guard, replace its expression with `(True or (original))` or `(False and (original))`. Pattern dispatch and its successful bindings precede the guard. The old expression has no runtime effects. It stays in the syntax tree so walrus bindings, closure references, and yield classification survive. A guarded nonfinal capture remains legal even when its guard always succeeds. Omit direct boolean literals owned by boolean replacement. Anchor at the guard expression. |
| `match_or_alternative_delete` | Remove one alternative and one neighboring top-level bar within each `PatternMatchOr`, including OR patterns nested in class, sequence, mapping, and AS patterns. Preserve the remaining alternatives and their order. Valid Python requires each alternative to bind the same names. Losing a successful alternative can lead to later cases or to fallthrough. |

The case edit deliberately avoids two faults. Erasing the only binding for a nested function's `nonlocal` can make the module uncompilable. Appending a false guard to the original pattern still evaluates that pattern and can bind names. Use the Ruff token interval between pattern/guard and suite to find the header colon and distinguish an inline suite from an indented one (a multiline guard can have its own lambda colon). The nested dummy match in an indented suite must use the exact indentation of that suite, obtained from its INDENT token. Its case uses that prefix plus four spaces. For an inline suite add four spaces to the outer case prefix for each new level. Insert the local line ending. The original case header's continuation lines, the entire original suite, comments, multiline strings, debug f-string fields, tabs, and form feeds keep their original bytes. Skip the edit when the two inserted logical indentation levels would exceed CPython's compile limit. [Python line structure](https://docs.python.org/3.14/reference/lexical_analysis.html#line-structure), [Python binding rules](https://docs.python.org/3.14/reference/executionmodel.html#binding-of-names).

Partition the OR node's original token interval at its top-level bars. Ruff's grouped-pattern parser returns the inner node, whose range can omit grouping parentheses. Scan balanced delimiters over the enclosing OR range once. For each removal use that alternative's full grouped token extent and the adjacent delimiter, including enough interstitial trivia to avoid a stranded explicit continuation. Preserve the grouping of every surviving alternative and of the enclosing expression. Test open sequence patterns, `(1 | 2) as key`, independently grouped alternatives, multiline comments, and explicit continuations. Multiple successful attribute, mapping, or equality operations may be observable. Assert the dispatch result and explicit application-side effects, leaving unspecified partial bindings from failed patterns outside the oracle. [PEP 634](https://peps.python.org/pep-0634/).

## Adjacent statement exchange

Generate `statement_order_swap` for two contiguous sibling statements in one AST suite. One adjacent exchange also implements a one-position move. A suite of size N has at most N−1 pairs. Examine nested suites independently, including each match arm, handler, else, and final suite. Module and class bodies are eligible under the same rules as functions. Use the existing visitor's module entry explicitly. Its collector otherwise calls `visit_stmt` directly for each root statement.

Admit ordinary standalone calls, directly awaited calls, assignments, augmented assignments, and validation assertions. Require at least one potential effect, such as a call, await, assertion, or attribute/subscript write, to avoid spending budget on independent literal stores. Use one simple target for the initial assignment contract. A plain-name target introduces a name. An attribute or subscript target reads its receiver and index, and can mutate an existing object. An augmented name target both reads and writes. Reject moving a bare-name write behind a read of that name when earlier availability is unproven. A conservative implementation can reject such pairs unconditionally and document that scope. This still tests initialization through `self.state` and `cache[key]`, ordered notifications, and independent locally bound call results. Indirect effects through callbacks and aliases are precisely what an order-sensitive test can observe.

Exclude imports, declarations, deletes, definitions, compound statements, terminal transfers, embedded yields, walrus bindings, and expressions introducing nested scopes outside the name-footprint model. Skip standalone delegation through `super()` to avoid the inheritance-specific move. Check both statements for barriers and relevant name reads. Skip equal spellings. Distinguish `await` on an ordinary call from `yield` and `yield from`. The exchanged awaits change scheduling and cancellation order intentionally. A raising first operation can cause different externally observable work to occur before failure.

Swap complete statement fragments around their original separator with one replacement, anchored at the first statement. Preserve statement grouping and internal continuation text. Statement-level ordinary comments may remain in separator slots as with existing `super_call_move`. Skip a pair where moving across a type, lint, formatting, or coverage directive would change the directive's attachment. Include trailing directives on the second line in this check. Validate both separate-line and same-line semicolon suites, closing grouping before a comment, and missing final newline.

## Five design reviews

1. **Control semantics.** Replacing both headers with constant suites in a bare try avoids dedenting strings and creating an enclosing docstring. Retaining handlers and replacing only the final header preserves handled-exception fallthrough and `except*` semantics.
2. **Compiler and binding behavior.** An in-memory CPython 3.14.9 probe rejected physical deletion of a sole capture referenced by a nested `nonlocal`. The dead nested case compiled. A header-only probe preserved the capture cell, walrus local, and original multiline body while routing to fallback. A tab-indented sole inline case fell through. Probes of both short-circuit guard forms preserved the walrus local and left the guard-side-effect log empty. A cleanup probe preserved the return value on both paths and skipped cleanup only for the mutant's early return.
3. **Source representation.** Ruff discards grouped-pattern delimiters from some child ranges. Partition the parent token range for OR edits. A header-only dead case avoids reindenting user statements. Read its existing suite indent from tokens and preserve multiline token contents, tab columns, local line endings, and encoding conversion.
4. **Admission and duplication.** Root suites bypass `visit_body` in the collector entry. Wire that entry once. Gate costly builders on edited-span selection. Distinguish guard false with captures from case omission. Document an obvious behavioral overlap for wildcard plus false guard. Compare default registrations against emitted candidates and preserve separate individual selectors.
5. **Complexity and test value.** Bounded adjacent exchanges avoid all-pairs growth. Keep scope/name-footprint and trivia decisions inside the owning operator. Defer new shared infrastructure until two operators need the same behavior. Code review must verify the helper comments and measured sparse-selection/retention costs. The design meets seven of eight software-design diagnostics (8.75/10). The remaining criterion is actual design-improvement effort, which can be assessed from the implementation and review record.
