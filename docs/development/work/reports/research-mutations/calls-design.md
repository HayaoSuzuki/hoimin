# Call, collection and rounding mutations

This implementation design defines candidate identities, source edits and test oracles for issues [1192](https://github.com/HayaoSuzuki/hoimin/issues/1192), [1195](https://github.com/HayaoSuzuki/hoimin/issues/1195), [1196](https://github.com/HayaoSuzuki/hoimin/issues/1196), [1198](https://github.com/HayaoSuzuki/hoimin/issues/1198) and [1199](https://github.com/HayaoSuzuki/hoimin/issues/1199). Examples describe proposed mutations. The test matrix records acceptance criteria.

## Shared analysis

Use the Rust analyzer's existing AST visitor, parser tokens, name resolution and candidate admission. Give the new rules one selection-gated call-analysis module. The collector supplies the AST node and its value-use context, source, selection, cancellation and the existing bounded sink. The module owns binding explicit arguments to parameter slots, proven imports, source edits, and any literal result contracts. A comprehension condition also needs its owning generator. An awaited call needs its enclosing await expression. Both facts are available during the ordinary traversal.

Extend the same-module signature index in `optional_keywords.rs`. Factor its complete argument binding and stable-identity checks so optional-keyword deletion and the new rules consume the same evidence. Keep each operator's own eligibility. Optional-keyword deletion currently excludes async functions. Result replacement can consume an async function's contract at a directly awaited call. Retain the own-scope generator checks in `function_body.rs` when distinguishing coroutine functions from async generators. Annotations supply a declared result contract, with runtime type uncertainty retained.

Use `callable_imports.rs` for explicit imports and `AstFacts` for builtins. The current import resolver accepts a root name and one member. Represent the actual bound path for dotted imports. In particular, `import urllib.parse` binds `urllib`, while `import urllib.parse as p` binds its submodule to `p`. Cover `from urllib import parse as p` and `from urllib.parse import quote as q`. Validate writes and escapes through aliases of the package, submodule and local member. Scope uncertainty includes star/lazy imports, relative imports, ambiguous class namespaces and dynamic namespace access. Multiple aliases referencing the same module must share invalidations. Keep invalidation specific to the affected module family. The existing scanner clears all its tracked modules on a module escape, so broadening one scan's module list can change unrelated operators' output. Preserve existing output when another operator is enabled.

Register `round`, `filter`, `sum`, `len` and any replacement builtin consulted by the new rules in name resolution. At synthesized sites check the destination spelling at the original lexical site, even when its name does not occur there. Prefer proven in-scope destination spellings. Where needed apply the existing guarded standard-library import spelling in `effective_python.rs`; invalidate the fallback on shadowed import machinery or destination-module modification. For dotted modules, `__import__('urllib.parse')` alone yields the top-level package.

## Escaping and argument roles

| Operator | Eligible source and edit | Observable contract |
| --- | --- | --- |
| `stdlib_escape_remove` | Resolve `re.escape(pattern)`, `html.escape(s, quote=True)`, and `urllib.parse.quote` or `quote_plus` with `string, safe, encoding, errors`. Bind positional and named inputs, including a later keyword that supplies the primary value. Retain that value. For additional supplied arguments use a parenthesized tuple of their original value expressions, indexed at the primary argument's position in evaluation order. | Each original argument expression runs once. The conversion, optional argument validation and quoting disappear. Regex accepts text and bytes. HTML uses a text contract. URL quoting returns text even for bytes input. Restrict URL removal to statically supported text inputs, including a trusted declared text parameter, literal, f-string or proven text-producing call. Skip known HTML bytes. |
| `call_argument_swap` | Enumerate adjacent explicit slots in source order. Positional pairs use `f(..., *((a), (b))[::-1], ...)`. Named pairs exchange their keyword labels while retaining both value expressions in place. For a mixed boundary with positional-or-keyword formal `p` and explicit keyword `k`, replace that pair with `**{'k': (a), 'p': (b)}`. | Callee and receiver run once before the argument expressions. Values are evaluated in original order and supplied to opposite roles. Positional pairs retain arity and binding shape, including bound method and dynamic callee calls. Named and mixed pairs require a proven signature with explicit formals, eliminating observable reordering in an arbitrary `**kwargs` dictionary. A positional-only formal is ineligible for the mixed encoding. |
| `call_result_default` | A consumed synchronous call with known result contract becomes `(original_call, default)[1]`. A consumed, directly awaited proven coroutine call becomes `(await original_call, default)[1]`. Emit one default per supported builtin return contract, for example `False`, `0`, `0.0`, `''`, `b''`, `[]`, `()`, `{}`, or `{*()}` for an empty set. Resolve the annotation's type at the definition and support builtin container generic aliases. | Original evaluation, writes, exceptions and awaiting occur along the taken control-flow path. A fresh container is created per successful evaluation. Dropping the original result can change finalization and weak-reference timing. Skip unused expression statements, unknown types, declared None, bare coroutines and generator/async-generator calls. A nested call whose result controls short-circuit evaluation is a consumed value. |

For escaping and swapping, reject expanded arguments, duplicate assignments and unsupported signatures. Exclude provably identical simple swap values, including the same stable read or equal literals of the same type. Repeated calls with identical source can return distinct values. Use exact token boundaries to keep comments, commas and grouping outside the changed operation. Escaping and call-result replacement change different aspects of a call. Existing conversion deletion, optional keyword deletion and return tuple swaps continue to describe separate faults. [Python evaluation order](https://docs.python.org/3/reference/expressions.html#evaluation-order), [regular expressions](https://docs.python.org/3/library/re.html#re.escape), [HTML escaping](https://docs.python.org/3/library/html.html#html.escape), [URL quoting](https://docs.python.org/3/library/urllib.parse.html#url-quoting)

## Selection and aggregation

| Operator | Edit and preconditions |
| --- | --- |
| `comprehension_filter_remove` | At one `if condition` site in a list, set, dict or generator comprehension, replace the test expression with `True`. This bypasses the predicate and its effects, retains token boundaries and leaves every other clause in its original position. Skip a literal true condition and named-expression bindings needed after the removed evaluation. |
| `comprehension_filter_invert` | Replace one condition by `not (condition)`. Preserve one test per reached element, generator laziness and original nested clause order, including async comprehensions. Suppress equivalent spelling already covered by an existing unary removal at the same span where applicable. |
| `filter_predicate_swap` | Swap a resolved builtin `filter` with `itertools.filterfalse` and vice versa for exactly two positional arguments. Change the callable reference. Preserve the original predicate object, including `None`, the input iterator, lazy consumption and exception behavior of the predicate. Validate the replacement callable's name at the site. |
| `set_union_intersection_swap` | Exchange `union` and `intersection` on proven exact set/frozenset receivers with at least one ordinary operand. A set literal, set comprehension or proven builtin constructor qualifies. Also allow a stable local initialized by one of those forms using a unique reaching assignment. An annotation alone can describe a subclass with custom methods. Preserve operand evaluation and the receiver's result type. |
| `aggregate_sum_count` | For a resolved one-argument builtin `sum(items)`, emit `sum(1 for _ in (items))`, parenthesizing generator-expression inputs correctly. The input expression is evaluated once and consumed as an iterator, including an empty or one-shot source. Counting deliberately skips arithmetic on elements. Exclude explicit starts and expansions. In the converse direction allow `len` to become resolved `sum` on a proven concrete numeric list/tuple with no external iteration hooks. Dynamic length and arbitrary unsized iterators do not have a common interface. |

Each candidate acts on a single clause or call. Eager dictionaries/sets/lists and lazy generators retain their native result kinds. Where earlier filters suppress the remainder, later tests and iterables execute only if reached. Cover duplicates with list input and exact-order assertions. Existing `ItertoolsTakeDropSwap`, `any/all`, bitwise set operations and list-to-generator conversion target different contracts. [Python comprehensions](https://docs.python.org/3/reference/expressions.html#displays-for-lists-sets-and-dictionaries), [filterfalse](https://docs.python.org/3/library/itertools.html#itertools.filterfalse), [builtins](https://docs.python.org/3/library/functions.html)

## Rounding and decimal precision

| Operator | Edit and preconditions |
| --- | --- |
| `rounding_function_swap` | Resolve one-argument positional `round`, `math.floor`, or `math.ceil`. Emit the other two members in fixed lexical order, checking source and destination identity. Document the distinct arithmetic protocols and non-finite inputs that may raise. |
| `round_digits_remove` | For a resolved builtin round with explicit non-None `ndigits`, replace just the digits expression with `(digits, None)[1]`. The digits expression still evaluates once at its original position. The default rounding operation may return an integer or use a different custom numeric method contract. |
| `decimal_rounding_mode_swap` | Exchange proven `ROUND_HALF_EVEN` and `ROUND_HALF_UP`, `ROUND_CEILING` and `ROUND_FLOOR`, or `ROUND_DOWN` and `ROUND_UP`. Map `ROUND_HALF_DOWN` to `ROUND_HALF_UP` and `ROUND_05UP` to `ROUND_UP`. Match the `rounding` argument to a verified Decimal.quantize, Context or localcontext, or an assignment to a verified context's `.rounding`. Direct imports and aliases use a proven replacement spelling. |
| `decimal_quantum_shift` | For `Decimal.quantize` with an exact, finite literal Decimal quantum, emit valid decimal literal quantum exponents one higher and one lower. Quantize takes the exponent as its unit. Handle trailing zeros and scientific notation with checked exponent bounds. Exclude dynamic quantums and invalid Decimal strings. Preserve existing context/rounding arguments. |
| `decimal_context_precision` | For explicit positive literal precision in `Context(prec=...)`, `localcontext(prec=...)` or a verified context's `.prec` assignment, coarsen values of at least 3 to 1. Change precision 1 to 3 and 2 to 4. These moves stay positive and differ from the existing one-step integer literal mutation. Handle constructor positional precision when its signature establishes that slot. |
| `intermediate_rounding_remove` | Identify an inner recognized round or quantize in an arithmetic operand beneath a final recognized round/quantize. Retain the inner numeric input and the evaluation of supplied options, then perform the outer arithmetic and final rounding as written. This distinguishes rounding each line item or subtotal from rounding only the result. |

Recognize Decimal/Context constructor calls, `getcontext()`, `with localcontext(...) as ctx` and uniquely initialized local variables before trusting their methods or settings. Unknown methods with the same name remain ineligible. An explicit rounding mode overrides a context default. A missing mode uses the active context. Replacing or bypassing quantization can change Decimal flags, exceptions and traps. Cover these effects directly in the numeric oracle. [Decimal arithmetic and signals](https://docs.python.org/3/library/decimal.html), [builtin round](https://docs.python.org/3/library/functions.html#round)

## Five design reviews

1. **Coverage.** A regex-only edit would miss HTML and URL quoting. Treat argument misbinding, returned values, filter clauses, lazy filters, set operations, aggregates and intermediate rounding as independent observable behaviors. Register the selected IDs in the default catalog and document targeted exclusion.
2. **Identity.** The current one-member import policy would misidentify `urllib.quote` after a dotted import. Track imported paths, both sides of callable swaps, module mutations and class lookup. Resolve known set and Decimal receivers independently of their method spelling.
3. **Evaluation.** Reversing expression text reverses side effects. Positional unpacking and keyword relabeling preserve evaluation order. Indexing an evaluated tuple preserves call effects. Wrap the entire await and skip unused results. Counting by iteration supports one-shot iterators.
4. **Source and resource bounds.** AST ranges can omit redundant parentheses or include an unparenthesized generator enclosed by its call. Use parser tokens when slicing. Apply site/line/symbol selection before building replacements. Poll cancellation in every per-site loop, and stop on sink rejection. Emit swaps in linear adjacent order and cap same-span variants at the existing candidate-prefix witness. Different source starts can have distinct selections and require separate eligibility checks. Preserve UTF-8 offsets, comments outside edits and stable candidate IDs.
5. **Integration and falsification.** Register names and defaults in `hoimin-core/src/config.rs` and update CLI behavioral ranking and its reason tests. Record coverage status in `valid-python-operators.json`, and add independent parseable examples to the Rust and CPython contract suites. The JSON file inventories the legacy cross-producer Lean corpus; its `covered` status must not imply model coverage supplied only by separate compiler/runtime fixtures. Exercise explicit selection, default selection, exclusion, saved plans, verify, report and cancellation through existing paths. Put weak/strong test pairs in real temporary projects so the observed survivor/kill distinction tests a user-visible requirement. Running those gates is part of implementation.

The design review satisfies the eight software-design-philosophy diagnostics (10/10 at design scope). The abstraction owns stable callable identity, slot binding and edit selection. Its interface comment must document evaluation and cancellation guarantees. Existing operators need parity tests when sharing previously private analysis.

## Independent test oracles

Use separate Arrange, Act and Assert blocks in each test. Table-driven cases should make one independent claim per row. Use a fresh project, trace or Decimal local context per case.

| Family | Fixed cases for rstest | Property or end-to-end evidence |
| --- | --- | --- |
| Escaping | Unqualified, aliased, dotted, package alias, wildcard, overwritten module or member, scope shadow, reordered keywords, invalid binding, options that raise, regex bytes, HTML text, URL text/bytes. | Generate safe text and text containing characters from the relevant grammar. Weak example accepts an alphanumeric value. Strong examples assert literal matching of a dot, HTML escaping of an ampersand, and quoting a URL component containing a space. |
| Argument swaps | Two/three positional slots, bound method receiver lookup, mixed boundary, keyword-only slots, positional-only exclusion, duplicate values, distinct calls with identical source, varargs exclusion, exception in each evaluated position. | Generate distinct slot markers and traces. The trace equals the baseline prefix, including an exception cutoff, and successful parameter bindings differ by exactly the selected transposition. A transfer test checks the two account balances separately. |
| Result replacement | Synchronous writes, awaited writes/cancellation, raised exception, false short-circuit, result whose truth conversion raises, unused outer call with consumed inner argument, bare coroutine, generator, missing/rebound annotations. | A write-only test survives changing an update count to zero. A returned-count assertion kills it. A fresh container is distinct on successive calls. Assert exception class and trace separately. |
| Collections | All four comprehension kinds, multiple for/if, each eligible condition independently, async iteration, duplicates, None predicate, predicate error, one-shot iterator, exact set/frozenset receiver, custom homonym, empty aggregate, explicit start. | Generate lists and compare ordered results to an independent reference loop. For laziness inspect trace before first iteration, after one item, and after exhaustion. Distinguish unwanted elements, duplicate multiplicity, union/intersection, and values whose sum differs from their count. |
| Rounding | Positive/negative ties and non-ties, digit carry, negative ndigits, signed zero, NaN, infinity and Decimal traps/flags with isolated contexts, explicit vs implicit mode, context restoration, exponent limits, and intermediate arithmetic. | Decimal('2.45') quantized to one tenth distinguishes half-even 2.4 and half-up 2.5. At one decimal place, rounding 2.45 before multiplying by three differs from rounding only the product. Generate bounded integer coefficients and decimal exponents, then compare value, sign, exponent and selected signals to independent Decimal calculations. |
| Plumbing | Per-ID default/exclusion, saved plan replay, CLI reporting, CRLF/Unicode/comments, line/symbol filters, huge arity, low candidate and payload budgets, cancellation during indexing and emission. | Every emitted replacement reparses. Applying it leaves bytes outside the selected span intact. For each limit k, candidates and overflow match the bounded prefix of the unlimited run. Enabling an unrelated operator preserves candidates of operators enabled individually. |

A CPython 3.15 design probe verified all three argument-rewrite forms with a traced callee, three argument expressions and observed bindings. It also verified reordered escape-option evaluation, one awaited write with a replaced result, and the Decimal midpoint and intermediate-stage examples. These probes exercise the proposed Python expressions. The analyzer and CLI acceptance tests remain implementation gates.
