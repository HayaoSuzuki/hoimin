# Issue #342 Linux resource waits

Linux root termination and run close now release the shared registry mutex before cgroup cleanup. A root cleanup mutex serializes operations on that root. A run close mutex serializes close calls; close publishes `closed`, snapshots roots, releases the registry, and acquires the root mutexes in UUID order. These guards remain owned through recursive run-directory cleanup.

Before deleting event files, termination records accounting and marks the root inactive under the registry mutex. Successful physical cleanup removes the entry even if accounting failed. Failed cleanup restores the previous active flag. Close similarly hides all captured roots from counter reads, removes successfully cleaned entries, and restores accounting eligibility for remaining entries when run-directory cleanup fails. Only successful run-directory removal sets `cleaned`. Existing accounting-primary error aggregation remains in use.

The private `terminate_root_with` and `close_with` functions contain the production algorithms; their production callers supply `cleanup_cgroup`. Tests substitute only the physical cleanup operation so they can pause after deleting fake counter files while exercising the real registry and locking logic.

- Final broader check: `docker exec hoimin-342-linux-tests cargo test -p hoimin-cli --lib resource:: -- --test-threads=1`: 43 passed, 1 ignored subprocess fixture, no failures.

- `rustfmt --edition 2024 crates/hoimin-cli/src/resource/linux.rs` and `git diff --check -- crates/hoimin-cli/src/resource/linux.rs`: passed.

Seven added regressions:

- `root_cleanup_releases_state_and_allows_sibling_termination`: pauses one root after its event files are deleted; confirms state access and sibling termination complete before releasing that root.
- `close_cleanup_releases_state_and_publishes_closed_before_waiting`: verifies close publishes its state and makes the root inactive before physical cleanup.
- `close_waits_for_inflight_root_cleanup_without_holding_state`: closes while a root cleanup is paused, verifies the closed flag remains readable, then releases the root and finishes both operations.
- `close_keeps_all_root_gates_through_recursive_run_cleanup`: verifies every root gate and the close gate remain held throughout child and recursive run cleanup, including a failed child cleanup subsequently completed by recursive cleanup.
- `failed_root_cleanup_restores_accounting_and_remains_retryable`: verifies restored event observation produces an out-of-memory classification and a later cleanup succeeds.
- `failed_close_restores_only_failed_roots_and_retries_run_removal`: verifies successful siblings disappear, failed roots remain observable, new preparation is rejected, and close can retry removal.
- `accounting_error_still_commits_successful_root_cleanup`: verifies malformed counters do not prevent cleanup or cause an already removed root to be cleaned again.

These regressions use controlled fake cgroup files and channels, with timeouts only as deadlock watchdogs. They establish the production algorithm's ordering and progress, not kernel cgroup hard-limit behavior. Existing Linux pidfd and launcher tests also passed. No real delegated-cgroup integration or Rust 1.88 execution was performed in this subtask.
