# Issue #956: internal cleanup ownership

## Design and scope

Replace the report status plus optional retry reason with `CleanupDisposition`
(Clean, Failed, Deferred with an optional coordinator-contention reason).
`CleanupRecord` owns this classification and independent `CleanupEvidence`.
The shell outcome is a record plus presentation error, without another variant.
Only report assembly projects disposition to `DiskCleanupStatus`; report-only
Retained and CleanupAfterDelivery never enter a cleanup record. Evidence alone
can be reconstructed from a report for startup-janitor diagnostics.

Keep cleanup admission, retry interval/deadline, marker error classification,
root identity checks and all four finalization paths unchanged. Unknown remaining
roots stay unknown even for Failed/Deferred; path evidence does not encode status.

## Design reviews (before implementation)

1. State-space review: placing retry reason in Deferred excludes Clean/Failed
   contention and excludes both report-only statuses from actual results.
2. Ownership review: shell struct carries presentation text, while its disk
   projection reads the record disposition; no duplicated classification remains.
3. Evidence review: counts, bounded details and remaining root share an evidence
   type, allowing display reconstruction without inventing execution outcomes.
4. Policy review: preserve the 10 ms contention retry and shutdown deadline;
   live-child, deadline and integrity deferrals remain janitor work.
5. Scope review: retain marker detail extraction and independent secondary errors;
   do not modify core lifecycle transitions, report schemas or Lean models.

Software-design-philosophy diagnostic assessment: 7/8 rows evidenced (8.75/10,
not a claim of perfect design). Module responsibility, interface depth,
implementation independence, intent comments, design review, hidden classification
and documented boundaries are addressed by this replacement. The 10–20% design
investment row is unmeasured; time tracking would be required to establish it.

1. Producer review: inspected every cleanup return, including claim deadline,
   zero budget, live children, both contention locks, Windows capability reuse,
   missing entries and interrupted identity checks. Only contention constructs
   Deferred with a reason. Remaining paths preserve their previous disposition.

   struct stores no status alongside the record and no report-only fallback.
3. Diagnostic review: bounded insertion moved unchanged to CleanupEvidence.
   Marker failures append evidence for Clean and append display error for
   Failed/Deferred. Delivery secondary extraction remains unchanged.
4. Report review: actual records project their disposition; absent records copy
   only report evidence, preserving Retained and CleanupAfterDelivery. Startup
   reclaim adds saturating omitted/truncated counts without overwriting status.
5. Platform/test review: searched all CleanupRecord constructors and consumers,
   including Windows-only first/second/resumed/while-closing fixtures and inline
   cleanup calls in copy.rs. Replaced the inconsistent misleading-string fixture
   with valid Failed and Deferred records. Exact thread-failure assertions reject
   an erroneous Clean result as well as incorrect deferral.

| Route | Classification source and retained behavior |

| Outer execution | same disk projection; incomplete outcomes preserve kind and append finalization error, Clean marks cleaned |
