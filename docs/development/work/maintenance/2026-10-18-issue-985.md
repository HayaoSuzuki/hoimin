# Regular-file admission for verify and progress

Issue [#985](https://github.com/HayaoSuzuki/hoimin/issues/985) identified blocking
opens of writerless FIFOs in `verify` and `progress`. Starting from `3de9beca`,
this change routes their manifest/report opens through
`artifacts::open_regular_file`. On Unix the helper uses `O_NONBLOCK` and checks
the opened descriptor. Both commands read from that descriptor, accept symlinks
to regular files, and report nonregular inputs through their existing errors.

Verify retains both requested and canonical manifest paths for output protection.
The decoders retain their content checks, and progress retains JSON/JSONL input.
Neither command adopts review's 64 MiB limit. Avoiding the wait for a FIFO writer
does not establish a deadline for other filesystem operations, an I/O throughput
bound, or an RSS bound.

## Requirements and design reviews

1. Traced `read_manifest` and `open_report` to blocking opens before parsing;
   selected the existing descriptor helper rather than a path-metadata check.
2. Kept caller errors: `ManifestInvalid` for verify and `ProgressError::Read`
   for progress. An opened nonregular descriptor yields `InvalidInput`.
3. Checked symlink policy and protection: follow regular-file input symlinks;
   retain verify's absolute requested spelling and canonical target, in order.
4. Separated file-kind admission from parsing and byte limits. Reusing
   `bounded_read` would impose an unrelated review policy.
5. Scored the scoped design 10/10 against the software-design-philosophy
   diagnostics: all eight pass. The shared opener owns flags and descriptor
   validation; callers own decoding, protection and diagnostics. No new interface
   or configuration is needed.

## Implementation plan reviews

1. Chose a focused public CLI test binary, `artifact_inputs`, with generated
   independent tests for the finite input-kind matrix.
2. Put the deadline outside the command process. A drop guard kills and waits
   on timeout or panic; temporary output files avoid pipe-buffer waits.
3. Separated rejection, manifest parsing and report acceptance expectations.
   Each generated function has one fixture, one invocation and unconditional
   assertions, with Arrange/Act/Assert separated by blank lines.
4. Added regular/symlink, directory and missing controls, progress JSON/JSONL
   acceptance, and 65 MiB whitespace padding to detect an accidental review cap.
   Directory checks use caller context because Windows can reject the open
   before descriptor inspection.
5. Waited for the shared baseline before Cargo and production edits; used one
   Cargo process, two build jobs, two test threads and the shared task target.

## Implementation reviews

1. Inspected ownership: `read_manifest` reads the admitted `File`; `open_report`
   returns that same file to buffered and fingerprinted readers. No reopen occurs
   between admission and content reads.
2. Compared verify protection before and after: canonicalization, requested path,
   ordering and error context remain in `read_manifest`.
3. Traced both report entry points and duplicate confirmation. Fingerprinted and
   ordinary report reads share the changed opener; duplicate confirmation already
   uses `open_regular_file`.
4. Checked regression independence and cleanup: direct/symlink FIFO tests each
   launch one child. The guard reaps on deadline assertion. Moved the padding
   buffer to the heap to avoid consuming a test thread's stack.
5. Reviewed the diff for complexity and scope: two production callers, one test
   binary and this record. Removed test phase comments to follow the repository's
   blank-line AAA convention. No decoder, format, limit or dependency changed.

## Verification reviews

1. Observed RED before production edits: 12 controls passed; the four direct or
   symlink FIFO cases failed at their five-second watchdog (exit 101).
2. Observed GREEN after the caller changes: all 16 cases passed in 2.70 seconds
   (exit 0), including usable JSON/JSONL and inputs larger than review's limit.
3. Ran neighboring integration suites: plan 105 passed/1 ignored, progress 99
   passed. This includes current-plan reparsing and the public CLI test protecting
   the requested manifest symlink and its referent from metrics output.
4. Ran the artifact library selection: 12 passed/1,032 filtered out. No claim
   extends that focused run to the whole library. Root coordination owns the final
   whole-branch workspace run; its pre-edit baseline had 3,306 passed/39 ignored.
5. Reviewed platform and evidence limits: this execution used macOS. FIFO and
   symlink cases use Unix `cfg`; Windows and Linux execution remain for CI/final
   validation. The 65 MiB examples test admission policy, not general memory use.
