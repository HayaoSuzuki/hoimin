# Issue 1006 design discovery

Read-only inspection at 34e3349099ce7fd61838629ee8c0d0b814e65a5d. No fresh benchmark result is claimed here. `selected` in hoimin-python/src/analyzer/rust.rs scans request.lines on every token/AST candidate; `expression_selected` has the same entry point. Public AnalyzeRequest accepts arbitrary LineRange arrays. The existing core LineSelectionIndex is a path-keyed selector index with empty-means-none semantics, not this per-file empty-means-all boundary.

## Proposed boundary and alternatives

Prepare one private CandidateSelection per successful file analysis, separate from the source-position LineIndex. It owns an All/Restricted line index and borrows path/symbol selectors. All is used only for an originally empty slice. Restricted can be empty after filtering reversed intervals and must then select nothing. Preserve inclusive u32 coordinates, including zero and MAX values accepted by the raw public struct. No caller sorting requirement and no public API migration.

Sort valid intervals by (start,end), replace each end with the maximum end of its prefix, and query the final start <= line with partition_point before checking that end. This represents the same union for overlaps/nesting/duplicates/adjacency without a path map or a second copy of core target normalization. The prefix-max invariant is documented: all starts to the left qualify, so their maximum end is exactly the membership test. Preparation O(R log R), retention O(R), membership O(log R); All allocates nothing. This does not compact duplicate or adjacent ranges, which is an explicit memory/time tradeoff measured below.

Thread &CandidateSelection through private candidate creation, AST collector and annotation production. It owns symbol matching currently inside selected; no symbol index or module-resolution redesign. Keep the existing unrestricted fast path in expression_selected. Public AnalyzeRequest fields remain unchanged. Suggested file analyzer/rust/selection.rs and separate selection_tests.rs; no new external dependencies or compatibility wrapper.

Alternatives: linear scan preserves the defect; path-keyed core index adds path allocations/semantic adaptation; changing AnalyzeRequest.lines to a public prepared type needlessly migrates callers; wrapper/Deref prepared requests obscure the independent index; normalized interval union is valid but duplicates existing target normalization unless factored across unrelated scopes. The prefix maximum has a direct independent linear oracle and one compact private representation.

Cancellation is cooperative, not a hard latency promise. Keep initial cancellation/error precedence, check before preparation, while copying and prefix construction, and after sorting. The standard sort is one bounded synchronous phase, as existing parsing/index construction already is; do not use panic control flow or a comparator with inconsistent ordering to interrupt it. Candidate payload accounting remains unchanged; selection storage is not candidate payload.

## Five design review passes

1. Semantics: empty raw input selects all; nonempty all-invalid input selects none. For arbitrary valid/reversed/overlapping/adjacent ranges and arbitrary u32 query, compare with ranges.is_empty() || ranges.iter().any(start <= q && q <= end). At MAX no end+1 arithmetic is needed. Symbol admission remains conjunction with line admission, including nested/module-qualified selectors.
2. Information hiding: one private prepared owner is reused by token, AST and annotation paths; keep selection membership separate from source-position indexing (#1008) and path ranking (#446). Public callers supply raw ranges without hidden preprocessing obligations.
3. Cancellation/limits: no change to max_candidates, ordering, truncation, ID creation or logical payload accounting. Test pre-cancel and cancellation during preparation; original syntax/hierarchy diagnostics keep precedence. Existing discarded-replacement and exact payload tests stay relevant.
4. Proof of actual work: first instrument the old predicate under cfg(test) and run sparse blank-line workload N=1000,2000,4000,8000, max1. Record actual old comparisons, not the issue's predicted N squared. New counters distinguish preparation comparisons, number of queries and membership comparisons; guard C log R using actual query count plus an independent linear oracle. No timing assertions in CI.
5. Evidence/scope: preserved release binary/rlibs at /tmp/hoimin-perf-three-baseline support matched before/after probes. Measure raw API workload/control and actual CLI many --line plus noncontiguous --changed. Record source/selector/output hashes, zero candidates/diagnostics/truncated=false for historical sparse fixture, at least3 warm samples and median/range, requested heap separate from RSS. Include small unselected/all-selected/unsorted overlap cases; do not assert universal speedup from adversarial fixture. One behavior per generated test, AAA, bounded property cases.
