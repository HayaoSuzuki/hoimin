# Report configuration decoding (#939)

## Scope and design

Review must reject duplicate known fields in the current report's embedded
`RunConfig`, including nested configuration fields. The previous reader first
collected configuration into a `serde_json::Value` map, which retained only the
last value, then called `from_value`. That erased evidence needed by typed
configuration decoding.

Parameterize the existing private report document and run header by the
configuration type. Review selects `RunConfig`; progress selects
`serde_json::Value`. Keep schema, event identity/order, stable identity, count,
completion and baseline validation in the shared report validator. Check the
opaque configuration's object/null shape once at the progress read boundary
for both JSON and JSONL. Review's typed decoder already requires a configuration
object. No old-schema adapter, public API, configuration trait or generic JSON
parser is needed.

The internally tagged run event buffers serde content, so tests must establish
that duplicate map entries survive that boundary into typed configuration
validation. `RawValue` would require changing the tagged representation or an
additional extraction pass; it is unnecessary if typed decoding passes the raw
input regressions. A second full document parser would duplicate ownership of
the run header.
