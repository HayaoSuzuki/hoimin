# Django拡張のセルフレビュー

設計と計画の各5回は[承認済み方針と実装計画](../superpowers/plans/2026-10-11-issue-790-django-extension.md)に記録した。

## 実装段階の5回

1. **対象と互換性。** generatorへpath・symbolを渡せるようにしたが、既存proofreadtoolsのwrapperと候補集合は保持した。対象外関数へ編集が漏れない先行テストは未実装で失敗し、実装後成功した。製品コード・依存・schema・既定operatorには変更がない。
2. **実行判定。** Django公式runnerの実テスト件数とskip数をbaselineと照合する。AssertionErrorと通常エラーを分ける。Exit(0)だけで成功とせず、タイムゾーンに関する22件の既知skipを隠さない。
3. **観測とoracle。** 固定の入力領域・設定と明示的なnowを使う。probeの差は暫定結果であり、報酬も暫定差とoperator新規性のheuristicに限定する。実moduleで元・変異を各2回照合した対象だけを検証済みと呼ぶ。生成した期待値はcharacterizationで、人の仕様確認を代替しない。
4. **資源と原状復帰。** 既存ProcessHandler・workerの1GiB、16プロセス、出力1MiB、コピー8GiB、空き10GiBを共有する。未完出力・timeoutは次の候補へ進む条件にしない。各変異のresetと最終cleanup・元checkout照合・子孫回収を確認してから結果を保存する。
5. **CIとコスト。** 小さいPython契約だけを自動・手動qualityへ同時追加し、一致テストを通した。実Django実験はignoredにする。全OSSの全suiteやネイティブビルドを追加せず、各armのwallと起動数を測る。準備・resetも含む実時間は別に報告する。

## 診断と判断

- 最初のcloneはhoiminの無視対象 `.superpowers` 配下に置いたため、workerコピーで除外された。baseline未実行で停止し、worker清掃・子孫回収を確認した。固定cloneだけをrepository外の一時ディレクトリへ移した。空のworkerを生存として数えない。
- 手動編集用Pythonの既定cp932がworkflow内のUTF-8文字を読めず停止した。編集の読み書きをUTF-8で明示した。実験の子プロセスには既存のUTF-8設定を適用する。
- 独立レビュアーがHypothesisの再確認時に時間予算を超えるとpredicateがTrueからFalseになり、FlakyFailureとなる境界条件を指摘した。単純なsleep再現と、時計と入力を固定した先行回帰テストで確認した。実験中の補助コードは変更せず、終了後にcacheで修正し、Django契約7件が成功した。実experimentではsearch起動が0件だったため、この修正で比較値は変わらず、15armの再実行は不要と判断した。
- 既存pytest一時ディレクトリへのsandboxアクセス拒否は環境の失敗として区別し、必要な権限で実行した関連24件とworkflow lintが成功した。

## 計画の解釈

arm内のprobe witnessは暫定の入力探索結果として記録する。
全てのprobe差を検証済みと数えず、最終照合の最大3候補だけを実moduleで検証済みと呼ぶ。
生存候補を見つけた場合に限り入力生成を行うため、既存suiteで全検出されたarmから入力探索の優位は判断しない。

30秒は候補開始の時間窓として実装されたが、同期reset等によりarm実wallは最大35.547秒となった。
当初のwall上限を完全に達成したとは扱わず、設定と実時間を区別し、報告へ超過を記載した。
fixedはrank順・pool結合順からnumberformatへ偏っており、random/guidedとの差を探索アルゴリズム単独の因果効果とは解釈しない。

## テスト段階の5回

1. **先行失敗。** Python補助moduleとRustの対象指定APIが未実装で失敗することを確認した。時計固定のdeadline回帰はFlakyFailureで失敗し、cache修正後に成功した。
2. **観測の負例。** 同一関数を等価と呼ばず、例外や非scalarを反例に数えない。timesinceへ常に明示的nowとdepthを渡すこと、生成資料が実moduleをimportすることを契約で確認した。
3. **結果照合。** 15arm・各5 seed・71評価・35候補ID、41 assertion・30その他エラー・生存0を証拠から集計した。収集62・skip22、root command 79回を照合した。生成テストのDjango end-to-end成功を主張しない。
4. **互換性とlint。** Rust契約9件、Python関連25件が成功した。既存proofreadtoolsの契約も保持した。Clippy全target・全featureの警告をエラー扱いし、ty、Ruff check/format、cargo fmt、workflow lintを通した。自動・手動CIの一致テストも成功した。
5. **証拠・清掃と費用。** 生存候補のない負の結果も全候補pool・各試行・plan fingerprint付きで保存した。worker削除・元checkout照合・子孫回収・drain完了を確認した。検証後cargo cleanで5,414ファイル・3.3GiBを削除し、実験wall・reset等の未分解費用・予算超過を明記した。

## 独立レビューの最終確認

別のレビュアーが15arm・71行・35候補ID・判定件数・時間・root起動数・清掃結果を再集計し、報告との一致を確認した。
Django契約7件と時間境界の元の再現例も成功した。
30秒超過、fixedの関数配分の偏り、生存0件、Django生成テスト経路の未実行を含め、主張の範囲が明示されており、未解決の要対応指摘なしとの結論だった。
OKFの39ページの形式、新しい出典hash・脚注・入口からの到達性、全398候補のspanと構文、15armのseedとroot起動数も別途確認した。
