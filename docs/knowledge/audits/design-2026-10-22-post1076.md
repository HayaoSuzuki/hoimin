# #1077 — review の拒否前副作用

`ReviewStore::open_read` は regular-file/size check の後、通常の READ_ONLY 接続を開き、
最初の `PRAGMA application_id` で用途を判別する。DELETE-only の確認はその後なので、
誤って指定した別用途の閉じた WAL DB でも補助ファイルが生成され得る。
公開 `list/show` からこの経路へ到達する。[^review-store][^review-entry]

小さい Python SQLite 同等操作を確認した。Python 3.14.8 / SQLite 3.53.1 で、
WAL mode の table と 1 行を commit/close し、READ_ONLY 接続、foreign_keys/trusted_schema
の設定、application_id 読取り、close の順に実行した。before の通常 SQLite 観測が
補助ファイルを先に作ることは避けた。

| 観測 | DB | WAL | SHM |
| --- | ---: | ---: | ---: |
| 取得前の閉じた fixture | 8,192 bytes | なし | なし |
| RO 接続・用途読取り・close 後 | 8,192 bytes | 0 bytes | 32,768 bytes |

DB 本体の bytes は一致した。**これは現行 bundled rusqlite／公開 CLI の再現ではない。**
現行 Rust 経路の regression RED を着手時に最初に確認する条件を Issue に明記した。
元データの破壊・外部攻撃を実証した指摘としては扱わない。対応する review DB は DELETE
mode に限るので、session の immutable URI 一式の移植を必須にせず、接続前の WAL header
拒否を最小案とする。補助ファイルを事後削除して結果だけを合わせない。[^session][^review-store]

# #1078 — 表示用の履歴所有

snapshot は synchronous render の終了まで生存するが、現在の ReviewRow は history と
最新 review を所有するため、選択した履歴の全 clone と最後の event の clone を要求する。
stale 行も同様で、show/list/record に同じ構築経路がある。snapshot を所有者にし、
`history: &[ReviewEvent]` と `review: Option<&ReviewEvent>` を private な表示型に使えばよい。
candidate の所有まで変える必要はない。空の履歴を local default から借りたまま逃がさず、
`&[]` などで扱う。新しい cache、trait、Arc、型階層は不要。[^review-entry][^review-render]

既存の whole-command show テストは unrelated histories を増やし、selected history は
3 件に固定する。#1052 の store 側の改善は保たれているが、本件の選択履歴の二重保持は
検出しない。1/16/64 件・1–4 KiB 程度の reason/evidence、1 MiB 以下の fixture、sink writer
で表示用 allocation を測る条件を付けた。出力形式・保存履歴・SavedOutput の意味は変えない。
効果の数値は未測定。[^review-scaling]

# #1079 — mutant 適用時の全文作業

apply_mutation は raw bytes を hash した後、CandidateValidationContext の生成でも同じ
全文を hash する。さらに元の本文を保持しながら、別の Vec に変異後全文を作る。
S-byte 本文の span L を encoded replacement R へ置換すると、本文だけで
S + (S−L+R) bytes が同時に生存する。これを処理全体の使用量や、削減できる RSS と
混同しない。各実行 mutant の処理であり、修正済みの #1074 の project index 構築とは別。
[^mutation][^candidate][^exception-project]

正常経路の raw hash を一度にし、検証後に借用 context を解放して本文 buffer を safe な
操作で再利用する。context を先に作ると raw/decoded size 超過に由来する MutationSpanInvalid が
MutationHashMismatch より先になる場合があるため、単に順序を変える提案にはしない。
全検証が write より先であること、encoding/BOM、capability、race/reset 保護を維持する。
contracts の変更前証拠も残し、同じ buffer と自分自身の比較で検証を無意味にしない。
[^mutation][^candidate]

64/256/1024 KiB のコメント中心 ASCII source と小さい同長置換で apply の peak requested heap と
raw hash 作業を観測する。大規模 fixture、unsafe、unchecked hash constructor は不要。
伸長・縮小・Unicode/Latin-1・複合エラー・reset は機能条件として別に確認する。
性能数値や CLI 全体の高速化はまだ主張しない。

# 起票しなかった候補

- **sampling の dense index。** k が小さくても N 個の usize を作り、truncate 後も capacity が残る。
  ただし現行 plan 読取り上限内の補助領域であり、疎／密の分岐を増やす価値は未測定。
  将来測るなら N=1k/4k/16k、k=1/8 の allocation と seed/ordered prefix を確認する。
  今回は余分な複雑さを追加する Issue を起票しない。[^sampling]
- **enum の増設。** RunIdentity、WorkerState、report lifecycle、SessionMode は既に必要な coupled state を表す。
  ExitPolicy/OutcomeFlags の bool は同時成立する独立の原因であり、一つの enum にすると情報を失う。
  ProgressState の型を分割するだけの変更も、現時点で誤りや全体の単純化を実証できない。
  operator の文字列や plan kind も、型へ置換すること自体を目的に起票しない。[^machine][^report]
- **見かけの重複 state。** active と seen の mutant 集合は未完了と既出 ID の一意性、
  SQLite の完了 flag と所有権 lock は永続状態と cross-process 排他という別の事実を扱う。
  一律に統合しない。[^report][^session]
- **Legacy/fallback の名前。** DiffPlan::Legacy は rename/copy/unmerged/長い path の現在の意味を保つ。
  古い保存形式への対応ではない。OS の verified cleanup fallback や Python の名前解決 fallback も
  現在の意味に必要で、互換性という理由だけで削れない。[^git-tracked]
- **serde default と custom decoder。** 現行の任意フィールドや、文字列 discriminator・重複 key・
  streaming の検証を担う。調べた経路では古い format を受け入れる adapter は確認できなかった。
  schema/fingerprint の拒否条件は現在の入力整合性であり、互換 reader とは区別する。[^report][^event][^compatibility]
- **progress と review の機能廃止。** 履歴の価値は残すという合意どおり、表示の allocation を減らす。
  progress は隣接 payload を保持し、履歴 metadata をまとめる構造になっている。独立した identity
  比較・duplicate byte confirmation を単一 cache にする提案は採らない。[^progress]
- **新しい TOML 設定。** 利用者向け設定ファイルを追加する根拠はない。Cargo/開発ツールの TOML は
  製品の config 拡張と別であり、削除や置換の対象にしない。

有限の original/source/artifact 読取り、process 出力の bounded queue と ring spool、
metrics の parent capability と公開、review の private 初期公開、端末表示と配布 workflow を
追跡した。修正済み項目や既に保証外と明記された条件は再起票しない。
[^session][^exception-project][^mutation][^artifacts][^pipe-output][^metrics][^review-store][^release]

#1077 以外の新しい安全性の欠陥・データ破壊はこの監査では実証していない。これは安全性全般の
保証ではない。最新の dependency advisory との照合、任意の concurrent writer、hot journal、
電源断、悪意あるテストコードの隔離を新たに検証したものではない。
