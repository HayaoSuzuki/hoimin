# Scope and product decisions

The 2026-10-22 static audit examined main at
`8691e86562bf65ccf1624b784f845ed92bbda1cc`, after the previous design-audit
archive merged. Three domain investigations covered core/execution/workspace
ownership, artifact/configuration/persistence boundaries, and analyzer costs
plus release/security boundaries. The coordinator checked candidate source paths
and existing Issues, then obtained a fresh read-only challenge of the proposed
findings. This is selected-boundary inspection, not line-by-line coverage of
every operator and native platform.[^history]

The owner reconfirmed the trusted local-project CLI model. Resource safety,
input validation, protection of original files and distribution integrity remain
in scope; sandboxing malicious user-selected test programs does not. Prior
decisions remain: no backward compatibility or saved-artifact migration, feature
removal may be considered, review's persistent history and progress's multiple
report saturation remain useful, and existing formal proofs remain while broader
proof work is deferred. No configuration-file feature is proposed.[^principles]

No implementation build, runtime reproduction, benchmark, native-platform test
or proof execution was used to establish the audit findings below. Follow-up
implementation checks are recorded separately at the end of this page.

# Findings and implementation boundaries

| Issue | Priority proposed at audit | Evidence and minimal change |
| --- | --- | --- |
| [#1060: prepared symbol admission](https://github.com/HayaoSuzuki/hoimin/issues/1060) | P2 | Each candidate scans distinct selectors and allocates prefix strings, even after line rejection. Prepare private per-file symbol membership and preserve nested/module semantics. |
| [#1061: finite duplicate confirmation](https://github.com/HayaoSuzuki/hoimin/issues/1061) | P2, provisional | Optional duplicate-byte confirmation reads regular files to EOF without an initial-length budget. Reuse the existing finite reader; failed confirmation must not become a progress-input error. |
| [#1062: review-only schema probe](https://github.com/HayaoSuzuki/hoimin/issues/1062) | P3 | Review uses its header probe only for schema diagnostic precedence before typed decoding. Remove this extra route; progress still needs JSON/JSONL dispatch. |
| [#1063: obsolete Rust-floor exception](https://github.com/HayaoSuzuki/hoimin/issues/1063) | P3 | Three deprecation suppressions claim to preserve Rust 1.88 although the declared floor/toolchain is 1.99. Use the supported atomic API without a compatibility exception. |

For #1060, CLI target resolution preserves distinct symbol qualnames after
sort/dedup and passes them to the analyzer. N selected functions and N different
selectors can produce triangular comparison work in one candidate-producing
path. The old release shape repeats one selector for one function, so dedup
removes that growth axis. This establishes avoidable operations, not a measured
wall-clock speedup. A prepared representation must distinguish unrestricted
selection from a nonempty request with no matching module; an empty restricted
set must not become all symbols.[^selection][^target][^fixtures]

For #1061, initial report decoding is finite, but the subsequent duplicate
annotation reopens equal-fingerprint paths and compares ordinary buffered files
until EOF. Two equal files that keep growing, including distinct hard-link
paths, can extend that loop. Continuous-growth execution was not reproduced.
The defect is a missing finite-read boundary, not an established external attack
or a demand for a new fixed artifact-size cap. Reopened-file errors already mean
no optional duplicate annotation. An unlink after a descriptor is open need not
fail if the descriptor remains readable.[^duplicate][^artifacts]

For #1062, a normal schema-first document needs only a short probe. A valid
schema-last document can make `IgnoredAny` scan almost all preceding values
before typed decoding scans them again. The probe does not retain a whole
`Value` tree. Old-schema rejection can return before typed decoding; keeping that
old-shape diagnostic priority is the unnecessary policy. Review's existing
64 MiB boundary, typed configuration checks before project-root access, nested
event checks and closed current shapes remain necessary.[^report][^dispatch]

For #1063, the obsolete exception occurs in copy charging and portable process
classification/termination. The standard library documents `fetch_update` as
the deprecated alias of `try_update`, available since 1.95. The change must keep
atomic orderings, checked arithmetic and fault-injection counts. It is a small
maintenance reduction with no claimed runtime improvement.[^copy][^portable][^rust-floor][^atomic]

# Types, state ownership and rejected alternatives

The existing execution types already separate meaningful facts. Process reaping,
output draining, monitor joining, measurement quiescence and cleanup attempts
are not exclusive phases. `ExecutionFinalization` is an appropriate single owner
for related evidence; another broad lifecycle enum would discard information or
require parallel state to recover it.[^finalization]

The audit also considered these smaller changes and did not propose standalone
implementation Issues for them:

| Candidate | Reason to leave it unchanged in this work |
| --- | --- |
| `WorkspacePlan.aggregate_bytes` and mutable `CopyAllowance.granted` | An immutable allowance could remove a copied limit and publication protocol, but grant validation, reservation retention, charging and admission need careful preservation. Current writers are ordered under the state mutex; no race was found. Benefit is modest and unmeasured. |
| Progress ID sets, content indexes and detail duplicate-ID scans | Some work is repeated, but matching identity and content fallback are different views. Measure before caching indexes; do not retain all historical reports to avoid reconstruction. |
| `PendingEffect` worker/cleanup associations | A larger enum could exclude hypothetical combinations, but the controlled production constructors already establish their associations; no inconsistent path was found. |
| Shell lifecycle wrapper | Its narrow boundary also supports existing runtime/model correspondence. Removing a forwarding layer without preserving that correspondence has no demonstrated net benefit. |
| `ReportSequence` active set versus retained identity map | These represent unfinished work and identity history. The historical rationale still applies; field-count reduction alone is insufficient. |

The first two decisions follow current writers/readers; the last three retain
the established evidence distinctions documented in the previous audit history.
No feature removal was justified by the inspected paths.[^copy][^comparison][^history][^pending][^shell-lifecycle][^sequence]

# Security and distribution observations

No new exploitable vulnerability was established. The bounded-reader gap in
#1061 is a resource-robustness finding with unmeasured frequency and impact.
Selected release paths pin actions/container references, limit write-token
checkout to the merged commit, and check staged wheel bytes/provenance. This
static inspection does not attest external repository settings or actual hosted
executions. Previously deferred same-user workspace replacement and general
parser/source-size caps were not revived without evidence that changes the
trusted local-use assumptions.[^security][^release][^provenance]

# Follow-up implementation and validation

The four changes are implemented on `fix/issues-1060-1063`, in the dedicated
`.worktrees/issues-1060-1063` workspace. Symbol admission uses a private
`All`/restricted borrowed-set enum; optional duplicate comparison wraps both files
in the existing `SnapshotReader`; review no longer performs its schema-only
preparse; the three atomic updates use `try_update` with unchanged orderings
and closures.[^implemented-selection][^implemented-duplicate][^implemented-review][^implemented-copy][^implemented-portable]

Before functional edits, the coordinator observed these regressions against the
old production paths:

- Symbol misses at S=C=32 performed 1,024 selector/prefix operations against a
  32-lookup budget; line-rejected candidates still performed symbol work.
  Selector preparation cancellation also failed. One additional new test initially
  expected no truncation diagnostic; its expectation was corrected to the
  existing candidate-limit diagnostic before relying on it as a semantic control.
- Four tiny duplicate-confirmation tests failed when appending or truncating after
  readers were prepared, including a hard link and omitted optional annotation.
  The fixtures start at four bytes and append only 128 bytes; no continuous writer
  or hang experiment was run.
- The new old-shape review test observed unsupported-schema precedence instead of
  typed rejection; 13 other review controls passed. The relaxed old-format test
  checks rejection, while current-schema ordering and configuration-before-root
  controls remain.

Follow-up validation on macOS arm64 with Rust 1.99.0:

- `cargo test --locked --offline --workspace --all-features -- --test-threads=2`
  passed, including the existing executable model-corpus correspondence tests.
  There were no failed test summaries. Ignored native/helper fixtures were not
  promoted to execution evidence.
- `cargo clippy --locked --offline --workspace --all-targets --all-features -- -D warnings`
  passed after replacing one new empty-vector assertion with an equality assertion.
- `cargo fmt --all -- --check` passed.
- `python -m pytest -q tests/test_performance_shapes.py`: 116 passed;
  `python tools/performance_shapes.py check`: 29 shapes validated.
- Strict allowlisted documentation generation with
  `python -m tools.docs_site --output site` passed. OKF YAML/reserved structure
  and reachability cover 52 pages; new/updated citations and source hashes were
  checked separately. No newly broken local targets were introduced; 27 existing
  occurrences were confirmed at the baseline rather than silently repaired.
- A fresh read-only code review found no actionable correctness issue. Native
  Linux/Windows execution, new proof runs and general performance bounds remain
  unverified.

Rust commands used two build jobs, disabled debug information and incremental
builds for debug/test profiles, and shared one task-owned target directory.
Release builds also used two jobs and ran sequentially. Source timestamps were
refreshed before the candidate release build to prevent reuse of the baseline
from the shared target; distinct executable digests were verified before any
sample. No task builds or tests ran during measurement.

The [raw release observations](../../performance/2026-10-22-issue-1060-release.json)
retain 30 samples: three fixed inputs × five pairs × two binaries, with one
discarded warmup per binary/input and alternating pair order. Every successful
plan was complete, and candidate values/order matched by digest across both
binaries. The [offline macOS probe](../../performance/probes/measure-symbol-admission.py)
records the fixture generation and checks.[^measurements][^probe]

The archived run's revision/build fields were checked against the actual builds.
For future probe runs those fields are optional caller declarations, the date is
observed at execution, and source hashes describe the current checkout; an
executable digest alone does not attest its source revision.[^probe]

| Input | Baseline median wall ms | Candidate median wall ms | Baseline median max RSS bytes | Candidate median max RSS bytes |
| --- | ---: | ---: | ---: | ---: |
| One function, one selector | 10.120 | 9.874 | 7,962,624 | 7,995,392 |
| 32 functions, no symbol restriction | 7.974 | 8.094 | 8,077,312 | 8,011,776 |
| 512 functions, 512 distinct selectors | 20.002 | 12.913 | 10,469,376 | 10,616,832 |

The many-selector fixture is faster in these samples and has a 147,456-byte
higher median process RSS. This is consistent with trading repeated lookup work
for O(S) set storage; RSS is not a measurement of that set's retained heap.
Small/unrestricted observations include startup noise, and five pairs with no
confidence interval or timing acceptance threshold establish no universal speedup
or non-regression guarantee. The deterministic gate separately bounds actual
preparation/probe operations; it does not count allocator events or hashed bytes.

To repeat the bounded comparison from the repository root with two already-built
release binaries, choose a new output file:

```sh
python docs/performance/probes/measure-symbol-admission.py \
  --baseline /absolute/path/to/baseline/hoimin \
  --candidate /absolute/path/to/candidate/hoimin \
  --output /tmp/hoimin-1060-new-results.json
```

No product Python code changed, no broad fuzz/benchmark campaign was run, and no
formal source or existing proof correspondence was removed. The diagnostic score
above remains attached to the original static audit, not a new post-fix audit.

# Recheck conditions

Revisit this audit when symbol selection semantics, artifact read ownership,
current-schema rejection, copy grant publication, platform process observation,
or the product trust boundary changes. Distinguish initial-length read budgets
from atomic snapshots: same-length in-place rewrites remain outside their
guarantee. Preserve model/native/static evidence classifications when updating
formal correspondence or platform code.[^artifacts][^history]
