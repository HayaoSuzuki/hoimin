# 監査対象と指摘の分類

監査のbaseは `4a93b2720ee4be3ef9c0664b4c8b6116776eabc9` であり、品質検査は2026-07-23のmacOS 15.7.7 arm64で実行された。対象は6設計領域の製品用Rustコードで、確認範囲の表、指摘の台帳、Issue対応表が残されている。[^overview][^coverage][^findings][^issues]

最終報告では台帳の8項目を判定し、7件を対応が必要な指摘、1件を理由付きで棄却した指摘とした。対応が必要な7件は、確認済み不具合3件と高リスク設計4件である。重大度の内訳はP1が3件、P2が4件だった。この数値は指摘の判定結果であり、7件の修正完了や現在のIssue状態を示してはいない。[^report]

# 後続設計で参照する論点

| 論点 | 当時の代表的な指摘 |
| --- | --- |
| プロセスの生存期間 | Job Objectへの所属前の実行、終了処理が失敗した後の起動元プロセスの終了回収 |
| progressで比較できる条件 | 候補ID集合が変わった比較で改善の停滞・飽和を判断する問題 |
| 読込み時の再検証 | 保存されたplan設定の不変条件を読込みで再検査するか |
| ファイル操作中の競合 | パス名の事前検査と実際の利用の間に対象が変わる問題 |
| 識別子の算術 | 資源予約IDが枯渇し、既存予約と同じIDになる問題 |

これらは監査対象baseでの指摘である。後の変更は[実行・後始末](../design/runtime-lifecycle.md)、[plan/verify](../design/selection-plan-verify.md)、[session](../design/session-report.md)と、各修正報告を照合して確認する。[^report]

# 品質検査の結果と実機確認の範囲

元報告には、整形、Clippy、workspace試験、契約検査、Python試験、releaseとwheelのビルド、wheelの起動確認、core依存検査の成功が記録されている。sandbox内でキャッシュへ書き込めなかった試行は実行環境の制約として残し、再実行の結果と分けている。[^overview]

OS別では、Windows Job Objectと権限を委譲したLinux cgroupの動作を同macOSホストでは実行しておらず、確認範囲を `limited` としている。また、ローカルログはGitの追跡対象外である `.audit/` 配下に保存したと記録されている。リポジトリの取得だけで全ログが手に入るとは限らないため、追試時は元資料の保存先も確認する。[^overview][^report]

# 後続結果の追記条件

元台帳の追跡先に後続修正が見つかったら関連付ける。原文の判定、対象base、実機確認の範囲を残し、新しい版での結果は別の証拠として追記する。過去の検査成功を、現在のコードに対する検査成功として転記しない。
