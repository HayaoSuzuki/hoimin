# Scope and settled decisions

This is a static audit of main `2d3e46afc8e371e92931795a03e3ecc94b0330bc`
on 2026-10-22, after PR #1069 merged. That PR implements #1065–#1068;
those completed findings are not new Issues here. Their implementation measurements
and native focused results remain in the preceding record.[^previous][^prior-implementation]

The user again requested software-design-philosophy and grilling. The existing
decision tree remains settled: trusted local-project CLI, no backward-compatibility
adapters or saved-format migrations, feature removal eligible, no TOML expansion,
review SQLite history and multi-report progress saturation retained, and formal
sources preserved. A sandbox for malicious tests is outside the trust boundary.
No new product choice required another question. Three independent domain reviews
explored facts; a fresh reviewer challenged the two surviving Issue drafts.
No builds, behavioral tests, interruption experiments or benchmarks were run for
this audit.[^principles][^compatibility]

## Original-manifest read budgets

`build_manifest` passes an opened raw `File` into `hash_contents`; `stream::chunks`
continues reading until EOF. Preflight's second manifest and `verify_originals`
use this builder. A selected ordinary generated-data/log file appended by another
local tool can extend hashing beyond the initial opened length. The empty consume
closure in these rechecks has no per-chunk copy/owned budget enforcement.
An eventual changed-content comparison therefore does not itself bound the work
performed before that comparison.[^manifest][^stream][^copy][^workspace]

The first snapshot writer's ordinary path does check copy/owned budgets for every
chunk. Its duplicate-entry branch hashes without that consume check; preserve
this distinction rather than call all snapshot I/O budgetless. #1066 fixed
`WorkerRoot::read/hash` for source/fingerprint acquisition; these callback-based
original-file consumers bypass that route. The preceding scope deliberately
avoided changing unrelated streaming policy, so this finding supplies a separate
consumer trace.[^copy][^prior-implementation]

Use the existing finite reader at the original-file boundary for manifest and
snapshot consumption, retaining native workspace paths and current chunk budget
checks. Do not route native copy paths through portable-source policy, add a fixed
cap, or indiscriminately alter every private-worker reader. Acceptance uses small
deterministic append/truncate fixtures through preflight and verification,
observes at most initial length plus one growth byte, and checks pending-snapshot
cleanup/no successful verification event after failure. Preserve stable and empty
files, duplicate includes, hashes, permissions and capability opening.[^finite]

This establishes missing byte-budget enforcement, not an exploit, a measured
memory increase or an elapsed-time guarantee. Finite bytes do not make an atomic
snapshot, detect same-length rewrites or bound arbitrary filesystem I/O time.

## First review-store publication

`ReviewStore::open_write` first creates the public destination with `create_new`,
then configures SQLite and commits the schema transaction. A process interruption
or initialization error in between can leave an empty or uninitialized public
file. The next invocation takes the existing-file branch, polls `user_version`
for up to one second, and then rejects the application/schema mismatch. Retrying
`review record` at that path needs manual removal of the incomplete file.
This is a static failure/retry trace, not an observed incident.[^review-store]

Do not fix this by automatically initializing arbitrary schema-zero files.
Existing empty, corrupt, foreign and unsupported databases must remain unchanged
and rejected. Initialize privately, complete/close the new database, then publish
without replacing an existing destination, or choose another design meeting the
same safety conditions. Competing initializers should open the completed winner;
revision-conflict rules must still permit only one matching append.[^review-tests]

Keep publication, connection pathname and temporary DB/journal ownership together.
Acceptance injects failures before schema commit, retries the same public path,
checks no-clobber and concurrent initialization on supported platforms, and retains
DELETE journaling, the 16-MiB bound, project/schema validation and protected-input
checks. Specify temporary cleanup without deleting another initializer's or an
existing user's files. No broad SQLite crash-recovery or arbitrary power-loss
proof is claimed.[^review-store]

# Types, state ownership and compatibility: rejected changes

- `SourceScope` already distinguishes unspecified/all/one/indexed roots while
  keeping ordered symbol lookup separate. Candidate line/symbol admission is
  prepared; no new enum is justified just by counting bools or Options.[^core-target][^previous]
- Current schema rejection and checked reconstruction are safety checks, not
  old-format compatibility support. Release exception adapters retain live
  callers; `DiffPlan::Legacy` and filesystem fallback names do not establish an
  obsolete saved-format adapter. No new feature removal or compatibility-removal
  Issue met the evidence threshold.[^compatibility][^release][^history]
- Session `runs.finished` is written but is not used for current selection
  decisions. It still records a historical observation and appears in retained
  formal contracts; removing it was not shown to simplify the whole system.[^session-model][^session-implementation][^session-schema]
  Lifecycle reap/drain/monitor/cleanup facts, telemetry cross-checks and budget
  release-history alternatives retain the preceding audit's distinctions.[^previous][^history]
- Exception import traversal is iterative, alias propagation has reverse
  adjacency, and inheritance lookup has an explicit 256-step bound. Module
  mapping's roots-by-paths work has precedence/collision semantics; without a
  distinct demonstrated avoidable cost it remains a hypothesis. Per-record
  candidate spool reopening remains measurement-dependent rather than a new
  Issue from this audit.[^graph][^hierarchy][^previous]
- Raw private-worker mutation/reset reads have different ownership and process
  quiescence assumptions from live original workspace reads. The original-file
  finding does not justify broad concurrent-writer claims for those paths.

This is a scoped complexity diagnostic, not a repository-wide correctness,
security or performance score. Do not round it into the skill's 9–10 band,
which requires all eight diagnostics. Changed scopes and resolved navigation
make numerical comparisons with earlier audits unreliable as a trend.

| Diagnostic | Assessment | Evidence or remaining action |

| Module purpose describable in one sentence | Supported | Core selects transitions/targets, workspace owns file acquisition/copy, review owns assessed history, progress compares reports. |
| Interfaces simpler than implementations | Supported | Source scopes, capability readers, checked plans and review commands hide substantial validation and ownership rules. |
| Implementation changes without changing callers | Supported | Both proposed fixes fit inside the manifest/input and review-store owners; no new CLI settings or public protocol are needed. |
| Interface comments describe abstractions | Supported | Finite-reader, source and lifecycle contracts state their byte/time/ownership limits; keep those limits when adding the new consumers. |
| Design discussion part of review | Supported | Three domain investigations and an independent challenge checked alternatives, prior fixes and static-evidence limits. |
| Modules hide important design decisions | Supported | Membership, descriptor access, publication/schema validation and state transitions have identifiable owners; proposed fixes consolidate rather than distribute their rules. |
| Newcomers can follow documented boundaries | Supported | Current contract navigation and the local-reference inventory are repaired; the 53-page baseline has no missing local link/source targets or unreachable pages. |
| Actual 10–20% design investment | Unassessed | No time-allocation data was collected. Assess a defined period and recorded effort before scoring; missing data is not evidence of underinvestment. |

No diagnostic row was established to fail in this scoped review. Toward an
evidenced 10/10, assess actual design investment and retain the reviewed
abstraction/navigation conditions as implementation evolves. Implement #1070 and
#1071 on their own merits; adding enums alone cannot supply the missing evidence.
