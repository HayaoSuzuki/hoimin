## Session database admission (#1073)

The session owner inspects existing databases before opening them for session
writes. Only a new path or a genuinely empty DB with version/application ID zero
may initialize. Current schema-5 sessions must have application ID zero and
exact canonical table/index/constraint definitions after whitespace normalization.
A reference schema is built from the same initializer, rather than keeping a
second DDL definition. Version 5 alone does not identify a hoimin database.

The checked-in required-budget schema-5 golden matches that initializer and
remains accepted without schema/data rewriting. The earlier nullable schema-5
golden is retained unchanged as a rejected fixture. It is rejected even when
all budgets happen to be valid; there is no compatibility adapter or repair.
Malformed rows in an otherwise current schema still receive runtime validation.

Closed WAL databases use an immutable advisory read to avoid creating WAL/SHM
companions merely to reject a database. Rollback-mode/empty databases use ordinary
read-only SQLite access so initialization locks remain effective. A regular-file
check precedes the header read. Literal path characters, including URI punctuation,
are escaped; Unix non-UTF8 coverage is conditional on ordinary SQLite accepting
the native filename. The live connection checks version, application ID and
schema within one read transaction. Initialization repeats admission under an
IMMEDIATE write transaction, rolls back failed DDL, and enables WAL only afterward.
Foreign keys, the five-second busy timeout and WAL contention retry remain.

New regression cases failed on the original implementation. The initial companion
file test was corrected after discovering its observation connection had itself
created WAL files before the baseline; the corrected test demonstrated the real
failure before immutable admission was introduced. Independent review also found
a mixed-snapshot race between reading version and schema. A deterministic test
failed with `InvalidIdentity` before read-transaction admission and passes after.
Another test flushes unfinished rollback-mode schema pages while holding the
SQLite lock and verifies the opener waits for rollback before initializing.

Tests inspect closed on-disk DB bytes, schema/rows, version, journal mode and
companion names/content. Tests also cover foreign tables, conflicting names,
application IDs, incomplete schemas, old/future versions, canonical reopening,
locked recheck and genuine SQLITE_FULL initialization rollback. No files owned
by another actor are deleted. Immutable preflight ignores active WAL frames;
these tests are not a guarantee for arbitrary foreign concurrent writers, hot
journals, path replacement races, process kills or power-loss recovery. Existing
Lean model results are not proof of this new SQLite/filesystem admission logic.

The first workspace run found that two persistence-failure fixtures installed an
extra trigger before reopening, which current-schema admission correctly rejects.
Their seed/resume commands now stay identical and consult an external armed
marker; the mutant test process installs the SQLite ABORT trigger after admission.
They still check classification, durable-empty results and identity surfaces, and
explicitly confirm the injected save failure. Lifecycle oracle expectations and
proofs are unchanged.

## Exception source lifetime (#1074)

`ExceptionProject::load` reserves paths/origins, then reads, hashes, decodes and
summarizes each file through borrowed text. `ExceptionIndexBuilder` retains owned
summaries, not source bodies; final import/class/visibility construction starts
after every source body has been released. The CLI no longer builds a full
`Vec<(Path, String)>` or copies every decoded body into it. The remaining internal
`from_sources` helper serves current single-file analysis and pure tests.

Mapping and summary failures are deferred until all bounded acquisition succeeds.
This preserves the priority of later input/decode/fingerprint failures over an
earlier analysis error, including prepared-origin count failure. Regression tests
combine these failures, retry after repair and check successful cache reuse.
Existing raw fingerprints, decoded hashes, prepared-origin semantics, package
precedence, collisions, syntax skipping, cancellation, summary budgets and the
64-MiB total/16-MiB per-file/4096-file limits remain.

The isolated `exception_project_heap` integration test calls public discovery,
which actually loads the project, and asserts the expected Child-to-Root handler
mutation, location and absence of diagnostics/truncation. One long comment per
file keeps the summary small. Fixtures contain exactly 64 KiB per file and at
most 1 MiB total. The warmed current-thread runtime still includes its blocking
worker in the global allocator measurement.

## One run-identity owner (#1075)

`RunState` holds one private `RunIdentity::Ephemeral(String)` or
`RunIdentity::Session(String)`. A session becomes established only after accepted
creation/resume, independently of configured mode. The accepted ID replaces the
generated ID once; reports, processes and results read that owner. Lookup,
persistence and finish use its established-session reference. Paired ID fields,
assignments and the result fallback are removed. Finalization-attempt tracking
remains separate because it has a different responsibility.

This is a representation refactor with no demonstrated wrong behavior before
it. The existing 121 machine tests passed before and after, covering disabled,
fresh, resumed and fallback-to-fresh runs, pre-establishment failure/cancellation,
output/persistence ordering and finish behavior. No artificial failing test for
the old representation was added; schemas and public run-ID behavior are unchanged.
