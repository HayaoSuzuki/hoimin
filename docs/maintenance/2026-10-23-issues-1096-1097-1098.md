Branch: `refactor/issues-1096-1097-1098`.

## Changes and decisions

- File locks use Rust 1.99's standard `File` methods. `TryLockError::WouldBlock`
  replaces comparison with a platform-specific error number. Existing local
  serialization, deadlines, guard release, lease inheritance and reclamation
  decisions remain in place. The obsolete classifier and its synthetic test are
  removed; a Linux O_PATH descriptor regression checks real hard-error handling.
- The coordinator keeps two 512-byte slots and the generation-selection/write
  protocol. Each schema-2 slot has a full BLAKE3 digest at bytes 480..512, covering
  bytes 0..480. The cursor capacity is 458 bytes, above every admitted managed
  root name. A full digest avoids another truncated-checksum contract. This is
  corruption detection, not authentication.
- New coordinators use `hoimin-workspaces-v2`. Old namespace contents are not
  inspected, migrated or reclaimed. This avoids blocking new invocations on a
  persistent schema-1 coordinator and prevents old/new writers sharing a format.
  Old artifacts require separate manual cleanup after older processes exit.
  Unsupported coordinators in the current namespace fail without rewriting.
- `hoimin completions`, its parsed argument type, dispatch and writer are removed.
  No replacement generator or compatibility alias is added. The shared clap
  command remains the parser/documentation source. Historical records are kept.
- The three changes share one manifest, lockfile and dependency inventory update,
  so they are delivered in one commit/PR. No new dependency or retained-package
  upgrade is included.

no dev debug information. CLI/test scratch uses a dedicated temporary parent.
