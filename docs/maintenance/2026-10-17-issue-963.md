# Issue #963: derive disk history statistics

## Scope and design review

Baseline `a72ca276efbb6c98499878f5c1cdeaadd39c23b8` already reports the
historical minimum correctly. This change removes `latest_owned_bytes` and
`FilesystemStats.latest`, which have no production readers, and the separately
stored global minimum. `DiskMonitorStats::minimum_available_bytes()` derives the
global minimum from retained per-filesystem minima on the existing snapshot.
It changes internal representation, not sampling, stop policy or report schemas.

1. Ownership review: each filesystem retains its first value and minimum. The
   global minimum needs no independent assignment or synchronization invariant.
2. Domain review: an empty history yields `None`; a measured zero yields
   `Some(0)`. No sentinel, enum, compatibility field or adapter is needed.
3. History review: the map retains absent filesystems. Taking its minimum equals
   taking the minimum across all accepted raw capacities, including reappearing
   keys; pruning that map would change this contract.
4. Boundary review: sampling derives the current observation before updating
   history. Stop policy consumes that observation, while the shell separately
   queries end capacity. Neither uses historical minima as current capacity.
5. Interface review: the accessor keeps aggregation knowledge with monitor
   statistics. It uses the same cloned snapshot as other report statistics;
   no second lock, polling mechanism or shared state owner is introduced.

Software-design-philosophy assessment for this change: seven of eight diagnostic
rows have evidence (8.75/10). The monitor owns measurement history; its accessor
hides the aggregation rule, documents retained history and needs no caller-side
configuration. The review explicitly considers complexity and module ownership.
Design-time percentage is unmeasured; recording effort would establish the last
diagnostic. Adding another abstraction would not resolve that evidence gap.

## Test development

The original monitor filter passed 20 tests (one existing ignored). Four new
tests then passed against the original representation. These characterize
preserved behavior and do not claim to reproduce a pre-existing runtime bug.

Finite tables cover no samples, measured zero, missing and returning filesystem
keys, plus heartbeat failure, measurement failure and empty capacity maps with
and without earlier successful history. Rejected samples compare the complete
statistics snapshot. A valid sequence crosses the stop threshold, recovers its
current capacity, then crosses again: all samples still contribute to retained
count, peak, duration, first capacity and minimum after the sticky stop.

The bounded proptest generates zero to 23 samples, each with one to four
filesystem keys and arbitrary `u64` capacities. Its expected minimum comes from
flattening the raw input maps, independently of production aggregation helpers.
Default proptest case counts and shrinking are retained. Each test has one
invariant and separates setup, sampling and assertions with blank lines.

A temporary mutation replaced the original accumulated global minimum with
the latest reading's minimum. The finite historical-minimum test failed with
`Some(90)` instead of `Some(50)`. The mutation was restored before refactoring.
This is test-sensitivity evidence, not an original defect. The resulting disk
filter passed 32 tests with one existing ignored test.

## Implementation review

1. State review: repository searches and the diff confirm removal of both
   latest fields, their updates and the stored global minimum. Public report
   fields remain present; the shell calls the new accessor.
2. Atomicity review: all successful statistics still update within the same
   lock, and `stats()` still clones under that lock. The accessor reads only
   its snapshot and cannot observe a partially applied sample.
3. Rejection review: heartbeat errors, meter errors and empty maps return before
   the statistics lock. Count, peak, maximum measurement and filesystem history
   therefore remain unchanged on those paths.
4. Stop review: successful statistics update before policy evaluation. Existing
   sticky stop and secondary-error publication code is unchanged; accepted
   measurements continue to update statistics after a stop has been recorded.
5. Report review: end capacity still comes from `available_for_managed_roots`.
   Per-filesystem start/minimum, negative net change and end-query failure
   handling remain unchanged, as do JSON/JSONL types and schema versions.
