# Python 3.14・3.15対応の検証記録

対象ブランチ: `python-314-315`。
初期状態: 元チェックアウトの`.gitignore`に既存変更がある。専用worktreeは変更なしのHEADから作成し、既存変更を持ち込まない。
ローカル検証用Python: 3.14.9、3.15.1。

## 設計段階のセルフレビュー

1. 対応範囲: ユーザーが選択した3.14・3.15の実行環境対応と既存構文の検証に限定した。
2. 配布: バイナリwheelはPython ABIに依存しないため、Pythonごとの再ビルドを不要とした。
3. 解析: 新構文を対応済みと表記しない。既存の3.14意味論に対する検証を3.15でも行う。
4. CI: Rust matrixのartifact衝突を防ぎ、3.15 smokeを公開前の既存wheel jobに含める。
5. リソース: 初期空き約106 GiBを確認。Cargoの並列数2とdebug情報抑制を採用し、元チェックアウトの成果物は削除しない。

## 実装・検証

設計・配布実装・CIと文書・Windows fixture修正・Renovate補強・最終検証・PR準備の7段階で、それぞれ5回のセルフレビューを実施した。

## 配布・実装段階のセルフレビュー

1. 配布範囲: 3.13と3.16を除外し3.14と3.15を許可する回帰テストを追加した。変更前はclassifier不足と3.15拒否で失敗することを確認した。
2. Python選択: smokeのuvxが3.14に固定される回帰テストの失敗を確認し、sys.executableへ変更した。venvとuvxが同じPythonを使う。
3. 依存解決: uv lockで範囲を拡大し、パッケージ名・バージョンの集合は変更されていないことを確認した。3.15向けwheel情報は追加される。
4. 既存構文: CPythonを使う23個のRustテストファイルで3.14・3.15のみ許可する。ソース解析や演算子の意味論を変更していない。
5. 静的検査: Ruffとtyが通過した。tyの初回エラーはfuzzグループ未導入が原因であり、CIと同じ依存グループの導入後に解消した。

## CI・文書段階のセルフレビュー

1. 自動CI: LinuxのRust matrixに両版を追加し、性能検証artifact名へPythonを含めて衝突を防いだ。
2. 手動CI: Windows/macOSのRust matrixにも両版を追加し、通常CIとのステップ比較を維持した。
3. 配布検証: 各OSで同じwheelを3.14・3.15で検証する。公開前の既存wheel job内の通常ステップとし、continue-on-errorは設定していない。
4. 証跡: リリースsmokeは3.14と3.15のJSONを別名で保存し、両方を同じartifactへ含める。
5. 文書: Python 3.14を共通コードの基準としたまま、インストール可能範囲と新構文非対応を明記した。履歴文書の過去のバージョン記録は変更していない。

## Windowsの既存テスト失敗の切り分け

Rust全体テストの`session_hardlinks`で既存のbaseline実行テストが失敗した。
単独実行でも同じWindowsのファイル名構文エラーを再現した（0 passed、1 failed）。
原因はRust Command経由で`cmd /C`へ渡す引用符付きリダイレクトであり、Python版の違いではない。
テストの目的であるbaselineのマーカー作成・sessionの作成とresumeの検証を保ち、Windowsのfixtureだけを明示的なPython実行へ変更した。
CLIのコマンド処理は変更していない。
この修正を含めてテストを再実行する。

## Windows fixture修正段階のセルフレビュー

1. 再現性: 初回全体テストの失敗に加え、既存の該当テスト単独でも同じWindows構文エラーを再現した。
2. 変更範囲: Windowsのfixtureコマンドのみを変更し、CLI実装やUnixのfixtureには変更を加えない。
3. 検証の目的: baselineのマーカー生成、初回実行とresumeの終了コード、run_idとreused結果のassertionを保持した。
4. 拒否経路: ソース・sessionへのhardlinkをbaseline前に拒否する3件を含め、修正後の4件がすべて通過した（1.59秒）。
5. Python選択: fixtureはCIのuv syncで用意されるworktreeの`.venv`を明示する。minorバージョンを固定せず、3.14・3.15のmatrixで同じテストを実行する。

初回の3.14 Rust全体実行は、3758 passed、1 failed。
失敗した既存fixtureを修正して4件の再実行が通った後、3.15.1でRust全体を再実行する。

## Renovateの両版維持に対するセルフレビュー

1. 許可範囲だけでは3.14指定も3.15へ更新でき、matrixの片方や共通基準を失う可能性があることを確認した。
2. この更新方針を確認する回帰テストを追加し、設定変更前に1件失敗することを確認した。
3. actions/python-versionsだけを対象とする別ルールでmajor/minor更新を無効化し、他の依存関係やpatch更新は制限しない。
4. allowedVersionsとmatchUpdateTypesは同じルールで併用しないという[Renovate公式仕様](https://docs.renovatebot.com/configuration-options/#matchupdatetypes)に従い、範囲制約と更新種別制約を別ルールにした。
5. 開発者文書にminor系列変更の手動レビュー方針を記載し、追加テストと既存CI契約テストを再実行する。
