## Finding and recommendation

`WorkspaceManifest` derives `Clone` over `Vec<ManifestEntry>` and `Vec<Utf8PathBuf>` (`manifest.rs:91-96`); each entry owns a path string. `WorkspacePlan` derives `Clone`, storing the manifest by value (`copy.rs:91-110`). Successful materialization calls `self.manifest.clone()` (`copy.rs:743-754`) into each `WorkerWorkspace` (`mod.rs:463-477`). All observed consumers only read the manifest. There is one constructor site, in `build_manifest_with_contents` (`manifest.rs:222`). Private fields already prevent external mutation. The problem is duplication of immutable metadata, not multiple mutable state authorities.

Recommend keeping the public `WorkspaceManifest` value as an immutable handle with private `Arc<ManifestStorage>` containing **all three** existing fields (entries, directories, logical_bytes). Make `ManifestStorage` private, with Debug/Eq/PartialEq as needed but no Clone derive. Keep the outer Clone/Debug/Eq/PartialEq. This puts both ownership and clone cost policy in the module that owns manifest construction and lookup. Plan and worker continue owning a `WorkspaceManifest` handle; no public Arc, getter for the Arc, custom Deref, new cache, Mutex, registry, or generic abstraction is needed.

An interface comment should say that clones share immutable metadata; the storage remains alive while any manifest handle remains; it contains no worker root, reservation, charge, or cleanup authority. Do not expose a mutable accessor or introduce Arc::make_mut/get_mut paths.

The source-level cost is removing `const` from `WorkspaceManifest::logical_bytes()` and from `WorkspacePlan::completed()` (the latter calls the former). Ordinary call expressions and return types stay the same. Searches found no other const function calling logical_bytes in the workspace module. The public `plan.manifest()` and `worker.manifest()` getters can remain const: they still return a reference to an ordinary manifest field. No compatibility shim is requested or warranted.

## Concrete alternatives

| Alternative | Effect | Design tradeoff |
|---|---|---|
| `Arc<WorkspaceManifest>` fields in plan and worker | Shares all metadata between plan clones/workers, without modifying the manifest representation | Small hot-path fix, but shares knowledge of Arc across `copy.rs` and `mod.rs`; `from_materialized` takes Arc; both manifest getters and completed lose const; public `plan.manifest().clone()` remains deep and cannot serve as a sharing regression probe. Viable if the intended contract is explicitly only worker sharing. |
| Private `Arc<ManifestStorage>` inside `WorkspaceManifest` (recommended) | Every manifest clone shares all immutable metadata, including standalone clones and plan/worker transfers | Stronger, simpler value contract localized in `manifest.rs`. One allocation/control block per built manifest; one atomic refcount operation per clone; a single scalar accessor and completed lose const. Existing lifecycle code does not change. |
| Separate Arc slices for entries and directories | O(1) collection clones | Two ownership domains/refcounts and scalar placement decisions for one logical snapshot. No current independent lifetime or replacement need. Reject unnecessary decomposition. |
| Put manifest into `DiskSnapshot` | Couples metadata and disk snapshot lifetime | Requires plan/worker access rewrites and changes responsibilities; standalone validation manifests have no disk snapshot. Expands this issue into lifecycle redesign. Reject. |
| Share only entries, intern paths, add Mutex/cache, or borrow from plan | Partial sharing or extra infrastructure | Directory/path amplification may remain; borrowed worker lifetimes cannot outlive plan without wider API changes; mutable infrastructure adds synchronization without a mutable requirement. Reject. |

Keeping logical_bytes outside shared storage solely to preserve const would still be safe because it is immutable, but splits one snapshot's representation across wrapper and shared allocation without a present requirement. Prefer the coherent storage. Moving Vec into Arc does not clone entries; converting to Arc slices is unnecessary for this issue.

## Exact implementation surface for the recommendation

1. `crates/hoimin-cli/src/workspace/manifest.rs`: import `std::sync::Arc`; add private `ManifestStorage { entries: Vec<ManifestEntry>, directories: Vec<Utf8PathBuf>, logical_bytes: u64 }`; replace the public manifest's three fields with `storage: Arc<ManifestStorage>`; retain value equality; change all collection access/comparison/search inside this module to storage access; wrap the one final construction with Arc::new. Make logical_bytes an ordinary fn. Preserve sorting, ancestor insertion, overflow checks, hash/size comparisons, and first-difference precedence.
2. `crates/hoimin-cli/src/workspace/copy.rs:511`: make completed ordinary fn. Its return value and accounting inputs remain identical. Keep plan's manifest value field and successful transfer `self.manifest.clone()`; that call now explicitly means a cheap immutable handle clone. No `from_materialized` signature change, new constructor, duplicate handle accessor, or compatibility API.
3. No necessary production edits to `mod.rs`, `reset.rs`, `mutation.rs`, `operation.rs`, `disk.rs`, `root.rs`, `owned.rs`, core grants, or serialization schemas. Compilation must still inspect cross-crate const callers; the search here is not a substitute for that check.
4. Add focused manifest metadata heap integration coverage in an isolated test binary or extend `workspace_heap.rs` while keeping exactly one test in the binary to avoid global allocator overlap. Preserve its existing large-file check. Add small behavior/lifetime cases near current workspace unit tests, and improve relevant existing failure/cancel tests rather than duplicating entire harnesses.

`ManifestEntry::clone()` can remain deep: an entry cloned explicitly is an independently owned entry; the expensive unwanted operation is cloning the immutable whole manifest. Equality remains structural through Arc's Eq/PartialEq implementations; do not change it to pointer equality. Debug formatting may expose the new private wrapper in debug-only text; do not promise byte-identical Debug output.

## Call and lifecycle inventory

- `build_manifest` and `build_manifest_with_contents` return plain `WorkspaceManifest` values; the latter makes sorted entries/directories from BTree collections and computes checked logical bytes (`manifest.rs:175-237`). Manifest-building transient memory remains O(files + directories + path bytes); this change removes multiplied retention, not inventory storage.
- `WorkspacePlan::preflight_validated_in` creates a pending disk snapshot and manifest, passes a borrowed manifest to validation, builds a fresh current-source manifest, compares it, checks limits, and only then publishes the plan (`copy.rs:439-499`). Both completed snapshots temporarily exist during verification. Do not substitute Arc identity for content comparison and accidentally skip source validation.
- `create_worker` records the granted slot, materializes, and removes the slot on failure (`copy.rs:586-601`). Partial copied bytes are released on copy error (`copy.rs:736-739`). Only a successfully materialized workspace clones the manifest handle at present. Preserve these orderings.
- Materialization creates per-worker directories and reads the shared snapshot through fresh readers; it copies permissions and enforces allowance and optional contracts (`copy.rs:642-754`). Sharing metadata does not remove the unavoidable O(files × workers) filesystem operations. Say metadata-retention/clone-time improvement, not total materialization becomes O(workers).
- `verify_originals` constructs a new manifest of live original files and compares paths, size, hash, and directories (`copy.rs:565-581`). This must continue detecting additions, removals, and same-size content changes.
- Reset builds worker-local temporary sets, repairs directories, and restores changed worker files from `Arc<DiskSnapshot>` (`reset.rs:29-153`). It reads immutable manifest directories/expected file sizes. Temporary reset inventories can still scale with each concurrently resetting worker; this issue does not remove that separate peak.
- Mutation reads an expected entry and validates both candidate hash and actual worker hash before validating spans/encoding and writing (`mutation.rs:16-125`). Never update shared expected hashes after mutation. Other workers must still validate against original snapshot content.
- `WorkerWorkspace` separately owns retained root capabilities, temp/managed child, snapshot Arc, allowance Arc, plan state Arc, worker ID, charged amount, and cleanup flags (`mod.rs:463-505`). Keep every field and Drop ordering. The shared manifest contains none of those.
- `WorkerWorkspace::Drop` closes capabilities, attempts cleanup where required, and releases allowance/slot only after directory disappearance (`mod.rs:588-609`). Manifest deallocation has no filesystem effect and must not gain a custom destructor controlling worker cleanup.
- Active vs pending cleanup state is exclusive (`WorkerSlot`, `mod.rs:788-810`). `operation::reset_worker` retains the complete workspace after failed discard; `operation::create_worker` validates grants before touching pending ownership and drops a cleaned pending workspace before replacement. A pending workspace naturally keeps a manifest Arc and snapshot Arc alive.
- Owned create/verify tasks hold `Arc<WorkspacePlan>`; apply/reset tasks own `Box<WorkerWorkspace>`; completions return exclusive active/pending ownership (`mod.rs:872-1013`). Cancellation of an awaiting task is not proof a blocking filesystem task has stopped. A detached task retains its plan or workspace and therefore its manifest data naturally.
- `WorkspaceHandler::close` preserves all state if cleanup fails; clears workers then plan only after success (`mod.rs:1458-1480`). `retain_workers_for_janitor` changes cleanup policy but does not itself drop manifest state. Managed children retain lease/parent/root capabilities so detached blocking tasks cannot race startup janitors (`owned.rs:8473-8520`). No new cycle: manifest storage contains no Arc back to plan, worker, or disk snapshot.

## Meaningful RED, parameter, property, and lifetime cases

2. **RED actual-worker metadata scaling:** preflight/ledger/grant setup outside interval; retain 1/4/16 actual workers on empty fixtures, with all worker requests and output Vec capacity prepared before baseline. Measure LIVE delta after each worker group is fully materialized, not transient peak. Use a second 1,000-file fixture and small (e.g. 64-byte) payloads to show the result is not specific to empty files. Avoid making elapsed time a CI assertion.
3. **Parameter preservation of manifest view:** zero files, one empty file, nested/empty directories, multiple files, nonempty bytes; compare entries/order/hashes/sizes/directories/logical bytes between plan, cloned plan, standalone manifest handle, and workers. Equality is content equality, including separately preflighted equal trees. 4. **Worker survives plan ownership drop:** create two workers; drop original plan and all plan clones; alter the original tree, mutate/write/remove a worker file; reset one surviving worker and assert snapshot bytes restored. The second worker remains unchanged. This is a strong public behavioral lifetime check; it needs no Weak hook. Keep separate tests for plan-drop lifetime and worker isolation if AAA one-case policy is strict.
5. **Manifest outlives last filesystem owner:** clone `plan.manifest()`, record plain expected values, drop workers/plan/project, and query the surviving handle. It remains valid independently of snapshot disk ownership. Drop last handle and observe release in the allocator probe (or unit-private Weak) rather than adding a production observer API.
6. **Failed creation does not disturb a sibling:** existing `failed_snapshot_copy_rolls_back_only_the_slot_and_keeps_the_bound_reservation` (`copy.rs:1874`) supplies the failure harness. Extend/create a sibling-worker variant: retain manifest handle and one successful worker; induce a later snapshot read failure; assert typed error, unchanged sibling manifest/content, only failed slot rollback, and charge of the surviving worker. If measuring final shared storage release, use a unit-private Arc::downgrade on storage, never public refcount APIs.
7. **Cancellation with delayed materialization:** reuse MaterializationPause and bounded release guards. Pause owned creation while it holds plan ownership; release external owner/cancel wait; resume and observe completion/drop. Manifest must be readable until actual task completion and reclaimed after all handles disappear. Existing shell tests `repeated_cancellation_does_not_extend_paused_materialization_shutdown` (`shell.rs:9382`) and `cancellation_released_inside_grace_finishes_orderly` (`shell.rs:9438`) cover scheduling/cleanup integration; run them as preservation checks, and only add focused metadata lifetime observation if needed. Do not add sleeps as lifetime synchronization.
8. **Delayed cleanup retains only that worker's ownership:** reuse existing reset-depth/discard or supported cleanup failure fixture (`workspace_recovery.rs:984`, `mod.rs:1922`, `mod.rs:2050`). Leave worker 0 pending, clean worker 1, drop plan ownership where the test permits, then retry worker 0 cleanup. Shared metadata remains available while pending; worker 1's slot/charge is independently released; final cleanup reclaims remaining metadata. Prefer a deterministic supported failure over chmod assumptions that differ for privileged users/Windows.
9. **Bounded property model:** 16-32 cases, 0..8 short files, 0..4 empty dirs, 1..4 workers, operations length <=12. Build expected manifest data directly from generated file payloads/path names; include duplicate plan/manifest handles, drop-order choices, worker write/delete/reset and one original-source edit/verify checkpoint. At each operation assert unchanged manifest data, independent worker model bytes, exact logical charge for live materialized workers, and reset-to-original payloads. No oracle should call the implementation's content_matches/first_content_difference or calculate expectations from the current worker manifest. Existing ownership sequence proptest in `mod.rs:2297` already covers pending admission rejection; do not recreate it with the same implementation as oracle.

A practical minimal new suite is two isolated heap regression cases, one parameterized immutable-content/drop-order property, and focused reuse of current failure/cancel/delayed-cleanup harnesses. ## Security and cleanup constraints

- No dereference of a manifest path replaces WorkerRoot capability checks. Sorted relative path policy, symlink/reparse rejection, hardlink safety, depth checks, retained root identity, and permission restoration must stay in existing code.
- Arc shares Rust metadata only; do not share mutable file cursor/worker file handles. Existing snapshot with_file opens a reader per access and reset rewinds its own reader.
- No move of cleanup flags, worker IDs, charge, temp owner, root handles, or mutable PlanState into shared manifest storage. Doing so could let one worker cleanup affect another, release accounting early, or publish quiescence before handles close.
- Preserve declaration/drop ordering for Windows capabilities, including pending local owner/cleanup wrapper and DiskSnapshot reader-before-owner. Metadata Arc has no OS cleanup authority and requires no reorder.
- Do not make metadata lifetime conditional on cleanup success. It follows owned plan/worker/standalone handles. Failed pending cleanup retains its owning workspace until retry/transfer; a detached live task owns a handle independently of the awaiting future.
- No compatibility wrappers, fallback deep-copy path, feature flag, mutable lazy index, leaked global cache, or cycle to owners.

## Five distinct design-review passes

1. **Cause and complexity audit:** traced derived Clone from private Vec fields through derived plan Clone and successful worker construction; read reset/mutation/source verification. Result: immutable metadata ownership is the sole selected change; filesystem materialization remains intentionally per-worker. Existing large-file heap test misses this axis.
2. **Boundary/alternative audit:** compared Arc-at-owner, Arc-at-manifest-storage, dual slices, snapshot coupling, and borrowed/cache variants. Result: recommend one private storage Arc; it changes one authoritative module and gives an honest cheap Clone value contract. No new forwarding interface earns its keep.
3. **Lifecycle/authority audit:** read materialization rollback, WorkerWorkspace Drop, active/pending transitions, WorkspaceTask ownership, managed child lease, and close ordering. Result: no ownership transitions should change. One Arc handle must remain in each live plan, worker, completion, or standalone manifest value. No new cycles or cleanup dependencies.
4. **Validation/security audit:** traced final preflight re-read, verify_originals, reset hash/size/permission flow, and mutation candidate/worker validation. Result: preserve structural equality/difference logic and all capability paths. Sharing must not turn identity into content validation, update expected hashes, or share cursors.
5. **Acceptance/evidence audit:** inspected workspace_heap, workspace_preflight_heap, the peak-only support meter, historical public probe, grant property tests, pending ownership property tests, and actual cancellation tests. Result: pure-clone RED + real-worker retained heap scaling with empty/small files distinguishes this fix; runtime, lifecycle, and RSS claims require separately identified evidence. No fresh baseline or passing tests are claimed here.

Getter signatures also match the literal-search pattern, so they are not additional constructors.
