# Linux cargo-nextest evaluation

## Scope and coverage

For [#756](https://github.com/HayaoSuzuki/hoimin/issues/756), the
[existing Linux Rust job](https://github.com/HayaoSuzuki/hoimin/actions/runs/38113472996/job/114393883068)
completed the comparison successfully. The overall trial CI failed its two
existing Python workflow-equality assertions because Linux temporarily differed
from the manual non-Linux job. The final change removes the experimental
workflow, helper, config and tests, restoring the existing CI without weakening
those assertions.

Both runners used the same checkout and compiled artifacts with workspace
default features: PR head `1bd6866524b3d6c4e7d26a67f36814567362a704`, base
`00893465e0328204453e5008dc3884035b85c7bd`, synthetic merge `096c482`.
The host was Ubuntu 24.04 image `20261004.327.1`, four CPUs, Rust 1.99.0,
Python 3.14.8 and nextest 0.9.148. Cargo retained two build jobs and its default
libtest concurrency; nextest used two test threads and zero retries.

The independent Cargo artifact/libtest inventory and nextest list matched:
145 binary paths and 2,785 qualified test identities, including ignored status.
There were 24 ignored tests and 2,761 normal tests passed with both runners.
Cargo output includes two extra summaries from recursive bootstrap fixtures;
naively summing every summary would incorrectly report 2,763 tests.
The nextest JUnit reports 2,761 tests, zero failures/errors.

Both workspace logs contain eight `SKIP:` lines for unavailable delegated cgroup
controllers. These tests return successfully after checking capability; their
hard-limit assertions did not execute. They are distinct from Rust ignore and
JUnit skip counts. Do not count them as successful delegated-cgroup validation.
Separate doctest runs found zero doctests in both libraries. The existing CLI
reference example tests and generated-reference check also passed in the job.

## Measurements

Installation took one second; the common test build after `uv sync` took
120.91 seconds. This is not an independent cold-cache comparison: uv sync has
already built the package, and both runners reuse the same test artifacts.
The table uses the helper's elapsed time and its observed process-tree peaks
sampled every 200 ms. [Evidence](2026-10-11-linux-evidence.md) preserves the
commands, raw metrics, GNU time output, inventory counts and log hashes.

| Workload | Cargo seconds | nextest seconds | Cargo tree RSS MiB | nextest tree RSS MiB | Cargo tree processes | nextest tree processes |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Timeout integration, repeat 1 | 15.97 | 20.32 | 181.0 | 123.6 | 8 | 8 |
| Timeout integration, repeat 2 | 14.32 | 20.35 | 200.5 | 123.3 | 10 | 8 |
| Workspace | 146.12 | 151.10 | 394.8 | 239.0 | 10 | 13 |

The probe selects `timeout` in `run_e2e` and `process_handler`, running in
Cargo/nextest/nextest/Cargo order. Each run reports 12 passed tests and 98
filtered tests; one of the 12 contains a cgroup capability skip. The workspace
runs execute once each, Cargo first, including existing interruption, timeout
and descendant-reaping assertions on supported Linux paths.

The separate doctest command took 0.83 seconds with sampled tree RSS 344.8 MiB.
Including doctests, the observed test-execution peak is therefore 394.8 MiB
for Cargo versus 344.8 MiB for nextest plus doctests. The shared build's GNU
time maximum RSS is about 1.63 GiB; replacing the test runner does not reduce
that build burden.

Tree RSS sums per-process RSS, including shared pages multiple times. It is not
GNU time's maximum RSS. The sampler includes time/Cargo wrapper processes and
can miss short-lived or reparented descendants; it is not proof of cleanup.
Existing test assertions provide behavioral cleanup checks. Helper elapsed time
also includes sampling overhead and exit-detection delay.

## Decision and reproduction

Do not adopt the evaluated two-thread configuration. The roughly five-second
workspace difference from one run each does not establish a general slowdown,
but the repeated timeout probe also showed no improvement. Adding installation
and separate doctests does not shorten the job. Reduced execution RSS does not
reduce its shared build peak. The evidence does not justify maintaining another
runner at present.

Keep Cargo, nightly shuffle, contracts and OS-specific jobs unchanged; do not
leave repeated comparisons in CI. macOS, Windows, delegated cgroups and other
nextest concurrency settings remain unverified. Do not generalize this result
to them. Intentional failure/forced-timeout diagnostic fixtures were conditional
on adoption and were not added. Any future adoption must demonstrate nonzero
failure/timeout status, retained logs/JUnit and descendant cleanup as well as
repeatable improvement and matching coverage.

To reproduce, use a separate branch/checkout at the
[comparison commit](https://github.com/HayaoSuzuki/hoimin/commit/1bd6866524b3d6c4e7d26a67f36814567362a704),
with its `.config/nextest.toml`, pinned Rust/Python dependencies and the
`rust` job's pinned installation, build and helper steps, in that order.
`tools/nextest_evaluation.py` writes to `RUNNER_TEMP/nextest-evaluation` and stops
on a failed command. Set `RUNNER_TEMP` to a fresh temporary directory on Linux.
The historical helper is private evaluation tooling, not a supported interface.
Undo the whole experimental commit to return to `cargo test --workspace`, then
check the existing CI-contract tests. Normal local commands remain in the
[development guide](../../development.md).
